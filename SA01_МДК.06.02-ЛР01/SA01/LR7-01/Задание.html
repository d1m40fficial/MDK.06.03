  2. Пять таблиц регламента, заполненных по столбцам (см. «Формат вывода»): область действия, распределение полномочий, переходы карточки, поля карточки, проверка регламента.
  3. Схема процесса — рисунок состояний/переходов или таблица переходов (таблица уже есть в шаблоне, отдельный рисунок не обязателен).
  4. Разбор контрольного случая — три абзаца: первичное решение, различающая проверка, пересмотр решения.

2. Глоссарий

Служба поддержки (Service Desk)
Единая точка контакта с пользователями: принимает, регистрирует и распределяет обращения, отвечает за результат услуги.
Линия поддержки (L1, L2, L3)
Уровень специалистов. L1 — приём и типовые решения; L2 — углублённая диагностика и восстановление; L3 — изменение продукта (конфигурации, кода) по эскалации.
Инцидент
Незапланированное прерывание или ухудшение услуги (например, не публикуется расписание).
Обращение (запрос)
Зафиксированный в карточке факт обращения пользователя — инцидент или консультация.
Карточка обращения
Запись с обязательными полями (ID, время, симптом, окружение, действия, итог), по которой восстанавливается история решения.
Регистрация
Присвоение обращению ID и занесение обязательных полей до начала работы. Без регистрации работа не начинается.
Приоритет P1 / P2
Степень важности обращения. P1 — критичный отказ, P2 — остальные. Приоритет задаёт цели сроков и порог эскалации.
Профиль (условия C1–C5)
Набор параметров варианта: режим поддержки (C1), цель реакции (C2), цель восстановления (C3), порог эскалации (C4), хранение доказательств (C5).
Режим поддержки
Окно, в котором принимаются и контролируются обращения. Для SA01: P1 — круглосуточно; остальные — 08:00–20:00.
Эскалация
Передача обращения на следующую линию или специалисту. Функциональная — по квалификации; порог задаётся условием C4.
Контрольный случай
Дополнительное учебное наблюдение варианта (V-P), по которому проверяют, что регламент выдерживает изменение условия. Первичное решение сохраняют и объясняют его пересмотр.
Разрыв (gap)
Место, где текущий процесс нарушает правило регламента (см. наблюдения P01–P05).

5. Порядок выполнения (шаги 1–6)

Шаг 1. Область действия и исключения

Что сделать. Перечислите услуги, входящие в сопровождение (регистрация, консультации, диагностика, восстановление, ведение базы знаний), и явные исключения (разработка новых функций — отдельным изменением). Для каждой строки укажите ответственную роль и основание.

Готово, если: упомянута критичная функция и все три канала; у каждого исключения указан владелец.

Шаг 2. Распределение полномочий

Что сделать. Распределите операции между L1, L2, L3, владельцем сервиса и администратором БД. Для каждой операции укажите исполнителя и способ передачи/подтверждения (принятие ack, запись в карточке).

Готово, если: назначения не нарушают ограничения ролей; у каждой операции ровно один ответственный за результат; видно, что делает именно L1, L2, L3.

Шаг 3. Жизненный цикл обращения

Что сделать. Опишите состояния и переходы: Новое → Зарегистрировано → Назначено → В работе → Решено → Закрыто и повторное открытие. Одна строка таблицы — один переход, с владельцем и контролем.

Готово, если: телефон и почта всегда приводят к регистрации; закрытие возможно только после проверки результата; есть ветка повторного открытия.

Шаг 4. Обязательные поля карточки

Что сделать. Определите обязательные поля карточки и момент их заполнения. Учтите наблюдения P01–P04 и жизненный цикл.

Готово, если: по заполненной карточке восстанавливаются автор, время, симптом, окружение, действия и итог.

Шаг 5. Эскалация и оповещение

Что сделать. Опишите основания и состав передачи обращения (что именно передаётся), адресата, канал и контроль принятия. Отдельно — порядок оповещения при критичном отказе.

Готово, если: маршрут P02 не теряет окружение; для P04 указан отдельный подтверждаемый канал, а не общая почта; порог взят из C4.

Шаг 6. Проверка регламента и контрольный случай

Что сделать. Проверьте регламент на P01–P05 и устраните разрывы. Затем разберите V-P: кто примет обращение при дополнительном ограничении и как подтверждается передача. Сохраните первичное решение и объясните его пересмотр по новым фактам.

Готово, если: для каждой строки показан разрыв и корректировка; по V-P видно исходное решение, применённое правило и обоснованный пересмотр; неизвестные данные помечены явно.

8. Чек-лист самопроверки

Перед сдачей отметьте каждый пункт. Если пункт не выполняется — вернитесь к шагу из карты работы.

  • Указаны вариант SA01, ФИО, группа; удалены серые подсказки.
  • Заполнены все пять таблиц; пустых обязательных полей нет.
  • Есть хотя бы одно исключение из сопровождения и у него указан владелец.
  • У каждой операции ровно один ответственный; ограничения L1–L3 соблюдены.
  • Телефон и почта приводят к регистрации; закрытие — только после подтверждения.
  • Передача на L2 содержит симптом, окружение и выполненные проверки.
  • Для критичного отказа указан отдельный подтверждаемый канал.
  • В таблице проверки есть строки для P01–P05 и отдельно для V-P.
  • Для V-P показаны первичное решение, применённое правило и пересмотр.
  • Есть заключение о модели приёма обращений с обоснованием.

9. Оценивание

Максимум 6 баллов: предметный результат — 2; обоснование по данным — 2; проверка и объяснение изменения условия — 2. Частичное выполнение критерия даёт пропорциональную долю. Допустимы разные решения при соблюдении ограничений и прослеживаемых основаниях. На сдаче объясните выбранный факт и корректировку при небольшом изменении условия.

10. Частые ошибки

  • Регистрация только по части каналов (телефон без карточки).
  • Передача на L2 без окружения и выполненных проверок.
  • Закрытие карточки без подтверждения пользователя.
  • Оповещение о критичном отказе общей почтой.
  • Два ответственных за одну операцию или нарушение ограничений роли.
  • Отсутствие статьи базы знаний после нового решения.
  • Оставленные подсказки-заглушки и пустые обязательные поля.
