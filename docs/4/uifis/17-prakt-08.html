01Что делаем

В лекции 9 мы прошли путь пакета: адреса, маска, шлюз, порты, TCP и диагностика по слоям. Теперь соберём сеть из двух виртуальных машин и проверим её на практике.

Схема простая. У каждой машины два адаптера. Первый работает в режиме NAT и даёт выход в интернет через хост. Второй подключён к внутренней сети VirtualBox с именем uifis-net и связывает машины напрямую. Внутренняя сеть не требует host-only адаптера и не меняет настройки Windows на учебном компьютере.

Результат работы это работающая связь между двумя машинами, HTTP-служба на сервере, диагностическая таблица и отчёт с пятью найденными неисправностями.

Что считается готовым результатом

Клиент пингует сервер по адресу 10.10.0.10, получает HTTP-ответ с порта 8080 и входит по SSH. В отчёте есть схема сети, вывод проверок и разбор пяти неисправностей.

Материалы к работе Шаблон отчёта в DOCX Таблица диагностики в CSV Шаблон netplan

Скачайте файлы в папку практики. Шаблон netplan содержит адрес сервера, для клиента измените последний октет.

02Подготовка

Нужны две виртуальные машины с Ubuntu Server 24.04 LTS:

Машина Роль Память Диск
uifis-srv01 Сервер 2048 МБ 15 ГБ
uifis-cli01 Клиент 2048 МБ 15 ГБ

Если машина uifis-srv01 уже создана на практике 6, используйте её. Вторую машину можно создать с нуля или клонировать первую, затем сменить имя и MAC-адреса адаптеров.

На каждой машине должно быть два адаптера:

Адаптер Режим Назначение
1 NAT выход в интернет и обновления
2 Internal Network, имя uifis-net связь между машинами

В VirtualBox откройте Настройки -> Сеть. Для второго адаптера включите Enable Network Adapter, выберите Internal Network и введите имя uifis-net. Имя должно совпадать на обеих машинах до символа.

Не включайте host-only сеть и не меняйте настройки Windows на хосте. Всё, что нужно, находится внутри виртуальных машин.

03Шаг 1. Имена интерфейсов

Запустите обе машины и войдите под пользователем student. Посмотрите интерфейсы:

ip -br a

В типичной установке VirtualBox первый адаптер называется enp0s3, второй enp0s8. Имена могут отличаться. Найдите интерфейс, который появился после добавления второго адаптера и пока не имеет адреса.

Посмотрите маршруты:

ip route

Через NAT должен быть маршрут default via 10.0.2.2. Внутренний интерфейс пока без адреса, поэтому маршрута 10.10.0.0/24 ещё нет.

04Шаг 2. Настройка сервера

Создайте файл netplan:

sudo nano /etc/netplan/60-uifis-net.yaml

Вставьте конфигурацию:

network:
  version: 2
  ethernets:
    enp0s3:
      dhcp4: true
      optional: true
    enp0s8:
      dhcp4: false
      dhcp6: false
      addresses:
        - 10.10.0.10/24
      optional: true

Замените enp0s3 и enp0s8 на свои имена. Сохраните файл: в nano это Ctrl+O, Enter, затем Ctrl+X.

Закройте права на файл:

sudo chmod 600 /etc/netplan/60-uifis-net.yaml

Проверьте конфигурацию:

sudo netplan try

Netplan покажет параметры и подождёт подтверждения. Если ошибок нет, нажмите Enter. Если конфигурация неверна, подождите, и прежние настройки вернутся. После успешной проверки примените файл:

sudo netplan apply

Проверьте результат:

ip -br a
ip route

На внутреннем интерфейсе должен появиться адрес 10.10.0.10/24. Маршрут по умолчанию должен идти через NAT, а не через внутреннюю сеть.

Почему на внутреннем интерфейсе нет шлюза? Потому что 10.10.0.0/24 это локальная сеть. Шлюз нужен только для выхода в другие сети, а выход уже обеспечивает NAT-интерфейс. Если указать шлюз на обоих интерфейсах, появится два default-маршрута и непредсказуемая маршрутизация.

05Шаг 3. Настройка клиента

Повторите настройку на uifis-cli01, изменив адрес:

addresses:
  - 10.10.0.20/24

Имя внутренней сети и имена интерфейсов должны совпадать с сервером. Примените файл так же:

sudo chmod 600 /etc/netplan/60-uifis-net.yaml
sudo netplan try
sudo netplan apply

Проверьте адрес и маршрут. Теперь у сервера 10.10.0.10, у клиента 10.10.0.20, маска /24.

06Шаг 4. Проверка связности

С клиента выполните:

ping -c 3 10.10.0.10

Ожидается три успешных ответа и нулевые потери. Затем посмотрите таблицу соседей:

ip neigh

Для адреса 10.10.0.10 должен появиться MAC-адрес сервера. Если ping не проходит, проверьте по порядку:

  1. Оба адаптера подключены и имеют режим Internal Network.
  2. Имя сети на обеих машинах одинаковое.
  3. Оба адреса в одной подсети 10.10.0.0/24.
  4. На внутренних интерфейсах нет лишнего шлюза.
  5. Внутренний интерфейс поднят и имеет состояние UP.

Проверьте обратное направление:

ping -c 3 10.10.0.20

Связь должна работать в обе стороны. Если ping идёт только в одну сторону, ищите асимметричную настройку или firewall.

07Шаг 5. HTTP-служба

На сервере создайте простую страницу и запустите HTTP-сервер:

mkdir -p /srv/uifis-http
cd /srv/uifis-http
echo "uifis network ok" > index.html
nohup python3 -m http.server 8080 --bind 10.10.0.10 >/tmp/uifis-http.log 2>&1 &

Команда --bind 10.10.0.10 важна. Она заставляет службу слушать внутренний адрес, а не только 127.0.0.1. Без этого клиент не подключится.

Проверьте, что порт слушается:

ss -tlnp | grep 8080

В выводе должен быть адрес 10.10.0.10:8080. Теперь с клиента:

curl -I http://10.10.0.10:8080/

Ожидается строка HTTP/1.0 200 OK. Если соединение отклонено, смотрите ss на сервере. Если запрос зависает, проверяйте firewall.

Если на сервере включён ufw, разрешите порт только для учебной сети:

sudo ufw status
sudo ufw allow from 10.10.0.0/24 to any port 8080 proto tcp
sudo ufw allow from 10.10.0.0/24 to any port 22 proto tcp

Не открывайте порт всему интернету. NAT-интерфейс не должен принимать HTTP-запросы снаружи.

Проверьте SSH с клиента:

ssh student@10.10.0.10

Первый вход попросит подтвердить отпечаток ключа. После входа выполните hostname и убедитесь, что попали на сервер. Выход командой exit.

08Шаг 6. Пять неисправностей

Неисправности выполняйте по одной. После каждой возвращайте рабочее состояние, иначе следующая проверка будет непонятной.

Неисправность 1. Неверная подсеть

На клиенте временно поставьте адрес 10.20.0.20/24 и примените netplan. Проверьте ping -c 3 10.10.0.10: связь пропадёт, потому что адреса в разных сетях, а маршрута между ними нет.

Проверка: ip -br a, ip route. Исправление: вернуть 10.10.0.20/24 и выполнить sudo netplan apply.

Неисправность 2. Служба на localhost

Остановите HTTP-сервер и запустите его с привязкой к 127.0.0.1:

pkill -f "http.server 8080"
python3 -m http.server 8080 --bind 127.0.0.1

С клиента curl получит connection refused, хотя ping до сервера работает.

Проверка: ss -tlnp | grep 8080 покажет 127.0.0.1:8080. Исправление: перезапустить службу с --bind 10.10.0.10 или 0.0.0.0.

Неисправность 3. Закрытый порт

Если ufw включён, поставьте запрет выше разрешающего правила:

sudo ufw insert 1 deny 8080/tcp

С клиента curl будет ждать и завершится по тайм-ауту. Это отличается от connection refused: служба работает, но пакеты не доходят. Если запрет добавить в конец, разрешающее правило может сработать раньше.

Проверка: sudo ufw status verbose. Исправление: удалить запрет и разрешить порт только из 10.10.0.0/24:

sudo ufw delete deny 8080/tcp
sudo ufw allow from 10.10.0.0/24 to any port 8080 proto tcp

Неисправность 4. Пропал default route

На клиенте удалите маршрут по умолчанию:

sudo ip route del default

Локальный ping до 10.10.0.10 продолжит работать, а curl -I https://example.com перестанет находить путь наружу.

Проверка: ip route, ping -c 3 10.10.0.10, curl -I https://example.com. Исправление: sudo netplan apply вернёт маршрут через NAT.

Неисправность 5. Неверный DNS

На клиенте временно подмените DNS:

sudo resolvectl dns enp0s3 192.0.2.1
sudo resolvectl flush-caches

Проверьте getent hosts example.com. Имя не разрешится, хотя IP-связность и маршрут остаются рабочими.

Проверка: resolvectl status, getent hosts example.com. Исправление: вернуть DNS от NAT командой sudo resolvectl revert enp0s3 или выполнить sudo netplan apply.

Заполняйте таблицу UIFIS_practice-8_diagnostics.csv по ходу работы. В колонку «Фактический результат» вписывайте короткий вывод команды, а в «Вывод» объясняйте, на каком слое была проблема.

Проверка Команда Что доказывает
Адреса ip -br a адрес и состояние интерфейса
Маршруты ip route локальная сеть и default
Связность ping доступность узла по ICMP
Соседи ip neigh разрешение MAC через ARP
Служба ss -tlnp процесс слушает нужный адрес
HTTP curl -I приложение отвечает
SSH ssh удалённый вход работает
Firewall ufw status порт разрешён или закрыт

10Шаг 8. Отчёт

Заполните шаблон UIFIS_practice-8_report-template.docx.

В отчёте должны быть:

  1. Цель и схема сети с двумя адаптерами.
  2. Параметры внутренней сети.
  3. Таблица проверок с фактическими результатами.
  4. Пять неисправностей: признак, проверка, исправление.
  5. Скриншоты настроек VirtualBox и команд.
  6. Вывод и ответы на контрольные вопросы.

В выводах объясните, как вы отличили ошибку маршрута от ошибки firewall и почему внутренняя сеть не должна иметь свой шлюз.
