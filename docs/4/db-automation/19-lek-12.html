01Одна идея

Каждую пятницу администратор делает одно и то же: запускает mysqldump, смотрит размер таблиц, удаляет записи старше года и записывает результат в блокнот. Однажды он пропускает пятницу из-за болезни, и неделя остаётся без копии. В другой раз удаляет не те строки, потому что перепутал дату в условии.

Автоматизация делает обслуживание повторяемым. Одна и та же программа с одними и теми же аргументами выполняет одну и ту же последовательность, пишет журнал и возвращает понятный код. Человек перестаёт быть источником случайности, а его работа сводится к проверке отчёта.

C# и .NET SDK 10 удобны тем, что дают типы, нормальную обработку ошибок и один способ сборки на все случаи. Программа собирается в файл, который запускает и человек из консоли, и Планировщик Windows.

02Проект и его структура

Проект создаётся одной командой в любом каталоге.

dotnet new console -n DeanAdmin
cd DeanAdmin
dotnet add package MySqlConnector

После этого в каталоге лежат три важные вещи.

DeanAdmin/
  DeanAdmin.csproj
  Program.cs
  bin/
  obj/

DeanAdmin.csproj описывает проект: целевую платформу, настройки языка и зависимости. Program.cs содержит код. bin и obj создаются сборкой, их не редактируют и не хранят в репозитории.

<Project Sdk="Microsoft.NET.Sdk">
  <PropertyGroup>
    <OutputType>Exe</OutputType>
    <TargetFramework>net10.0</TargetFramework>
    <Nullable>enable</Nullable>
    <ImplicitUsings>enable</ImplicitUsings>
  </PropertyGroup>
  <ItemGroup>
    <PackageReference Include="MySqlConnector" Version="2.4.0" />
  </ItemGroup>
</Project>

В шаблоне .NET 10 файл Program.cs не содержит класса и метода Main. Верхнеуровневые команды компилятор сам собирает в точку входа, а return в конце задаёт код возврата. Для небольшой утилиты это удобно: не нужно помнить про static void Main и отдельный массив args, он доступен по имени.

net10.0 это целевая платформа, и она должна совпадать с установленным SDK. Проверка простая:

dotnet --version

Команда должна показать версию 10. Если показана другая, проект не соберётся или соберётся под чужую платформу, и ошибка будет выглядеть как проблема с пакетом.

03Подключение к MySQL

MySqlConnector это независимый драйвер MySQL для .NET. Он даёт MySqlConnection, MySqlCommand и MySqlDataReader, то есть привычную модель ADO.NET.

using MySqlConnector;

var builder = new MySqlConnectionStringBuilder
{
    Server = "localhost",
    Port = 3306,
    Database = "dean",
    UserID = "dean_app",
    Password = Environment.GetEnvironmentVariable("DEAN_DB_PASSWORD"),
    CharacterSet = "utf8mb4"
};

await using var conn = new MySqlConnection(builder.ConnectionString);
await conn.OpenAsync();

Строка подключения собирается из частей, а не склеивается вручную. Причина проста: пароль с точкой с запятой или пробелом ломает склейку, а построитель экранирует значения сам.

Пароль берётся из переменной окружения. В коде его нет, в репозитории его нет, в журнале его тоже нет.

$env:DEAN_DB_PASSWORD = "UchebnyjParol2026"
dotnet run -- check

Соединение открывают как можно позже и закрывают как можно раньше. MySqlConnector держит пул соединений, поэтому OpenAsync обычно не создаёт новое TCP-соединение, а берёт готовое из пула, а await using возвращает его обратно даже при ошибке. Для программы обслуживания долгая жизнь соединения не нужна: одна команда, одно соединение, один результат.

Пароль в коде

Строка Password = "UchebnyjParol2026" в Program.cs попадает в git, в сборку и в журнал ошибок. Сменить пароль после утечки мало: он останется в истории коммитов. Пароль передают через переменную окружения или файл, который не входит в репозиторий.

04Что делает программа

Программа обслуживания решает три задачи: проверить состояние базы, сделать копию и почистить старые записи. Каждая задача это команда, а поведение задаётся аргументами.

Команда Что делает Что меняет
check считает строки, размеры и просроченные записи ничего
backup запускает mysqldump и проверяет файл файл на диске
cleanup удаляет записи старше года таблицу audit_log

Разделение на команды важнее, чем кажется. Флаг вида --do-everything через месяц обрастает условиями, и уже никто не помнит, в каком порядке выполняются шаги. Три отдельные команды запускаются по отдельности, проверяются по отдельности и в журнале выглядят как три разных события.

Неизвестная команда это ошибка аргументов, а не повод выполнить что-то по умолчанию.

if (command is not ("check" or "backup" or "cleanup"))
{
    Console.Error.WriteLine($"unknown command: {command}");
    return 2;
}

Ошибка аргументов возвращает код 2 и не трогает базу. Это правило кажется мелочью, пока опечатка в задании Планировщика не запускает не ту команду.

05Аргументы и режим проверки

Аргументы это единственный способ менять поведение, не пересобирая программу. Разбор стоит начать с проверки, что аргумент вообще передан.

if (args.Length == 0 || args[0] is "-h" or "--help")
{
    Console.WriteLine("usage: DeanAdmin <check|backup|cleanup> [--dry-run]");
    return 2;
}

var command = args[0];
var dryRun = args.Contains("--dry-run");

Флаг --dry-run означает «покажи, что сделаешь, но ничего не меняй». Это самая полезная привычка в автоматизации: сначала запуск в режиме проверки, потом боевой запуск.

if (dryRun)
{
    Log("INFO", $"plan command={command} changes=0");
    Console.WriteLine($"Будет выполнено: {command}");
    return 0;
}

Режим проверки отвечает на вопрос «сколько строк будет затронуто» до того, как они затронуты.

SELECT COUNT(*) FROM audit_log WHERE at < NOW() - INTERVAL 365 DAY;

Программа выполняет этот запрос и печатает число. Если число неожиданно большое, запуск останавливают и разбираются, а не удаляют данные.

06Параметризованные запросы

Значения никогда не подставляют в текст SQL через склейку. Для них есть параметры.

await using var cmd = new MySqlCommand(
    "UPDATE enrollments SET grade = @grade WHERE id = @id", conn);
cmd.Parameters.AddWithValue("@grade", grade);
cmd.Parameters.AddWithValue("@id", id);
await cmd.ExecuteNonQueryAsync();

Драйвер отправляет текст команды и значения отдельно, поэтому значение с кавычкой не меняет смысл запроса. Это защита от SQL-инъекции и одновременно защита от ошибок с датами и строками: параметр с @ получает тип и экранирование сам.

await using var cmd = new MySqlCommand(
    "SELECT COUNT(*) FROM students WHERE email = @email", conn);
cmd.Parameters.AddWithValue("@email", email);
var found = Convert.ToInt32(await cmd.ExecuteScalarAsync());

AddWithValue удобен, но тип он выводит по значению. Для DECIMAL и дат надёжнее указать тип явно:

cmd.Parameters.Add("@amount", MySqlDbType.Decimal).Value = amount;
cmd.Parameters.Add("@paid_at", MySqlDbType.DateTime).Value = paidAt;

07Журнал

Журнал это не отладочная печать, а рабочий документ. По нему восстанавливают, что произошло ночью, когда человека не было.

static void Log(string level, string message)
{
    var dir = Path.Combine(AppContext.BaseDirectory, "logs");
    Directory.CreateDirectory(dir);
    var line = $"{DateTime.UtcNow:yyyy-MM-ddTHH:mm:ssZ} {level} {message}";
    File.AppendAllText(Path.Combine(dir, "dean-admin.log"),
        line + Environment.NewLine);
}

Формат строки фиксированный: время в UTC, уровень, событие и числа. Такой журнал читается глазами и разбирается скриптом.

2026-04-03T21:00:02Z INFO start command=backup dry_run=false
2026-04-03T21:00:03Z INFO backup file=dean-2026-04-03.sql rows=41
2026-04-03T21:00:03Z INFO done elapsed_ms=1240 code=0

Три правила журнала: писать начало и конец, писать числа, не писать пароль. Строка password=... в журнале сводит защиту на нет.

Путь к журналу строится от каталога программы, а не от текущего каталога. Планировщик запускает задание из C:\Windows\System32, и относительный путь logs\dean-admin.log окажется совсем не там, где его ищут. AppContext.BaseDirectory всегда указывает на папку с DeanAdmin.exe.

Журнал растёт, поэтому раз в месяц его стоит чистить или переименовывать по дате. Простая ротация: если файл больше десяти мегабайт, он получает имя с датой, а новый начинается с пустого. Без ротации через год в одном файле будет миллион строк и поиск по нему займёт больше времени, чем сама работа.

08Обработка ошибок и коды возврата

Ошибки делятся на четыре группы, и каждой соответствует свой код.

Код Значение Что означает для задания
0 успех ничего
1 ошибка работы показывает сбой в отчёте
2 неверные аргументы сигнал об ошибке в задании
3 отказ базы сигнал о проблеме с MySQL 
try
{
    await conn.OpenAsync();
}
catch (MySqlException ex) when (ex.Number == 1045)
{
    Log("ERROR", $"access denied code={ex.Number}");
    return 3;
}
catch (MySqlException ex)
{
    Log("ERROR", $"mysql code={ex.Number} message={ex.Message}");
    return 1;
}
finally
{
    Log("INFO", "connection closed");
}

Номер ошибки важнее текста. Текст зависит от версии сервера и локали, а номер стабилен: 1045 это отказ доступа, 1062 дубликат ключа, 1205 истёк таймаут блокировки, 1213 взаимная блокировка.

return из верхнего уровня программы завершает её штатно: finally выполняется, файлы закрываются. Environment.Exit(1) завершает процесс немедленно и пропускает finally, поэтому его оставляют для аварийного выхода, а не для обычных ошибок.

Environment.Exit(1);

09Идемпотентность

Идемпотентность означает, что повторный запуск не меняет результат. Это главное свойство обслуживания: ночное задание может сработать дважды, и база не должна от этого пострадать.

Три приёма дают идемпотентность почти во всех задачах.

Проверка перед изменением. Программа сначала спрашивает, есть ли уже результат.

await using var check = new MySqlCommand(
    "SELECT COUNT(*) FROM schema_version WHERE version = @v", conn);
check.Parameters.AddWithValue("@v", version);
var applied = Convert.ToInt32(await check.ExecuteScalarAsync());
if (applied > 0) { Log("INFO", $"skip version={version}"); return 0; }

Условная вставка. Вместо INSERT используется команда, которая не падает на повторе.

INSERT INTO schema_version (version) VALUES (7)
ON DUPLICATE KEY UPDATE applied_at = applied_at;

Имя файла с датой. Копия за один день имеет одно имя, и второй запуск перезаписывает её, а не создаёт вторую.

var name = $"dean-{DateTime.Now:yyyy-MM-dd}.sql";

Сама копия делается внешней программой, потому что mysqldump умеет то, чего не умеет обычный SQL-запрос: выгрузить схему, данные и триггеры в один согласованный файл. Приложение запускает её как процесс и направляет вывод в файл.

var psi = new ProcessStartInfo(@"C:\xampp\mysql\bin\mysqldump.exe")
{
    RedirectStandardOutput = true,
    UseShellExecute = false
};
psi.ArgumentList.Add("--user=dean_app");
psi.ArgumentList.Add("--single-transaction");
psi.ArgumentList.Add("--default-character-set=utf8mb4");
psi.ArgumentList.Add("dean");

using var process = Process.Start(psi)!;
using var file = File.Create(Path.Combine(backupDir, name));
await process.StandardOutput.BaseStream.CopyToAsync(file);
await process.WaitForExitAsync();

Пароль здесь не передаётся аргументом: он виден в списке процессов. mysqldump читает его из файла настроек или из переменной окружения, а приложение проверяет код возврата процесса и размер полученного файла.

Класс Process живёт в пространстве System.Diagnostics, поэтому в начало файла добавляют using System.Diagnostics;. Без этой строки компилятор сообщит, что имя не найдено, хотя пакет установлен.

Почистка старых записей тоже идемпотентна: второй запуск в тот же день удаляет ноль строк, потому что подходящих записей уже нет.

DELETE FROM audit_log WHERE at < NOW() - INTERVAL 365 DAY;
Как быстро проверить идемпотентность?

Запустите команду дважды подряд и сравните журнал. Во втором запуске число изменённых строк должно быть нулевым, а код возврата тем же. Если второй запуск падает на дубликате ключа или создаёт второй файл, идемпотентности нет.

10Сборка и запуск

Во время разработки программу запускают через dotnet run. Аргументы отделяются двумя дефисами, иначе их перехватит сама команда.

dotnet run -- check --dry-run
dotnet run -- backup
dotnet run -- cleanup

Для Планировщика нужен готовый файл, а не исходники.

dotnet publish -c Release -o C:\DeanAdmin\publish

В каталоге publish появится DeanAdmin.exe и рядом библиотеки. Именно этот путь указывают в задании, потому что dotnet run требует SDK и рабочего каталога с исходниками.

Публикация занимает несколько секунд и не требует Visual Studio. Достаточно SDK и командной строки. Если нужно перенести программу на другой компьютер без установленного .NET, используют публикацию с параметром --self-contained, но для учебного стенда это лишнее: SDK там уже стоит.

11Типичные ошибки

  • Пароль в коде. Пароль попадает в git и в сборку. Лечение: переменная окружения и пользователь с минимальными правами.
  • Нет журнала. Ночью задание упало, утром никто не знает почему. Лечение: начало, конец и числа в каждой строке.
  • Скрипт ломает базу при повторном запуске. Второй запуск создаёт дубли или падает на уникальном ключе. Лечение: проверка версии, ON DUPLICATE KEY UPDATE, имя файла с датой.
  • Склейка SQL. "WHERE id = " + id открывает инъекцию и ломается на строках с кавычкой. Лечение: параметры.
  • Нет режима проверки. Первый запуск сразу меняет данные, и ошибка стоит дорого. Лечение: --dry-run и подсчёт строк до изменения.
  • Код возврата всегда 0. Планировщик считает успехом любой запуск, даже упавший. Лечение: разные коды для разных групп ошибок.

12Проверьте себя

Программа вернула 0, но данных в таблице нет. Что проверять?

Код 0 означает, что программа дошла до конца, а не что она сделала ожидаемое. Смотрят журнал: была ли команда, сколько строк она затронула, не сработал ли ранний выход по проверке версии. Частая причина это dryRun, оставленный включённым по умолчанию.

Почему Environment.Exit хуже return в обычной ошибке?

Environment.Exit завершает процесс сразу и не выполняет finally, поэтому соединение и файлы могут остаться незакрытыми, а последняя строка журнала не записаться. return из верхнего уровня даёт программе завершиться штатно.

Как сделать копию, которая не перезапишет вчерашнюю?

Дата в имени отделяет копию одного дня от копии другого: файлы dean-2026-04-02.sql и dean-2026-04-03.sql существуют одновременно. Если нужны несколько копий за день, в имя добавляют время до минут. Старые файлы удаляет отдельная команда по возрасту, иначе каталог растёт бесконечно.

13Итоги

  • dotnet new console и dotnet add package MySqlConnector дают основу приложения.
  • Строка подключения собирается построителем, пароль приходит из окружения.
  • Аргументы задают команду, --dry-run показывает план без изменений.
  • Параметры в SQL отделяют значения от текста команды.
  • Журнал фиксирует время, событие и числа, коды возврата сообщают результат.
  • Идемпотентность достигается проверкой, условной вставкой и именем файла с датой.
