01Два сервиса для одной полки

Перед командой «Склад+» стоит задача: отдать мобильному приложению список товаров и принимать новую карточку товара. Один разработчик открывает Flask, второй FastAPI. Через час у обоих работают два маршрута, оба отвечают JSON, оба запускаются одной командой. Разница проявляется позже: у первого клиент присылает цену строкой, и она молча сохраняется, у второго тот же клиент получает 422 со списком полей; у первого описание API живёт в документе Word, у второго открывается по адресу /docs и совпадает с кодом.

Фреймворк это набор готовых решений о том, как принять запрос, разобрать данные, вызвать код и собрать ответ. Flask и FastAPI решают эту задачу, но выбирают разные умолчания. Flask оставляет разработчику больше свободы и меньше подсказывает. FastAPI требует описать данные схемой и взамен проверяет их, строит документацию и подсказывает клиенту формат ошибки.

Выбор между ними не сводится к «что быстрее». Сначала нужно понять, какой контракт получает клиент, кто будет проверять данные и как быстро команда сможет объяснить API другой стороне. Эти вопросы важнее названия фреймворка.

02Flask: маршрут и функция

Приложение Flask начинается с объекта app и функций, привязанных к адресам. Декоратор @app.get(...) регистрирует функцию на метод GET, @app.post(...) на метод POST. Внутри функции доступны объект запроса request и помощники ответа jsonify, redirect, abort.

from flask import Flask, jsonify, request

app = Flask(__name__)
app.json.ensure_ascii = False

PRODUCTS = {
    42: {"id": 42, "sku": "SKU-1002", "title": "Шуруповёрт Makita DF333D", "price": 12450.0, "stock": 4, "category": "Инструмент"},
}


@app.get("/products/<int:product_id>")
def get_product(product_id: int):
    item = PRODUCTS.get(product_id)
    if item is None:
        return jsonify({"error": "Товар не найден"}), 404
    return jsonify(item)


if __name__ == "__main__":
    app.run(port=5057)

Запуск python app.py поднимает встроенный сервер на порту 5057. Обращение curl -i http://127.0.0.1:5057/products/42 возвращает:

HTTP/1.1 200 OK
Server: Werkzeug/3.1.9 Python/3.13.14
Content-Type: application/json
Content-Length: 132
Connection: close

{"category":"Инструмент","id":42,"price":12450.0,"sku":"SKU-1002","stock":4,"title":"Шуруповёрт Makita DF333D"}

Часть адреса в угловых скобках называется переменной маршрута. Запись <int:product_id> означает, что Flask примет только целое число и передаст его в функцию как аргумент. Если клиент запросит /products/abc, маршрут не совпадёт и сервер вернёт 404, не вызывая функцию. Без преобразователя product_id пришёл бы строкой, и сравнение со словарём по числовому ключу не сработало бы.

Путь запроса во Flask короткий. Рабочий процесс WSGI принимает соединение, разбирает HTTP-сообщение и передаёт его объекту приложения. Приложение ищет маршрут в таблице адресов, вызывает функцию и превращает возвращённое значение в HTTP-ответ. Если маршрут не найден, функция не вызывается, а клиент получает 404. Если функция выбросила исключение, в режиме разработки Flask покажет отладочную страницу с трассировкой, а в рабочем режиме вернёт 500.

Параметры запроса Flask достаёт из request.args. Это словарь, который ведёт себя как обычный словарь Python: request.args.get("category") возвращает строку или None.

@app.get("/products")
def list_products():
    category = request.args.get("category")
    items = list(PRODUCTS.values())
    if category:
        items = [p for p in items if p.get("category") == category]
    return jsonify({"count": len(items), "items": items})

Тело POST-запроса разбирает request.get_json(). Если заголовок Content-Type не равен application/json, Flask по умолчанию отвечает 415. Если JSON битый, ответ будет 400. Аргумент silent=True меняет поведение: вместо исключения функция вернёт None, и дальше разработчик сам решает, что отвечать клиенту.

@app.post("/products")
def create_product():
    data = request.get_json(silent=True) or {}
    if not data.get("sku") or not data.get("title"):
        return jsonify({"error": "Поля sku и title обязательны"}), 400
    new_id = max(PRODUCTS) + 1
    item = {"id": new_id, **data}
    PRODUCTS[new_id] = item
    return jsonify(item), 201, {"Location": f"/products/{new_id}"}

Ответ Flask собирает из возвращаемого значения. Словарь автоматически превращается в JSON, но код состояния по умолчанию 200. Чтобы вернуть 201, функция возвращает кортеж из тела, кода и заголовков. Порядок частей важен: сначала тело, затем код, затем словарь заголовков.

Ошибку в Flask можно вернуть кортежем, как в примере, или вызвать abort(404). Второй способ короче, но по умолчанию отдаёт HTML-страницу. Чтобы API оставался JSON, для abort регистрируют обработчик ошибок через @app.errorhandler(404). Без него клиент получает страницу на русском или английском языке, которую не может разобрать.

У такого подхода есть цена. Flask не знает, какие поля обязательны, какого они типа и что считать допустимой ценой. Всё это написано руками внутри функции. Если проверку забыть, ошибка проявится позже: либо 500 на None, либо отрицательная цена в базе. Чем больше маршрутов, тем больше одинаковых проверок приходится повторять.

03FastAPI: схема вместо ручной проверки

FastAPI строится вокруг аннотаций типов. Функция маршрута объявляет, что принимает и что возвращает, а фреймворк читает эти объявления и собирает проверку. Данные запроса описывают классом Pydantic: поля, типы и ограничения.

from fastapi import FastAPI, HTTPException
from pydantic import BaseModel, Field

app = FastAPI(title="Склад+ API", version="0.1.0")

PRODUCTS = {
    42: {"id": 42, "sku": "SKU-1002", "title": "Шуруповёрт Makita DF333D", "price": 12450.0, "stock": 4},
}


class ProductIn(BaseModel):
    sku: str = Field(min_length=3, examples=["SKU-5001"])
    title: str = Field(min_length=1)
    price: float = Field(gt=0)
    stock: int = Field(ge=0)


class Product(ProductIn):
    id: int


@app.get("/products/{product_id}", response_model=Product)
def get_product(product_id: int):
    item = PRODUCTS.get(product_id)
    if item is None:
        raise HTTPException(status_code=404, detail="Товар не найден")
    return item


@app.post("/products", response_model=Product, status_code=201)
def create_product(payload: ProductIn):
    new_id = max(PRODUCTS) + 1
    item = {"id": new_id, **payload.model_dump()}
    PRODUCTS[new_id] = item
    return item

Запуск python -m uvicorn fastapi_demo:app --port 5056 поднимает ASGI-сервер. Ответ на чтение выглядит почти как у Flask, но заголовки и порядок полей другие:

HTTP/1.1 200 OK
date: Sat, 31 Oct 2026 06:22:14 GMT
server: uvicorn
content-length: 97
content-type: application/json

{"sku":"SKU-1002","title":"Шуруповёрт Makita DF333D","price":12450.0,"stock":4,"id":42}

Разница видна на ошибке. Неизвестный идентификатор возвращает 404 и тело с полем detail:

HTTP/1.1 404 Not Found
content-type: application/json

{"detail":"Товар не найден"}

Неверное тело запроса доходит до функции только после проверки. Если отправить {"sku":"AB","title":"","price":-5,"stock":-1}, функция не вызовется, а клиент получит 422 и список нарушений. Фрагмент ответа:

{
  "detail": [
    {"type": "string_too_short", "loc": ["body", "sku"], "msg": "String should have at least 3 characters", "input": "AB"},
    {"type": "string_too_short", "loc": ["body", "title"], "msg": "String should have at least 1 character", "input": ""},
    {"type": "greater_than", "loc": ["body", "price"], "msg": "Input should be greater than 0", "input": -5},
    {"type": "greater_than_equal", "loc": ["body", "stock"], "msg": "Input should be greater than or equal to 0", "input": -1}
  ]
}

Каждый элемент списка называет место ошибки loc, правило type, сообщение msg и полученное значение input. Клиент может подсветить конкретное поле формы, не разбирая текст сообщения. Это заметно удобнее, чем одна строка «Неверные данные», которую возвращает ручная проверка.

response_model=Product описывает не только ответ, но и фильтр. FastAPI оставляет в ответе только поля, объявленные в модели. Если функция вернёт словарь с паролем или внутренним идентификатором, лишнее поле не попадёт к клиенту. Это защита от случайной утечки, а не замена продуманной модели.

Зависимости FastAPI оформляют через Depends. Функция может объявить, что ей нужна сессия базы, текущий пользователь или настройки, а фреймворк вызовет поставщика и передаст результат. Это не то же самое, что глобальная переменная: зависимость создаётся на запрос и освобождается после ответа. Для «Склад+» так подключают сессию SQLAlchemy и проверку токена, не повторяя код в каждом маршруте.

HTTPException прерывает выполнение и формирует ответ с полем detail. Это удобно для ошибок, которые зависят от данных: товар не найден, склад закрыт, остаток недостаточен. Ошибки формата до функции не доходят, поэтому смешивать их с HTTPException не нужно. Если нужен единый формат ошибок для всех маршрутов, добавляют обработчик исключений.

Валидация в FastAPI не отменяет проверку в базе. Схема проверяет формат: цена положительная, sku не короче трёх символов. Уникальность sku знает только база, и её нарушение придётся обработать отдельно, вернув 409. Схема и ограничение базы дополняют друг друга.

04Документация как побочный результат

FastAPI читает схемы и маршруты и строит OpenAPI-описание. По адресу /docs открывается интерактивная страница, где можно выбрать маршрут, заполнить параметры и отправить запрос. По адресу /openapi.json лежит машиночитаемое описание, из которого Postman импортирует коллекцию, а генератор клиента создаёт код.

Проверка на учебном сервисе:

> curl -s -o NUL -w "%{http_code} %{content_type}" http://127.0.0.1:5056/docs
200 text/html; charset=utf-8

Описание начинается так:

{
  "openapi": "3.1.0",
  "info": {"title": "Склад+ API", "version": "0.1.0"},
  "paths": {
    "/products/{product_id}": {
      "get": {
        "parameters": [
          {"name": "product_id", "in": "path", "required": true, "schema": {"type": "integer"}}
        ],
        "responses": {
          "200": {"description": "Successful Response"},
          "422": {"description": "Validation Error"}
        }
      }
    }
  }
}

Flask такой страницы не строит. Документацию добавляют расширениями, например flask-smorest или apispec, либо пишут вручную. Ручное описание быстро расходится с кодом: поле переименовали, документ остался прежним, клиент отправил старое имя и получил ошибку. Автоматическое описание не может разойтись с объявленной схемой, потому что строится из неё же.

Описание OpenAPI нужно не только для страницы. Из него импортируют коллекцию в Postman, генерируют клиентский код и проверяют, что сервер не потерял маршрут. Если маршрут есть в описании, а в коде его нет, клиент получит 404. Если маршрут есть в коде, но не попал в описание, клиент о нём не узнает. Поэтому описание проверяют вместе с кодом, а не после релиза.

Для учебной аудитории достаточно встроенного сервера. На рабочем сервере Flask запускают через waitress или gunicorn, FastAPI через uvicorn с несколькими рабочими процессами. Команда запуска и порт входят в контракт не меньше, чем маршруты: если сервис слушает другой порт, клиент не найдёт его по инструкции.

У автоматической документации есть обратная сторона. /docs и /openapi.json по умолчанию открыты всем, кто добрался до сервиса. Для учебного стенда это удобно, для рабочего контура страницу закрывают авторизацией или отключают в настройках. Описание API это карта системы, и не всякому клиенту её показывают.

05Сравнение без лозунгов

Flask и FastAPI часто сравнивают скоростью, но для выбора важнее свойства контракта и стоимость поддержки.

Признак Flask FastAPI
Базовый протокол WSGI, синхронный вызов ASGI, поддерживает async
Маршрут декоратор @app.get декоратор @app.get
Параметры пути преобразователи <int:id> аннотация типа product_id: int
Тело запроса request.get_json() вручную модель Pydantic в аргументе
Проверка данных пишется в функции по схеме, до вызова функции
Код ошибки проверки выбирает разработчик 422 автоматически
Документация расширения или вручную /docs и /openapi.json
Шаблоны страниц Jinja2 из коробки подключаются отдельно
Асинхронность ограниченная, WSGI полноценная, ASGI
Порог входа ниже, меньше понятий выше, нужны типы и Pydantic
Типичный проект небольшой сервис, сайт с шаблонами, дополнение к существующему коду новый API с контрактом и несколькими клиентами

Строка «асинхронность» требует пояснения. В Flask каждый запрос обрабатывается рабочим процессом. Пока функция ждёт ответа базы или внешнего сервиса, этот процесс занят, и чтобы обслужить больше клиентов, запускают несколько процессов. В FastAPI функция async def выполняется в событийном цикле и может отдать управление на время ожидания. Один процесс обслуживает много одновременных ожиданий, но только если внутри действительно есть await.

Если объявить async def и вызвать внутри блокирующую библиотеку requests, событийный цикл остановится на время запроса. Пользы от асинхронности не будет, а поведение станет хуже, чем у синхронной функции. Для асинхронного клиента берут httpx.AsyncClient, для базы используют асинхронный драйвер. Если библиотека синхронная, функцию объявляют обычным def, и FastAPI выполнит её в пуле потоков, не блокируя цикл.

Скорость зависит от нагрузки. Для редких запросов к небольшой базе разница между фреймворками незаметна. Для тысяч одновременных ожиданий внешнего API асинхронный сервер даёт выигрыш. Для тяжёлых вычислений на процесс разница снова исчезает, потому что узкое место в процессоре, а не в ожидании. Выбирать фреймворк по чужому графику производительности без своего сценария бессмысленно.

Экосистема тоже различается. У Flask больше готовых расширений и примеров, он давно живёт в учебных и корпоративных проектах. FastAPI моложе, но получил собственные расширения для базы, авторизации и фоновых задач. Если проект уже написан на Flask, добавление двух маршрутов дешевле, чем переписывание. Если API только начинается и у него будет несколько клиентов, схема и документация FastAPI экономят время на согласовании.

Проверка сервиса тоже различается по форме, но не по смыслу. Flask даёт app.test_client(), который вызывает приложение без сети. FastAPI даёт TestClient, построенный на httpx. В обоих случаях тест отправляет запрос, получает код и тело и проверяет их утверждениями. Разница в том, что FastAPI-тест может опираться на схему ответа, а Flask-тест проверяет словарь вручную.

Асинхронная работа с базой требует отдельного драйвера и сессии. Обычная сессия SQLAlchemy блокирует поток, поэтому в async def её либо не используют, либо оборачивают в пул потоков. Для учебного сервиса достаточно синхронной функции def: FastAPI выполнит её в пуле и не заблокирует цикл. Асинхронную сессию берут, когда запросов к базе много и они ждут диск или сеть.

06Что выбрать для «Склад+»

У «Склад+» есть сайт, мобильное приложение и будущая интеграция с бухгалтерией. Все три клиента обращаются к одним и тем же товарам, остаткам и накладным. Контракт должен быть описан один раз и проверяться на сервере, иначе каждый клиент придумает свои правила. Для такого сценария FastAPI подходит лучше: схема запроса и ответа лежит рядом с маршрутом, ошибка 422 единообразна, описание API доступно разработчику мобильного приложения без отдельного документа.

Flask остаётся разумным выбором в трёх случаях. Первый: сервис небольшой и состоит из нескольких маршрутов, а команда уже знает Flask. Второй: приложение отдаёт HTML-страницы и использует шаблоны Jinja2, где Flask сильнее. Третий: нужно добавить API к существующему Flask-проекту, и переписывание не окупается. В этих случаях ручная проверка и документация не исчезают, но их стоимость известна и приемлема.

Оба фреймворка могут работать в одном проекте. Например, старый Flask-портал с шаблонами и новый FastAPI-сервис за общим шлюзом. Клиент видит один адрес, шлюз направляет запросы по пути. Это не бесплатно: появляются два набора зависимостей, две конфигурации и две инструкции запуска. Решение оправдано, когда старая часть уже работает и переписывать её целиком не нужно.

Ещё один критерий это навыки команды. Схемы Pydantic требуют понимания типов и моделей. Если группа только начала работать с Python, Flask даст более короткий путь к первому работающему маршруту. Но короткий путь не отменяет проверку данных: её всё равно придётся написать, просто позже и, возможно, в каждом маршруте отдельно.

Стоимость переписывания считают не по строкам кода, а по риску. Если старый Flask-сервис обслуживает склад и его контракт проверен, перевод на FastAPI ради документации может стоить дороже, чем добавить описание к существующим маршрутам. Если API только проектируется, схема и проверка дешевле сразу, чем после подключения трёх клиентов.

Выбор фреймворка фиксируют в README и в описании архитектуры. Через полгода другой разработчик должен понять, почему выбран Flask или FastAPI, какие ограничения приняты и где лежит документация. Без этой записи выбор кажется случайным, и следующий проект начинают с нового фреймворка, ломая совместимость.

07Ошибки, которые проявляются после запуска

Код 200 вместо 201. В FastAPI маршрут создания по умолчанию возвращает 200, если не указан status_code=201. Клиент не понимает, создан ресурс или просто прочитан. Симптом: мобильное приложение не сохраняет идентификатор нового товара, потому что ищет его в другом ответе. Правильно указать код явно и вернуть Location, если клиент должен открыть карточку.

Схема проверяет не то. В модели стоит price: float, и этого достаточно для числа, но не для положительной цены. Клиент присылает -5, проверка проходит, товар сохраняется с отрицательной ценой. Симптом: отчёт по складу показывает отрицательную стоимость. Правильно добавить Field(gt=0) и всё равно проверить ограничение в базе.

response_model отсутствует. Функция возвращает объект базы целиком, включая поле с хешем пароля или внутренним комментарием. FastAPI сериализует всё, что смог. Симптом: в ответе появляется лишнее поле, которое клиент не должен видеть. Правильно объявить модель ответа и не возвращать сущность базы напрямую.

Блокирующий вызов в async def. Внутри асинхронной функции стоит requests.get или time.sleep. Событийный цикл останавливается, остальные запросы ждут. Симптом: под нагрузкой сервис отвечает по очереди, хотя объявлен асинхронным. Правильно использовать асинхронную библиотеку или объявить функцию обычной.

Проверка только на клиенте. Мобильное приложение проверяет обязательные поля, а сервер доверяет клиенту. Достаточно отправить запрос из Postman, чтобы сохранить товар без названия. Симптом: в базе появляются записи, которые не открываются в интерфейсе. Правильно проверять каждое поле на сервере, а клиентскую проверку считать подсказкой.

Разный формат ошибок. Один маршрут возвращает {"error": ...}, другой {"detail": ...}, третий HTML-страницу. Клиент не может написать один обработчик. Симптом: при ошибке приложение показывает пустой экран вместо сообщения. Правильно свести ошибки к одному формату через обработчики исключений.

CORS забыт. Браузерное приложение на другом порту получает ответ, но браузер его блокирует. Postman тот же запрос выполняет успешно. Симптом: «в Postman работает, в браузере нет». Правильно настроить список разрешённых источников на сервере, а не отключать защиту целиком.

Встроенный сервер в рабочем контуре. app.run() и uvicorn --reload предназначены для разработки. Они не рассчитаны на нагрузку и автоматический перезапуск. Симптом: сервис падает при первом же сбое и не поднимается. Правильно запускать через рабочий сервер и описать процесс в инструкции.

Отладочный режим остался включённым. app.run(debug=True) и uvicorn --reload показывают трассировку и перезапускают процесс при изменении файла. В рабочем контуре отладочная страница раскрывает пути, переменные и фрагменты кода. Симптом: после сбоя клиент видит внутренности приложения. Правильно выключать отладку в рабочей конфигурации и хранить её в настройках среды.

Исключение превращается в HTML. Flask по умолчанию отвечает HTML-страницей на необработанную ошибку, а FastAPI может отдать HTML, если ошибка возникла вне маршрута. Клиент, который ждёт JSON, падает на разборе. Симптом: Content-Type: text/html в ответе на API-запрос. Правильно добавить обработчик ошибок и вернуть JSON с кодом 500 и request_id.

Свобода или готовый контракт

Flask даёт меньше готовых решений и требует писать проверку и документацию руками. FastAPI требует описывать схемы, зато проверяет данные и строит документацию сам. Экономия времени зависит от числа маршрутов и клиентов: на двух маршрутах разница мала, на двадцати она заметна.

08Итоги

  • Flask регистрирует функции на маршруты и оставляет проверку данных разработчику.
  • FastAPI описывает запрос и ответ моделями Pydantic и проверяет данные до вызова функции.
  • FastAPI возвращает 422 со списком полей и строит OpenAPI-документацию по адресам /docs и /openapi.json.
  • response_model ограничивает набор полей в ответе и защищает от лишних данных.
  • Асинхронность помогает при ожидании ввода-вывода и не помогает при вычислениях.
  • Flask уместен в небольших сервисах, шаблонах и существующем коде, FastAPI в новом API с несколькими клиентами.
  • Проверка на клиенте не заменяет проверку на сервере, а формат ошибок должен быть единым.
