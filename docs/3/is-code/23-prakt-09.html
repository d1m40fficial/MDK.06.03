01Цель работы

Научиться работать с базой SQLite из программы: открывать соединение, выполнять выборку с параметрами, добавлять и изменять строки, завершать транзакцию и выводить результат в отчёт. Работа продолжает базу sklad.db из предыдущей практики, поэтому схема и данные уже готовы.

Результат работы это модуль db.py, скрипт report.py, файл report.csv и отчёт с результатами проверок. Скрипт читает остатки, добавляет товар, меняет цену, переносит партию между площадками и сохраняет отчёт в CSV. Отдельно сдаётся отчёт с объяснением, где именно фиксируются изменения.

03Краткие теоретические сведения

Соединение sqlite3.Connection открывает файл базы. Курсор выполняет команды и хранит результат. После чтения курсор отдаёт строки через fetchone(), fetchall() или цикл for. Свойство row_factory = sqlite3.Row позволяет обращаться к колонкам по имени, а не по номеру.

Изменения в SQLite выполняются внутри транзакции. commit() фиксирует её, rollback() отменяет. Если закрыть соединение без фиксации, незавершённая транзакция откатится. Контекстный менеджер with con фиксирует изменения при успешном выходе и откатывает при исключении, но не закрывает соединение.

Параметры запроса передаются отдельно от текста команды. В шаблоне ставят ?, а значения передают кортежем вторым аргументом execute. Для LIKE проценты остаются в значении, а не в шаблоне. Для IN число знаков вопроса должно совпадать с числом элементов списка.

Цена в учебной базе хранится целым числом копеек: 1290 рублей это 129000. Так сумма не накапливает погрешность, о которой говорилось в лекции 13. В отчёте копейки можно разделить на 100 только на выводе, а в базе и в расчётах держать целое число.

При переносе товара между площадками нужно изменить две строки: уменьшить количество на площадке отправления и увеличить на площадке назначения. Обе команды идут в одной транзакции. Если на отправлении не хватает товара, обе отменяются, и склад остаётся в прежнем состоянии.

Соединение открывают на короткое время и закрывают в finally. В учебном скрипте это одна операция, в веб-приложении одна обработка запроса. Долгое соединение держит файл и мешает другим процессам, а общее соединение на несколько потоков драйвер sqlite3 вообще запрещает. Если операция завершилась ошибкой, транзакция откатывается, а сообщение об ошибке должно остаться понятным пользователю.

04Ход работы

Шаг 1. Создайте модуль подключения

В папке db рядом с файлом базы создайте файл db.py. В нём будут две функции: connect открывает соединение с нужными настройками, open_db управляет транзакцией и закрытием.

import sqlite3
from contextlib import contextmanager
from pathlib import Path

DB_PATH = Path(__file__).with_name("sklad.db")


def connect():
    con = sqlite3.connect(DB_PATH)
    con.row_factory = sqlite3.Row
    con.execute("PRAGMA foreign_keys = ON")
    return con


@contextmanager
def open_db():
    con = connect()
    try:
        yield con
        con.commit()
    except Exception:
        con.rollback()
        raise
    finally:
        con.close()

Разберите код по частям. row_factory задаёт доступ к колонкам по имени. PRAGMA foreign_keys включает проверку связей в этом соединении. try передаёт соединение вызывающему коду, commit фиксирует успешную работу, except откатывает изменения при ошибке и пробрасывает исключение дальше, finally закрывает соединение в любом случае.

Проверьте модуль отдельным запуском. Выведите версию SQLite и количество товаров.

import sqlite3
from db import open_db

print("SQLite", sqlite3.sqlite_version)
with open_db() as con:
    print("Товаров:", con.execute("SELECT count(*) FROM products").fetchone()[0])

Ожидаемое число товаров после практики 8 равно восьми. Если файл не найден, проверьте, что db.py лежит в одной папке с sklad.db.

Шаг 2. Выведите остатки по площадке

Создайте файл report.py. Первая функция принимает название площадки и выводит артикул, название товара, количество и ячейку. Значение площадки передайте параметром, а не склейкой строки.

from db import open_db


def stock_by_warehouse(warehouse_title):
    with open_db() as con:
        rows = con.execute(
            "SELECT p.sku, p.title, st.qty, st.cell "
            "FROM stock AS st "
            "JOIN products AS p ON p.id = st.product_id "
            "JOIN warehouses AS w ON w.id = st.warehouse_id "
            "WHERE w.title = ? "
            "ORDER BY p.title",
            (warehouse_title,),
        ).fetchall()
    for r in rows:
        print(f"{r['sku']}  {r['title']}  {r['qty']}  {r['cell']}")


stock_by_warehouse("Москва")

Строка WHERE w.title = ? получает значение из кортежа (warehouse_title,). Обратите внимание на запятую: без неё Python передаст строку, и драйвер начнёт подставлять её символы по одному. Вывод должен содержать восемь строк для Москвы.

Добавьте в функцию два необязательных условия: категория и минимальное количество. Категорию передавайте названием, количество числом. Если параметр равен None, условие не добавляется. Для этого соберите список условий и список значений, а затем соедините их через AND. Не склеивайте значение в текст запроса.

Такой способ сборки условий часто называют динамическим запросом. Опасность здесь та же, что и в лекции: текст условий можно собрать из фрагментов, но значения должны остаться параметрами. Название категории и число попадают в список значений, а в шаблон добавляются только готовые куски AND c.title = ? и AND st.qty >= ?. Если бы название категории склеивали в строку, апостроф в названии сломал бы запрос.

Проверьте функцию на трёх наборах: площадка без фильтров, площадка с категорией «Электрика», площадка с минимальным количеством 100. Убедитесь, что число строк меняется, а ошибок нет.

Шаг 3. Добавьте товар и остаток одной транзакцией

Добавьте в report.py функцию add_product. Она принимает артикул, название, номер категории, цену в копейках, площадку, количество и ячейку. Сначала вставляется товар, затем его остаток. Идентификатор товара берётся из lastrowid и передаётся во вторую вставку.

def add_product(sku, title, category_id, price, warehouse_title, qty, cell):
    with open_db() as con:
        cur = con.execute(
            "INSERT INTO products (sku, title, category_id, price) VALUES (?, ?, ?, ?)",
            (sku, title, category_id, price),
        )
        product_id = cur.lastrowid
        con.execute(
            "INSERT INTO stock (warehouse_id, product_id, qty, cell) "
            "VALUES ((SELECT id FROM warehouses WHERE title = ?), ?, ?, ?)",
            (warehouse_title, product_id, qty, cell),
        )
    print("Добавлен товар", sku, "с номером", product_id)

Вызовите функцию для нового товара: артикул SKU-1013, название «Уровень строительный 600 мм», категория 2, цена 1290 рублей, то есть 129000 копеек, площадка «Москва», количество 10, ячейка A-03-01. Проверьте, что товар появился в выборке из шага 2.

Повторите вызов с тем же артикулом. База отклонит вставку сообщением UNIQUE constraint failed: products.sku. Это ожидаемая проверка уникальности. Обработайте её в функции через except sqlite3.IntegrityError и выведите понятное сообщение, не показывая пользователю весь стек.

Шаг 4. Измените цену и проверьте число строк

Добавьте функцию change_price. Она принимает артикул и новую цену, выполняет UPDATE и возвращает rowcount.

def change_price(sku, new_price):
    with open_db() as con:
        cur = con.execute(
            "UPDATE products SET price = ? WHERE sku = ?", (new_price, sku)
        )
        return cur.rowcount

Вызовите функцию для SKU-1013 и цены 1390 рублей, то есть 139000 копеек. Результат должен быть равен единице. Затем вызовите её для несуществующего артикула SKU-9999. Результат равен нулю, и это не ошибка базы: условие просто никого не нашло. В report.py обработайте ноль отдельно и выведите сообщение «Артикул не найден».

Сравните два подхода к проверке. Можно сначала выполнить SELECT, убедиться, что товар есть, и только потом обновлять. Можно сразу выполнить UPDATE и посмотреть на rowcount. Второй способ короче, но между проверкой и изменением данные могут успеть измениться, поэтому в конкурентной среде надёжнее один UPDATE с проверкой результата.

Шаг 5. Перенесите остаток между площадками

Перенос партии затрагивает две строки. На площадке отправления количество уменьшается, на площадке назначения увеличивается. Если строки назначения ещё нет, её нужно создать. Для этого удобен оператор INSERT ... ON CONFLICT ... DO UPDATE.

Сначала разберите минимальный пример. Он добавляет остаток или прибавляет количество, если пара площадки и товара уже есть.

INSERT INTO stock (warehouse_id, product_id, qty, cell)
VALUES (?, ?, ?, ?)
ON CONFLICT (warehouse_id, product_id) DO UPDATE SET qty = qty + excluded.qty;

excluded это строка, которую пытались вставить. Если конфликт по составному ключу произошёл, SQLite выполняет UPDATE и берёт количество из excluded.qty. Так одна команда заменяет проверку и две ветки кода.

Напишите функцию transfer. Она принимает название площадки отправления, название площадки назначения, артикул и количество. Внутри одной транзакции выполните четыре действия: прочитайте текущий остаток, проверьте, что его хватает, уменьшите остаток и выполните вставку с ON CONFLICT. Если остатка не хватает, поднимите ValueError с понятным сообщением. Контекстный менеджер откатит транзакцию.

Проверьте перенос 20 единиц SKU-1005 из Москвы в Тверь. До переноса в Москве 320, в Твери 140. После переноса должно стать 300 и 160. Затем попробуйте перенести 5000 единиц и убедитесь, что количества не изменились.

Обратите внимание на колонку cell. При конфликте она не обновляется: ячейка на площадке назначения уже существует и не должна меняться из-за переноса. Если товар приходит на новую площадку, ячейка берётся из параметра. В реальном складе ячейку выбирает кладовщик, а программа только проверяет, что она свободна или подходит по категории.

Проверьте также случай, когда товара на площадке отправления нет совсем. Запрос вернёт None, и функция должна выдать сообщение «Товар не найден на площадке», а не пытаться вычесть из None. Это ещё одна проверка пустого результата, теперь уже в операции записи.

Шаг 6. Обработайте пустой результат

Добавьте функцию product_info, которая ищет товар по артикулу и возвращает словарь с полями или None. Проверьте её на существующем и несуществующем артикуле.

def product_info(sku):
    with open_db() as con:
        row = con.execute(
            "SELECT id, sku, title, price FROM products WHERE sku = ?", (sku,)
        ).fetchone()
    if row is None:
        return None
    return {"id": row["id"], "sku": row["sku"], "title": row["title"], "price": row["price"]}

Вызовите функцию для SKU-1005 и для SKU-9999. В первом случае вернётся словарь, во втором None. В report.py обработайте None сообщением «Товар не найден» и не обращайтесь к полям. Это же правило действует в API: отсутствие записи даёт код 404, а не 500.

Шаг 7. Соберите отчёт по категориям

Напишите функцию category_report, которая для каждой площадки и категории считает число позиций и общее количество единиц. Результат сохраните в файл report.csv с разделителем ; и кодировкой utf-8-sig, чтобы Excel правильно открыл кириллицу.

import csv


def category_report():
    with open_db() as con:
        rows = con.execute(
            "SELECT w.title AS warehouse, c.title AS category, "
            "count(*) AS positions, sum(st.qty) AS total "
            "FROM stock AS st "
            "JOIN products AS p ON p.id = st.product_id "
            "JOIN categories AS c ON c.id = p.category_id "
            "JOIN warehouses AS w ON w.id = st.warehouse_id "
            "GROUP BY w.title, c.title "
            "ORDER BY w.title, c.title"
        ).fetchall()
    with open("report.csv", "w", encoding="utf-8-sig", newline="") as f:
        writer = csv.writer(f, delimiter=";")
        writer.writerow(["Площадка", "Категория", "Позиций", "Всего, шт"])
        for r in rows:
            writer.writerow([r["warehouse"], r["category"], r["positions"], r["total"]])

Первая строка CSV дана как образец заголовка. Остальные строки формируются из запроса. Проверьте, что число строк в файле на единицу больше числа групп в запросе: заголовок не входит в данные.

Кодировка utf-8-sig добавляет в начало файла служебный символ, по которому Excel понимает, что перед ним UTF-8. Без него кириллица в некоторых версиях Excel открывается как набор символов. Разделитель ; выбран потому, что запятая уже встречается в названиях товаров и в десятичных числах. Если открыть файл в Excel, каждая строка должна попасть в отдельные колонки, а не в одну длинную строку.

Добавьте в отчёт ещё одну выборку: товары, у которых общее количество на всех площадках меньше 10. Она покажет, что нужно заказать. Запрос использует GROUP BY по товару и HAVING sum(st.qty) < ?, где порог передаётся параметром. Условие HAVING отличается от WHERE: оно фильтрует уже сгруппированные строки, поэтому в нём можно использовать агрегатную функцию.

08Критерии оценки

Оценка выставляется по шкале от 1 до 5. - 5: соединение открывается и закрывается корректно, все значения передаются параметрами, добавление и обновление проверены по rowcount, перенос выполняется в одной транзакции с откатом, CSV сформирован, отчёт полный. - 4: основные операции работают, но в одном запросе значение склеено в строку или не обработан пустой результат. - 3: выборка работает, но добавление или перенос не завершены, транзакция не проверена, CSV отсутствует. - 2: работа не выполнена. - 1: работа выполнена с использованием ИИ или скопирована полностью или частично, 1 балл без возможности исправления.
