## Цель работы

Научиться проверять учебный сервер и сеть до него по одному чек-листу, а не по памяти. Вы последовательно смотрите ресурсы сервера, состояние служб, адресацию рабочего места, маршрут до сервера, разрешение имени и доступность порта приложения. Каждая проверка даёт факт, факт сравнивается с нормой, а расхождение попадает в таблицу отклонений с мерой устранения.

Результат работы это протокол проверки, в котором по каждому пункту есть команда, ожидаемый результат, фактический результат и вывод. Протокол заканчивается одним из трёх выводов: система доступна, доступна частично, недоступна.

## Оборудование и программное обеспечение

- Компьютер с Windows 10 или 11, PowerShell и браузером.
- VirtualBox с учебной виртуальной машиной Windows 10 в роли сервера, имя SRV-SKLAD.
- XAMPP 8.5.12 на виртуальной машине: Apache и MySQL запускаются из панели управления XAMPP.
- Учебная копия «Склад+» на виртуальной машине, адрес http://localhost:8080.
- Проброс порта 8080 с хоста на виртуальную машину в настройках сети VirtualBox, тип подключения NAT.
- Учебная учётная запись с правами обычного пользователя. Права администратора и изменения настроек хоста не требуются.
- Word для протокола, таблица чек-листа выдаётся преподавателем в виде файла или заполняется в тетради.

## Краткие теоретические сведения

Проверка сервера отвечает на вопрос, хватает ли ему ресурсов и работают ли службы. Четыре показателя дают первичную картину: загрузка процессора, свободная оперативная память, свободное место на системном диске и время работы без перезагрузки. Загрузка процессора выше 80 процентов в течение нескольких минут означает перегрузку. Свободное место ниже 15 процентов на системном диске опасно: журналы и временные файлы СУБД быстро добирают остаток, и служба останавливается. Время работы в сорок дней без перезагрузки говорит о том, что обновления не применялись.

Служба это программа, которая работает в фоне и слушает свой порт. В XAMPP за веб-часть отвечает служба Apache, за базу данных служба MySQL. Остановленная служба даёт тот же симптом, что обрыв сети: браузер пишет, что сайт недоступен. Разница видна по порту: адрес отвечает, а порт закрыт.

Проверка сети идёт по уровням. Сначала адресация: адрес, маска, шлюз, DNS. Потом маршрут: отвечает ли шлюз, проходит ли пакет до сервера, на каком прыжке он останавливается. Потом имя: разрешается ли sklad.servis-it.local в адрес. И только потом порт: принимает ли соединение программа на сервере.

Протокол проверки это документ, а не набор выполненных команд. В нём фиксируют объект, дату, исполнителя, стенд и каждый пункт с фактом. Без протокола проверка заканчивается фразой «вроде работает», которую нельзя предъявить ни заказчику, ни себе через месяц.

Отклонение это расхождение факта с нормой. У отклонения есть риск и мера. Например, свободно 8 процентов диска: риск в остановке СУБД, мера в очистке журналов и расширении диска. Отклонение без меры это жалоба, а не результат работы инженера.

## Ход работы

### Шаг 1. Подготовьте протокол

Откройте Word и создайте документ «Протокол проверки сервера и сети». В шапке укажите объект (учебный сервер SRV-SKLAD, копия «Склад+»), дату, свою фамилию, стенд (VirtualBox, Windows 10, XAMPP 8.5.12) и адрес приложения.

Сразу за шапкой поставьте таблицу проверок с пятью столбцами.

| Номер | Проверка | Команда | Норма | Факт |
|---|---|---|---|---|
| 1 | Загрузка процессора | Get-CimInstance Win32_Processor | до 80 процентов | |
| 2 | Свободное место на диске C | Get-CimInstance Win32_LogicalDisk | не ниже 15 процентов | |
| 3 | Служба Apache | Get-Service Apache2.4 | работает | |
| 4 | Служба MySQL | Get-Service mysql | работает | |
| 5 | Адресация рабочего места | ipconfig /all | адрес, маска, шлюз, DNS заполнены | |
| 6 | Шлюз | ping шлюза | ответ получен | |
| 7 | Маршрут до сервера | tracert адрес сервера | не больше трёх прыжков | |
| 8 | Имя приложения | Resolve-DnsName sklad.servis-it.local | адрес получен | |
| 9 | Порт приложения | Test-NetConnection адрес -Port 8080 | TcpTestSucceeded True | |
| 10 | Отклик приложения | запрос в браузере | страница входа открылась | |

Проверки выполняйте в этом порядке. Он идёт от ресурсов к приложению, и каждый следующий шаг опирается на предыдущий.

### Шаг 2. Проверьте ресурсы сервера

Подключитесь к виртуальной машине, откройте PowerShell и выполните команды.

```powershell
Get-CimInstance Win32_OperatingSystem | Select-Object LastBootUpTime
Get-CimInstance Win32_Processor | Select-Object LoadPercentage
Get-CimInstance Win32_LogicalDisk -Filter "DriveType=3" |
  Select-Object DeviceID, @{n="FreeGB";e={[math]::Round($_.FreeSpace/1GB,1)}},
  @{n="SizeGB";e={[math]::Round($_.Size/1GB,1)}}
Get-Process | Sort-Object WS -Descending | Select-Object -First 5 Name, WS
```

Запишите в протокол загрузку процессора, свободное место и время последней загрузки. Процент свободного места посчитайте сами: свободное делить на общий размер и умножать на сто.

Если свободного места меньше 15 процентов, откройте папку .../xampp/mysql/data и посмотрите размер файлов. Разросшиеся журналы и старые копии баз это типичная причина. Ничего не удаляйте: в учебной работе достаточно зафиксировать отклонение и предложить меру.

### Шаг 3. Проверьте службы и слушающие порты

Посмотрите состояние двух служб и список портов, которые они держат.

```powershell
Get-Service Apache2.4, mysql | Select-Object Name, Status, StartType
Get-NetTCPConnection -State Listen | Select-Object LocalAddress, LocalPort, OwningProcess
```

Служба в состоянии Running держит свой порт в списке прослушивания. Если служба остановлена, порта в списке не будет, и это сразу объясняет, почему приложение не открывается. Запишите в протокол состояние обеих служб и номера портов.

Порт 3306 не должен слушать внешний адрес. Если MySQL слушает 0.0.0.0:3306, база открыта всей сети, и это отклонение по безопасности. В учебном стенде такое встречается после правки настроек «чтобы подключаться с хоста».

### Шаг 4. Проверьте адресацию

Вернитесь на рабочее место, откройте PowerShell и посмотрите настройки.

```powershell
ipconfig /all
Get-NetIPConfiguration | Select-Object InterfaceAlias, IPv4Address, IPv4DefaultGateway
```

Проверьте четыре поля: адрес, маска, шлюз, DNS. Адрес из диапазона 169.254 означает, что DHCP не ответил. Пустой шлюз означает, что выход из подсети не настроен. Адрес DNS, которого нет в стенде, даёт отказ при работе по имени.

Отдельно проверьте доступность виртуальной машины. При подключении через NAT адрес виртуальной машины виден в окне VirtualBox, а проброс порта задан в настройках сети. Запишите оба адреса: адрес рабочего места и адрес сервера.

### Шаг 5. Проверьте маршрут и имя

Выполните четыре проверки подряд.

```powershell
ping <адрес шлюза>
tracert <адрес сервера>
Resolve-DnsName sklad.servis-it.local
Test-NetConnection <адрес сервера> -Port 8080
```

Ping шлюза подтверждает, что рабочее место видит свою сеть. Tracert показывает путь до сервера: в учебном стенде это один-два прыжка, в офисной сети «Северного склада» путь длиннее и включает туннель. Resolve-DnsName показывает, какой адрес вернул DNS. Если имя не разрешается, а по адресу приложение открывается, отклонение относится к DNS, а не к сети.

Test-NetConnection даёт строку TcpTestSucceeded. Пример ответа по закрытому порту:

```text
PS> Test-NetConnection 10.0.2.15 -Port 8080
TcpTestSucceeded : False
```

False означает, что пакет до сервера дошёл, но программа порт не слушает: смотрите состояние службы, а не кабель. True означает, что порт принимает соединения. Это разные выводы, и в протоколе они записываются по-разному. Повторите проверку для адреса своего стенда и порта 8080.

### Шаг 6. Проверьте приложение

Откройте браузер и перейдите по адресу приложения. Страница входа должна открыться за несколько секунд. Если страница открывается, но вход не выполняется, сеть и порт здесь уже не при чём: проблема в учётной записи, в базе или в самом приложении.

Замерьте время отклика грубо, по секундомеру или по вкладке сети в инструментах браузера. Значение больше пяти секунд на учебном стенде это повод посмотреть загрузку сервера и журнал приложения.

### Шаг 7. Разберите выписку дежурного и сведите отклонения

Перед сменой дежурный инженер снял выписку по серверу SRV-BUH другого клиента и не успел её разобрать. В выписке только факты, без оценок.

```text
12.11 08:40  LoadPercentage      94
12.11 08:40  LastBootUpTime      02.11.2026 6:12
12.11 08:41  C: free 9,1 GB of 119,0
12.11 08:41  Apache2.4           Running  Automatic
12.11 08:41  mysql               Running  Automatic
12.11 08:42  0.0.0.0:3306        LISTEN   PID 3888
12.11 08:42  0.0.0.0:80          LISTEN   PID 4120
12.11 08:43  ping 192.168.1.1    4 sent, 4 received, 0% loss
12.11 08:43  tracert 192.168.1.50   3 hops
12.11 08:44  Resolve-DnsName sklad.servis-it.local -> 192.168.1.50
12.11 08:45  TcpTestSucceeded   True (port 8080)
12.11 08:47  браузер             вход открылся за 9 с, вход выполнен
```

Найдите в выписке строки, где факт расходится с нормой из шага 1, и перенесите их в таблицу отклонений.

| Отклонение | Риск | Мера | Срок |
|---|---|---|---|
| свободно 3 процента на диске D рабочего места кладовщика | не сохранится выгрузка отчёта | очистить папку временных файлов | сегодня |
| | | | |
| | | | |

Первая строка это образец формы, к SRV-BUH она не относится. Свои факты по SRV-SKLAD из шагов 2-6 добавьте отдельными строками.

Вывод соберите из трёх частей: сколько пунктов проверено, сколько оказалось вне нормы, какая из трёх оценок доступности следует из фактов. Пример формы на другом объекте: «Проверено десять пунктов по принтеру склада в Калуге, вне нормы один: служба диспетчера печати остановлена, очередь заданий не обрабатывается. Устройство недоступно». Фраза «всё работает» выводом не является: она не говорит, что именно проверено и что осталось сломанным.

В конце протокола поставьте дату, подпись и список выполненных команд. Команды нужны для повторной проверки: через неделю другой инженер должен получить те же факты теми же средствами.

- Заполненную таблицу из десяти проверок с командами, нормами и фактами.
- Таблицу отклонений с риском, мерой и сроком по каждому пункту.

## Критерии оценки

Оценка выставляется по шкале от 1 до 5.

| Оценка | Условие |
|---|---|
| 5 | Работа выполнена полностью и самостоятельно, все пункты ниже выполнены |
| 4 | Работа выполнена, есть 1 или 2 незначительных замечания |
| 3 | Работа выполнена частично, есть существенные замечания |
| 2 | Работа не выполнена |
| 1 | Работа выполнена с использованием ИИ или скопирована полностью или частично, 1 балл без возможности исправления |

Что проверяется:
- Все десять проверок выполнены и записаны с фактами.
- Команды указаны точно и их можно повторить.
- Нормы сравнения названы для каждого показателя.
- Отклонения найдены и описаны с риском и мерой.
- Вывод о доступности опирается на факты протокола.
- Протокол оформлен аккуратно, с датой и подписью.

Протокол без отклонений принимается только в том случае, если все десять проверок действительно в норме и это видно по фактам. Пустая графа «Факт» возвращает работу на доработку.
