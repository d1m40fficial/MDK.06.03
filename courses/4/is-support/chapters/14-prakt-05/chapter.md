## Цель работы

В среду 28 октября в 09:07 в поддержку «Сервис-ИТ» поступило три обращения из тульского склада «Северного склада». «Склад+» открывается, но при входе появляется «Ошибка 500». К 09:12 такие же сообщения пришли из Москвы, значит проблема не в одном рабочем месте. Система не работала до 09:46.

Цель работы: пройти путь от симптома до причины по слоям, проверить доступность сервера, портов и служб, найти узкое место по журналам и оформить карту диагностики. Результат работы это дерево проверок, протокол команд с результатами и карточка причины.

## Оборудование и программное обеспечение

- Персональный компьютер с Windows 10 и XAMPP 8.5.12.
- Запущенные модули Apache и MySQL в XAMPP Control Panel.
- Браузер и PowerShell.
- Python 3 из комплекта VS Code для создания файлов стенда.
- VS Code для страницы проверки и заметок.
- Word или draw.io для карты диагностики.
- Рабочая папка `.../sklad/incident`.

## Краткие теоретические сведения

**Диагностика** это последовательное исключение версий. Симптом описывает, что видит пользователь, причина объясняет, что сломалось. Между ними слои: рабочее место, сеть, имя, порт, служба, ресурсы сервера, приложение, данные. Проверка идёт по пути запроса, а не по списку удобных команд.

**Дерево проверок** это план до выполнения команд. В нём для каждого слоя указано, что проверяется, каким инструментом, какой результат считается нормой и что означает отклонение. Дерево не даёт перескакивать через слои и возвращаться к уже исключённым версиям.

**Проверка доступности** начинается с адреса рабочего места. Адрес `169.254.x.x` означает, что DHCP не ответил. Затем проверяют достижимость узла командой `ping` и маршрут командой `tracert`. Успешный ping доказывает только то, что узел отвечает, и ничего не говорит о службе.

**Проверка порта** идёт дальше. `Test-NetConnection` устанавливает TCP-соединение с конкретным портом и показывает `TcpTestSucceeded`. Открытый порт означает, что процесс слушает и принимает соединения, но не гарантирует правильный ответ приложения.

**Проверка приложения** использует `curl`. Команда показывает код ответа, заголовки и тело. Код 500 означает ошибку внутри приложения, 502 и 503 означают проблему со службой за веб-сервером, 504 означает, что служба не ответила вовремя.

**Проверка службы** отвечает на вопрос, запущен ли процесс и слушает ли он порт. В XAMPP MySQL часто работает как процесс `mysqld.exe`, а не как служба Windows. Поэтому смотрят и панель XAMPP, и список процессов, и порт.

Состояние службы и состояние порта проверяют вместе. Процесс может быть запущен, но слушать другой адрес или другой порт, и тогда снаружи он недоступен. Обратная картина тоже бывает: порт открыт, а приложение внутри возвращает ошибку. Поэтому вывод делают по двум проверкам, а не по одной.

**Карточка причины** это короткий документ: симптом, слой, доказательства, причина, решение, меры. Она отличается от протокола тем, что содержит вывод, а не перечень команд.

**Снимок состояния** это набор результатов проверок, снятых в момент сбоя. Снимок нужен, потому что после восстановления часть признаков исчезает: порт снова открыт, процесс запущен, ошибка в журнале осталась единственным следом. Поэтому результаты команд записывают сразу, а не восстанавливают по памяти.

**Время обнаружения** это промежуток от первого сообщения до момента, когда причина названа. Оно зависит не от сложности команд, а от порядка проверок. Дерево, построенное заранее, сокращает это время сильнее, чем знание редких утилит.

## Ход работы

### Шаг 1. Разберите обращение

Создайте папку `.../sklad/incident` и файл `make_incident.py`. Скрипт запишет обращение, журнал СУБД, снимок проверок, сценарий резервного копирования и историю задачи.

```python
from pathlib import Path

base = Path(r".../sklad/incident")
base.mkdir(parents=True, exist_ok=True)

files = {
"ticket.txt": """
INC-2026-1046, 28.10.2026 09:07, Тула
Симптом: страница входа открывается, после ввода логина ошибка 500.
Затронуты: три пользователя в Туле, с 09:12 жалобы из Москвы.
Что не работает: вход и сохранение заказов. Главная страница открывается.
""",
"mysql_error.log": """
2026-10-28T09:04:58.112034+03:00 0 [Note] InnoDB: Starting shutdown...
2026-10-28T09:05:02.441877+03:00 0 [Note] InnoDB: Shutdown completed
2026-10-28T09:05:11.008213+03:00 0 [ERROR] InnoDB: Unable to lock ./ibdata1 error: 32
2026-10-28T09:05:11.008390+03:00 0 [Note] InnoDB: Check that you do not already have another mysqld process using the same InnoDB data or log files.
2026-10-28T09:05:11.008512+03:00 0 [ERROR] InnoDB: Unable to open the system tablespace or log files, aborting
2026-10-28T09:05:11.008640+03:00 0 [ERROR] Aborting
""",
"checks_0907.txt": """
ping 10.10.4.10: отправлено 4, получено 4, потерь 0
Test-NetConnection 10.10.4.10 -Port 80: TcpTestSucceeded True
Test-NetConnection 10.10.4.10 -Port 3306: TcpTestSucceeded False
curl -i http://sklad.local/login: HTTP/1.1 500 Internal Server Error
Get-Process mysqld: процесс не найден
""",
"backup.bat": """
@echo off
mysqladmin -u root shutdown
start /b robocopy .../xampp/mysql/data .../backup/mysql /MIR /R:1 /W:1
start /b mysqld --standalone

for name, text in files.items():
    (base / name).write_text(text.strip() + "\n", encoding="utf-8")
print("создано файлов:", len(files))
```

Прочитайте `ticket.txt` и выпишите границы: что работает, что нет, кто затронут, когда началось. Главная страница открывается, значит веб-сервер отвечает, и версия «сервер выключен» маловероятна.

### Шаг 3. Подготовьте страницу проверки

Создайте `.../xampp/htdocs\sklad\check_db.php`. Страница пытается подключиться к MySQL и возвращает 500, если соединения нет.

```php
<?php
$db = @new mysqli('127.0.0.1', 'root', '');
if ($db->connect_errno) {
    http_response_code(500);
    echo 'DB error: ' . $db->connect_errno;
    exit;
}
echo 'OK';
```

Откройте `http://localhost/sklad/check_db.php` в браузере. При работающей MySQL страница показывает `OK`. Затем проверьте ответ командой.

```powershell
curl.exe -i -m 5 http://localhost/sklad/check_db.php
```

Вывод команды выглядит так.

```text
HTTP/1.1 200 OK
Date: Wed, 28 Oct 2026 06:12:03 GMT
Content-Length: 2

OK
```

Первая строка содержит код ответа, дальше идут заголовки, после пустой строки начинается тело. Ключ `-i` показывает и заголовки, и тело, ключ `-m 5` ограничивает ожидание пятью секундами. Запишите код ответа: он понадобится для сравнения со снимком стенда.

### Шаг 4. Проверьте рабочее место, сеть и порты

Выполните команды на своём компьютере и запишите результат. Эти проверки нужны, чтобы освоить порядок, а не чтобы воспроизвести сбой стенда.

```powershell
ipconfig
ping 127.0.0.1
Test-NetConnection localhost -Port 80
Test-NetConnection localhost -Port 3306
```

Команда `Test-NetConnection` печатает несколько строк, решение принимают по одной.

```text
ComputerName     : localhost
RemotePort       : 80
TcpTestSucceeded : True
```

`True` означает, что процесс принимает соединения на этом порту, `False` означает, что соединение не установилось. Остальные строки показывают, куда именно шло подключение.

Сравните свои результаты с `checks_0907.txt`. На стенде ping проходил, порт 80 был открыт, порт 3306 закрыт, а страница входа отдавала 500. Такую картину нужно объяснить словами: какие версии она исключает и какая остаётся.

### Шаг 5. Воспроизведите симптом

Остановите MySQL в XAMPP Control Panel кнопкой Stop. Подождите несколько секунд и повторите проверки.

```powershell
curl.exe -i -m 5 http://localhost/sklad/check_db.php
Test-NetConnection localhost -Port 3306
Get-Process mysqld -ErrorAction SilentlyContinue
```

Запишите три результата в протокол. Сравните их со снимком стенда: набор признаков должен совпасть. Затем запустите MySQL снова и убедитесь, что страница вернула 200.

Симптом воспроизведён, но причина ещё не найдена. Остановка вручную объясняет текущее состояние учебного ПК, а не события на стенде. Причину дают журналы.

### Шаг 7. Восстановите работу и проверьте

На стенде администратор остановил копирование, дождался освобождения файлов и запустил MySQL через панель XAMPP. Время восстановления составило 41 минуту, из них 39 минут ушло на обнаружение причины.

На учебном ПК выполните те же действия: запустите MySQL, дождитесь состояния Running, проверьте порт и страницу.

```powershell
Test-NetConnection localhost -Port 3306
curl.exe -i -m 5 http://localhost/sklad/check_db.php
```

Проверка считается законченной, когда порт открыт, страница возвращает 200 и вход в систему проходит под тестовой учётной записью. Одного запуска службы недостаточно: процесс может подняться и снова упасть.

Запишите время каждого действия: когда остановили MySQL, когда заметили отказ, когда нашли причину, когда восстановили работу. Эти четыре отметки показывают, где теряется время: на стенде почти всё время ушло на поиск причины, а не на ремонт.

## Что сдать

- Дерево проверок на семь слоёв с признаками нормы и сбоя.
- Протокол из семи шагов с результатами команд и выводами.
- Карточку причины с доказательствами и тремя мерами.
- Подтверждение восстановления: код 200, открытый порт 3306, успешный вход.
- Краткий вывод о том, какие версии были исключены и на каком шаге.

## Критерии оценки

Оценка выставляется по шкале от 1 до 5.

| Оценка | Условие |
|---|---|
| 5 | Работа выполнена полностью и самостоятельно, все пункты ниже выполнены |
| 4 | Работа выполнена, есть 1 или 2 незначительных замечания |
| 3 | Работа выполнена частично, есть существенные замечания |
| 2 | Работа не выполнена |
| 1 | Работа выполнена с использованием ИИ или скопирована полностью или частично, 1 балл без возможности исправления |

Что проверяется:
- **Дерево проверок.** Слои идут по порядку, признаки сформулированы
- **Проверки сети и портов.** Команды выполнены, результаты записаны
- **Воспроизведение симптома.** Код 500 и закрытый порт подтверждены
- **Разбор журналов.** Найдены время, код 32 и причина в сценарии
- **Карточка причины.** Причина доказана, меры конкретны
- **Оформление.** Протокол читается, выводы не противоречат данным
