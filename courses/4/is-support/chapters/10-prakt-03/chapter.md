## Цель работы

Собрать рабочий каталог запросов для «Северного склада», провести по нему заявку на доступ и настроить мониторинг доступности учебной ИС. Вы должны не просто создать учётную запись и запустить скрипт, а показать весь путь: от формулировки услуги до подтверждения пользователя и от датчика до понятного оповещения.

Результат работы это каталог запросов, оформленная заявка с проверкой прав, скрипт проверки доступности, журнал измерений и карта мониторинга с таблицей алертов.

## Оборудование и программное обеспечение

- Персональный компьютер с VS Code и Python, табличным и текстовым редактором.
- Локальный учебный стенд: страница или служба, доступная по адресу `http://localhost:8080/`.
- Терминал для запуска простого веб-сервера и скрипта проверки.
- XAMPP с MySQL и phpMyAdmin, если в вашем варианте нужно проверить доступность базы.
- Регламент поддержки, SLA и каталог услуг из практик 1 и 2.

## Краткие теоретические сведения

### Запрос и его место в процессе

Запрос на обслуживание это штатная просьба получить услугу, не связанная со сбоем. Запрос проходит путь: выбор услуги в каталоге, заполнение формы, согласование, выполнение, проверка результата, подтверждение и закрытие. Каждый шаг оставляет след в карточке, поэтому заявку можно восстановить через месяц.

Каталог запросов отличается от простого списка услуг. У позиции есть форма с обязательными полями, маршрут согласования, срок и формулировка результата. Без формы пользователь пишет свободным текстом, а поддержка каждый раз выясняет одно и то же.

### Доступ по принципу минимальных привилегий

Доступ выдаётся под задачу, а не «на всякий случай». Для кладовщика это роль с операциями прихода, расхода и перемещения в пределах своего склада. Просмотр финансовых отчётов, изменение справочников и администрирование в эту роль не входят.

Проверка прав идёт по матрице: роль, объект, действие. Если сотруднику нужна дополнительная операция, её оформляют отдельной заявкой с обоснованием и сроком. Накопленные лишние права опасны тем, что через полгода никто не помнит, зачем они выданы.

### Мониторинг доступности

Доступность проверяют активным запросом к услуге. Скрипт обращается по адресу, измеряет время ответа и сравнивает результат с порогом. Результат каждой проверки записывают в файл: время, код ответа, время выполнения, состояние.

Порог должен иметь длительность и уровень. Кратковременный скачок не повод будить дежурного, а устойчивое отклонение повод. Оповещение содержит объект, показатель, текущее значение, время начала и ссылку на инструкцию.

### Ложные срабатывания

Ложное срабатывание не требует действий и снижает доверие к мониторингу. Причины обычно простые: слишком узкий порог, отсутствие длительности, проверка во время плановой работы, дублирующие правила. Настройка важнее количества датчиков.

### Шаг 5. Подготовьте проверку доступности

Создайте файл `check_availability.py`. Ниже минимальный рабочий пример: он проверяет один адрес, измеряет время ответа и печатает результат. Разберите его по строкам, затем доработайте под задание.

```python
from time import perf_counter
from urllib.request import urlopen

URL = "http://localhost:8080/"
THRESHOLD_SECONDS = 2.0

start = perf_counter()
try:
    with urlopen(URL, timeout=5) as response:
        code = response.status
    state = "ok" if perf_counter() - start < THRESHOLD_SECONDS else "slow"
except Exception:
    code = 0
    state = "down"

print(code, round(perf_counter() - start, 3), state)
```

`urlopen` отправляет GET-запрос и возвращает объект ответа, `response.status` даёт код. `perf_counter` снимает время до и после запроса, разница это время ответа в секундах. Исключение означает, что служба не отвечает: код 0, состояние `down`. Порог сравнивается с измеренным временем, а не с кодом ответа.

Доработайте скрипт: добавьте запись каждой проверки в `availability.csv` (время, код, время ответа, состояние), второй адрес для отдельного файла в той же папке и строку `ALERT` при выходе за порог. Первую строку журнала заполните вручную как образец, остальные должен писать скрипт.

Запустите учебную службу в отдельном терминале.

```text
python -m http.server 8080
```

Команда поднимает простой веб-сервер в текущей папке: он отдаёт файлы по адресу `http://localhost:8080/` и печатает в терминал каждый запрос. Такой сервер удобен тем, что его можно остановить и запустить, не меняя настройки Windows.

Проверьте, что страница открывается в браузере. Затем запустите скрипт и убедитесь, что в `availability.csv` появилась строка с состоянием `ok`, кодом 200 и временем ответа меньше порога.

## Критерии оценки

Оценка выставляется по шкале от 1 до 5.

| Оценка | Условие |
|---|---|
| 5 | Работа выполнена полностью и самостоятельно, все пункты ниже выполнены |
| 4 | Работа выполнена, есть 1 или 2 незначительных замечания |
| 3 | Работа выполнена частично, есть существенные замечания |
| 2 | Работа не выполнена |
| 1 | Работа выполнена с использованием ИИ или скопирована полностью или частично, 1 балл без возможности исправления |

Что проверяется:
- **Каталог запросов.** Восемь позиций, форма, согласующий, результат
- **Разбор обращений.** Типы определены верно, обоснование проверяемое
- **Заявка на доступ.** Основание, срок, роль, согласующий
- **Проверка прав.** Лишние операции отмечены, вывод сделан
- **Скрипт и журнал.** Записаны `ok` и `down`, порог работает
- **Карта мониторинга.** Восемь объектов, пороги числами, владельцы
- **Таблица алертов.** Уровень, канал, действие, длительность
- **Оформление.** Документы читаемы, названия едины
