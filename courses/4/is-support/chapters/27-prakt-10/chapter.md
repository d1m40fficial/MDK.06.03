## Цель работы

Научиться описывать доступы так, чтобы их можно было проверить: построить матрицу ролей для «Северного склада», найти в выданных доступах лишние права, оформить заявку на доступ, выполнить её в учебной базе и зафиксировать изменения в журнале.

Результат работы это четыре артефакта: матрица доступа, заполненная заявка, журнал изменений доступов и вывод о найденных избыточных правах с мерами.

## Оборудование и программное обеспечение

- Компьютер с Windows 10 или 11, браузером и PowerShell.
- XAMPP 8.5.12 с MySQL или MariaDB и phpMyAdmin, панель управления XAMPP запущена.
- Учебная база sklad с таблицами orders, order_lines, stock и справочником пользователей.
- Учётная запись MySQL с правами создавать пользователей и роли.
- Word для отчёта, Excel для матрицы или таблица в Word.
- VirtualBox с учебной Windows 10, если проверяете блокировку локальной учётной записи.

## Краткие теоретические сведения

Доступ описывают двумя сущностями. Роль это именованный набор прав на объекты. Учётная запись это человек или служба, которой назначена роль. Пока права выдаются роли, а не человеку, матрица остаётся проверяемой: достаточно посмотреть, какие роли у сотрудника, и сравнить их с его должностью.

Минимальные привилегии означают, что роль получает только нужные действия над нужными объектами. Кладовщику нужны чтение остатков своего склада и создание документов приёмки. Удаление заказов, просмотр закупочных цен и управление пользователями ему не нужны, даже если технически это несложно выдать.

Лишние права накапливаются по трём причинам. Сотрудника перевели, а старую роль не сняли. Доступ выдали временно и забыли закрыть срок. Права добавили напрямую в обход роли, чтобы быстро решить частную задачу. Каждая причина оставляет след в журнале, поэтому журнал изменений ведут с первого дня.

Заявка на доступ содержит фамилию и подразделение, объект, действие, причину, срок и согласователя. Без срока заявка не принимается. Отзыв доступа оформляется так же, как выдача: с основанием и подписью руководителя.

Блокировка отличается от удаления. Заблокированная запись остаётся в системе, но войти под ней нельзя. Удаление убирает запись, и история действий по ней становится недоступной. Поэтому при увольнении сначала блокируют, а удаляют через тридцать дней.

## Ход работы

### Шаг 1. Подготовьте отчёт и исходные данные

Создайте в Word документ «Отчёт по доступам ООО "Северный склад"». В шапке укажите дату, фамилию, название учебного стенда и имя базы.

Возьмите список сотрудников и выданных ролей. В учебном кейсе он такой.

| Логин | Сотрудник | Должность | Роли в системе | Примечание |
|---|---|---|---|---|
| ivanova.ao | Иванова А. О. | менеджер по продажам | Менеджер, Бухгалтер | подменяла коллегу в июле |
| petrov.vs | Петров В. С. | кладовщик, Тверь | Кладовщик, Администратор ИС | настраивал принтер |
| sidorova.en | Сидорова Е. Н. | бухгалтер | Бухгалтер, Менеджер | помогала с заказами |
| kuznetsov.dm | Кузнецов Д. М. | кладовщик, Тула | Кладовщик | уволен 12.10 |
| sklad-service-backup | служба копирования | сервисная запись | Администратор ИС | владелец не указан |
| morozov.ii | Морозов И. И. | стажёр | Менеджер, прямой доступ к закупочным ценам | принят 01.11 |

Скопируйте таблицу в отчёт и допишите столбец «Избыточные права» пустым.

### Шаг 2. Постройте матрицу доступа

Нарисуйте таблицу, где строки это роли, столбцы это объекты. Используйте обозначения: Ч для чтения, С для создания, И для изменения, У для удаления, А для администрирования. Пустая ячейка означает запрет.

| Роль | Заказы | Остатки | Приёмка | Отгрузка | Закупочные цены | Отчёты | Пользователи |
|---|---|---|---|---|---|---|---|
| Кладовщик | | | | | | | |
| Менеджер по продажам | | | | | | | |
| Бухгалтер | | | | | | | |
| Администратор ИС | | | | | | | |
| Инженер поддержки | | | | | | | |
| Аудитор | | | | | | | |

Заполните матрицу по правилам кейса.

- Кладовщик читает остатки и заказы, создаёт и изменяет приёмку и отгрузку, видит отчёты только по своему складу.
- Менеджер по продажам создаёт и изменяет заказы, читает остатки и отгрузку, видит отчёты. Закупочные цены ему недоступны.
- Бухгалтер читает все документы и закупочные цены, видит отчёты, но не меняет заказы.
- Администратор ИС читает все объекты, управляет пользователями и видит журнал действий.
- Инженер поддержки читает объекты и журнал, но не меняет данные клиента и не управляет пользователями.
- Аудитор только читает, включая журнал действий, и ничего не меняет.

Проверьте матрицу двумя вопросами: может ли роль сделать лишнее и хватает ли ей прав для работы. Запишите в отчёт по одному примеру на каждый ответ.

### Шаг 3. Найдите избыточные права

Сравните таблицу сотрудников с матрицей и заполните столбец «Избыточные права». Для каждой строки укажите, какая роль лишняя и почему.

| Логин | Лишняя роль или право | Риск | Решение |
|---|---|---|---|
| ivanova.ao | | | |
| petrov.vs | | | |
| sidorova.en | | | |
| kuznetsov.dm | | | |
| sklad-service-backup | | | |
| morozov.ii | | | |

Ориентиры для проверки. У менеджера после подмены осталась роль бухгалтера, а вместе с ней доступ к закупочным ценам. У кладовщика роль администратора ИС появилась ради настройки принтера и даёт управление пользователями. У бухгалтера лишняя роль менеджера позволяет менять заказы. У уволенного кладовщика запись активна. Сервисная запись имеет административные права и не имеет владельца. У стажёра есть прямой доступ к закупочным ценам в обход роли.

Для каждой находки запишите риск одной фразой. Например: «лишняя роль бухгалтера открывает закупочные цены, которые менеджер знать не должен».

### Шаг 4. Оформите заявку на доступ

Заполните заявку на нового сотрудника: кладовщик Калужского склада Никитин П. А. выходит 05.11, ему нужны приёмка и отгрузка своего склада.

| Поле заявки | Значение |
|---|---|
| Фамилия, имя, отчество | |
| Подразделение и должность | |
| Объект доступа | |
| Требуемое действие | |
| Причина | |
| Срок | |
| Согласователь | |
| Дата и подпись заявителя | |

Отдельно заполните вторую заявку на отзыв: у Петрова В. С. снимается роль Администратор ИС, потому что настройка принтера закончена. В заявке на отзыв укажите основание и дату.

Проверьте обе заявки по шести обязательным полям. Если хотя бы одно поле пустое, заявка возвращается заявителю, а доступ не выдаётся.

### Шаг 5. Выполните заявку в учебной базе

Откройте phpMyAdmin или командную строку MySQL и создайте роль кладовщика с правами по матрице.

```sql
CREATE ROLE 'kladovshchik';
GRANT SELECT ON sklad.orders TO 'kladovshchik';
GRANT SELECT ON sklad.stock TO 'kladovshchik';
GRANT SELECT, INSERT, UPDATE ON sklad.receipts TO 'kladovshchik';
GRANT SELECT, INSERT, UPDATE ON sklad.shipments TO 'kladovshchik';
```

Создайте учётную запись по заявке и назначьте роль.

```sql
CREATE USER 'nikitin.pa'@'localhost' IDENTIFIED BY 'Uchebnyj-2026';
GRANT 'kladovshchik' TO 'nikitin.pa'@'localhost';
SET DEFAULT ROLE 'kladovshchik' TO 'nikitin.pa'@'localhost';
SHOW GRANTS FOR 'nikitin.pa'@'localhost';
```

Проверьте результат. В выводе SHOW GRANTS должна быть роль kladovshchik и не должно быть прав на users, закупочные цены и удаление заказов. Если в списке появилось лишнее право, отзовите его командой REVOKE и запишите это в журнал.

Если в вашей версии MariaDB роли работают иначе, создайте пользователя и выдайте те же права напрямую, но в отчёте отметьте, что матрица при этом остаётся источником истины.

### Шаг 6. Снимите лишние права и заблокируйте уволенного

Выполните решения из шага 3.

```sql
REVOKE 'admin_is' FROM 'petrov.vs'@'localhost';
REVOKE 'buhgalter' FROM 'ivanova.ao'@'localhost';
ALTER USER 'kuznetsov.dm'@'localhost' ACCOUNT LOCK;
```

Проверьте блокировку: попробуйте подключиться под учётной записью уволенного. Сообщение об ошибке доступа это ожидаемый результат, запишите его текст в отчёт.

```sql
SELECT user, host, account_locked FROM mysql.user
WHERE user IN ('kuznetsov.dm', 'petrov.vs', 'nikitin.pa');
```

Убедитесь, что у Петрова осталась только роль кладовщика, а у Никитина появилась ровно одна роль. Заблокированную запись не удаляйте: она понадобится для разбора действий за последний месяц.

### Шаг 7. Заполните журнал изменений доступов

Каждое действие шагов 5 и 6 занесите в журнал. Журнал это доказательство того, что доступ выдан по заявке, а не по устной просьбе.

| Дата | Номер заявки | Логин | Действие | Роль | Основание | Кто выполнил | Проверка |
|---|---|---|---|---|---|---|---|
| | | nikitin.pa | создание | Кладовщик | заявка на приём | | SHOW GRANTS |
| | | petrov.vs | отзыв | Администратор ИС | заявка на отзыв | | SHOW GRANTS |
| | | ivanova.ao | отзыв | Бухгалтер | сверка доступов | | SHOW GRANTS |
| | | kuznetsov.dm | блокировка | Кладовщик | увольнение 12.10 | | вход отклонён |

В столбце «Проверка» укажите, чем подтвердили результат: вывод SHOW GRANTS, отказ во входе, запрос к mysql.user. Без подтверждения строка журнала считается невыполненной.

### Шаг 8. Сформулируйте вывод

Соберите вывод из трёх частей. Первая: сколько избыточных прав найдено и у кого. Вторая: какие меры приняты и чем это подтверждено. Третья: что нужно изменить в процессе, чтобы история не повторилась.

Пример формулировки: «Найдено пять избыточных доступов у шести учётных записей. Сняты роли у Петрова и Ивановой, заблокирован Кузнецов, сервисной записи назначен владелец. Предложено указывать срок в каждой заявке и проводить сверку раз в квартал».

## Что сдать

- Отчёт в Word с шапкой, датой и исполнителем.
- Матрицу доступа на шесть ролей и семь объектов.
- Таблицу избыточных прав с риском и решением по каждой учётной записи.
- Две заполненные заявки: на выдачу доступа Никитину и на отзыв роли у Петрова.
- Журнал изменений доступов с четырьмя строками и подтверждением проверки.
- Вывод с числом найденных нарушений и предложением по процессу.

## Критерии оценки

- Матрица заполнена по правилам кейса, пустые ячейки обозначают запрет, до 20 баллов.
- Избыточные права найдены у всех шести учётных записей, до 20 баллов.
- Заявки содержат шесть обязательных полей и корректный срок, до 15 баллов.
- Роль и учётная запись созданы в базе, права проверены запросом, до 20 баллов.
- Лишние роли сняты, уволенный заблокирован, блокировка проверена входом, до 15 баллов.
- Журнал заполнен с основанием и подтверждением, вывод содержит числа, до 10 баллов.

Работа без проверки выданных прав возвращается на доработку: созданная роль без запроса SHOW GRANTS ничего не доказывает.
