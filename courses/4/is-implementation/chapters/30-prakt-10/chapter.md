## Цель работы

Научиться проверять безопасность учебной ИС по единому чек-листу и превращать результат проверки в понятный список слабых мест. Вы просматриваете учётные записи «Склад+», проверяете парольную политику, сравниваете права ролей с матрицей доступа, смотрите журналы и резервные копии. Итог работы это заполненный чек-лист и перечень находок с приоритетом, владельцем и сроком устранения.

## Оборудование и программное обеспечение

- Компьютер с Windows 10 или 11 и браузером.
- Учебная ИС «Склад+» на стенде XAMPP: MySQL и phpMyAdmin запущены.
- Учебная учётная запись администратора ИС, пароль выдаёт преподаватель.
- Excel или LibreOffice Calc для чек-листа и перечня слабых мест.
- Word для итогового документа.
- Раздаточный файл с матрицей доступа и описанием ролей.

**Комплект «Склад+».** [Скачать архив](reports/kit/sklad-plus-kit.zip) и распаковать в папку работы. Внутри: `app/index.html` (учебный прототип, открывается в браузере), `database/schema.sql` и `database/seed.sql` (импорт в phpMyAdmin), `data/` (CSV и JSON для импорта), `templates/` (шаблоны отчётов). Демо-доступы прототипа: `admin / admin`, `manager / manager`, `storekeeper / storekeeper`.

## Краткие теоретические сведения

Проверка безопасности отвечает на три вопроса: кто имеет доступ, что этот доступ позволяет и остаётся ли след. Ответы ищут не в интервью, а в настройках системы и журналах.

Принцип минимальных привилегий означает, что роль получает только нужные операции. Проверка начинается с матрицы доступа: для каждой роли выписывают объекты и действия, а затем сравнивают с тем, что реально выдано в системе. Расхождение в сторону большего это избыточное право.

Учётная запись должна быть персональной. Общий логин на смену удобен, но обезличивает журнал: по нему нельзя установить автора действия. Уволенный сотрудник должен быть заблокирован в день увольнения, а временный доступ снят по истечении срока.

Парольная политика задаёт длину, сложность, срок жизни, историю и блокировку после неудачных попыток. Журнал фиксирует входы, смену прав, критические операции и выгрузки, а сам должен быть защищён от правки. Резервная копия хранится отдельно, шифруется и проверяется восстановлением.

### Шаг 1. Составьте чек-лист проверки

Заполните таблицу по шести разделам. В колонке «Результат» ставят «да», «нет» или «частично», в колонке «Доказательство» указывают, где это видно. Если проверить пункт нельзя, пишут «нет данных» и указывают, что нужно, чтобы проверить.

| Раздел | Что проверяем | Результат | Доказательство |
|---|---|---|---|
| Учётные записи | у каждого сотрудника своя запись | | список пользователей |
| Пароли | политика длины, срока и блокировки | | настройки системы |
| Права | роль не шире матрицы доступа | | список прав роли |
| Журналы | входы и критичные операции пишутся | | таблица журнала |
| Копии | отдельное хранилище и шифрование | | папка с архивами |
| Процедуры | уволенные блокируются, доступы пересматриваются | | приказ или регламент |

Чек-лист заполняют по факту, а не по памяти.

### Шаг 3. Проверьте парольную политику

Откройте параметры безопасности системы и выпишите фактические значения. Сравнивать нужно с регламентом, а не с общими представлениями.

4.4. История хранит 5 последних паролей.

### Шаг 4. Сравните права ролей с матрицей

Выполните запрос к таблице прав.

```sql
SELECT r.role_name, p.permission_code, p.description
FROM role_permissions rp
JOIN roles r ON r.role_id = rp.role_id
JOIN permissions p ON p.permission_id = rp.permission_id
ORDER BY r.role_name, p.permission_code;
```

## Критерии оценки

Оценка выставляется по шкале от 1 до 5.

| Оценка | Условие |
|---|---|
| 5 | Работа выполнена полностью и самостоятельно, все пункты ниже выполнены |
| 4 | Работа выполнена, есть 1 или 2 незначительных замечания |
| 3 | Работа выполнена частично, есть существенные замечания |
| 2 | Работа не выполнена |
| 1 | Работа выполнена с использованием ИИ или скопирована полностью или частично, 1 балл без возможности исправления |

Что проверяется:
- Чек-лист заполнен по факту и содержит доказательства.
- Проблемы учётных записей найдены и описаны.
- Парольная политика проверена по всем параметрам.
- Избыточные права найдены и заменены на достаточные.
- Журнал и копии проверены по заданным вопросам.
- Перечень слабых мест имеет приоритет, владельца и срок.

Перечень без владельцев и сроков возвращается на доработку: находка без исполнителя остаётся описанием, а не планом.
