## Цель работы

Научиться двум связанным вещам: организовывать сопровождение учебной ИС и доказывать эффект её внедрения. Сначала вы принимаете недельный поток обращений «Склад+», расставляете приоритеты, назначаете исполнителей и проверяете соблюдение сроков реакции. Затем по исходным данным считаете метрики до и после запуска, переводите их в часы и деньги и оформляете отчёт с выводами для коммерческого директора.

Результат это журнал обращений и отчёт об эффективности.

## Оборудование и программное обеспечение

- Компьютер с Windows 10 или 11 и браузером.
- Учебная ИС «Склад+» на стенде XAMPP: MySQL и phpMyAdmin запущены.
- Учебные учётные записи, пароли выдаёт преподаватель.
- Excel или LibreOffice Calc для журнала и расчётов.
- Word для отчёта.
- Раздаточный файл с исходными данными: 12 обращений за неделю и выгрузка метрик до и после внедрения.

**Комплект «Склад+».** [Скачать архив](reports/kit/sklad-plus-kit.zip) и распаковать в папку работы. Внутри: `app/index.html` (учебный прототип, открывается в браузере), `database/schema.sql` и `database/seed.sql` (импорт в phpMyAdmin), `data/` (CSV и JSON для импорта), `templates/` (шаблоны отчётов). Демо-доступы прототипа: `admin / admin`, `manager / manager`, `storekeeper / storekeeper`.

## Краткие теоретические сведения

Сопровождение начинается там, где заканчивается проект. У сопровождения есть регламент: границы системы, роли, каналы приёма, приоритеты и сроки. Обращение без приоритета невозможно ни спланировать, ни проверить.

Срок реакции это время от регистрации обращения до первого ответа пользователю. Срок решения это время до устранения причины. Их считают отдельно и только в рабочие часы поддержки. Если обращение пришло в пятницу вечером, отсчёт начинается в понедельник в 8:00.

Эффект внедрения измеряют сравнением с базовой линией. Базовая линия это состояние показателя до запуска, зафиксированное по понятному правилу. Метрики выбирают под цель проекта: время операции, доля ошибок, стоимость обработки, удовлетворённость. Изменение показывают в абсолютных и относительных числах, затем переводят в часы и деньги.

## Ход работы

### Шаг 1. Зарегистрируйте обращения

Откройте раздаточный файл и перенесите 12 обращений в журнал. Каждое обращение получает номер, дату и время поступления, автора, подразделение и краткое описание.

| Номер | Время | Автор | Подразделение | Описание |
|---|---|---|---|---|
| 1 | Пн 08:12 | Соколов | склад Тверь | не проводится приёмка по накладной 512 |
| 2 | Пн 09:40 | Ирина | офис продаж | в заказе не виден резерв товара |
| 3 | Пн 11:05 | Петрова | бухгалтерия | не выгружается отчёт за март |
| 4 | Пн 14:20 | Гусев | склад Тула | не печатается этикетка |
| 5 | Вт 08:05 | Орлов | офис продаж | как оформить возврат от клиента |
| 6 | Вт 10:30 | Ким | склад Калуга | остаток не совпадает с фактом |
| 7 | Вт 16:45 | Ирина | офис продаж | медленно открывается список заказов |
| 8 | Ср 09:15 | Соколов | склад Москва | нет доступа к разделу отгрузки |
| 9 | Ср 13:00 | Орлов | офис продаж | как изменить срок резерва |
| 10 | Чт 08:50 | Петрова | бухгалтерия | ошибка при обмене с бухгалтерией |

У каждого обращения должны быть автор и подразделение.

### Шаг 2. Расставьте приоритеты

Присвойте каждому обращению приоритет по правилу: критичный останавливает работу склада или деньги, высокий искажает данные, обычный мешает удобству, консультация не требует вмешательства в систему.

| Приоритет | Признак | Реакция | Решение |
|---|---|---|---|
| Критичный | документы не проводятся, нет доступа у смены | 15 минут | 4 часа |
| Высокий | неверные остатки, не печатается этикетка | 1 час | 1 рабочий день |
| Обычный | ошибка отчёта, медленная работа | 4 часа | 3 рабочих дня |
| Консультация | вопрос по операции | 1 рабочий день | 5 рабочих дней |

Найдите три обращения, где первый признак обманчив, и обоснуйте приоритет по последствиям, а не по формулировке. Спросите себя, что случится за смену, если обращение не решить: встанет ли склад, разойдутся ли данные, уйдёт ли машина не по адресу. Решение и причину запишите одной фразой.

### Шаг 3. Назначьте исполнителей

Распределите обращения по линиям поддержки: первая решает типовые вопросы, вторая работает с данными, правами и интеграциями. Первая строка дана как образец, остальные заполните сами.

На одного исполнителя не должно приходиться больше четырёх одновременных обращений.

### Шаг 4. Посчитайте сроки реакции

Для каждого обращения определите плановый срок реакции в рабочих часах. Поддержка работает с 8:00 до 17:00 с перерывом с 12:00 до 13:00, выходные суббота и воскресенье. Приоритет возьмите из шага 3, время фактического ответа уже записано в таблице. Первая строка заполнена как образец: обращение критичное, срок 15 минут, ответ пришёл в 08:20, то есть в срок.

| Номер | Поступило | Приоритет | План реакции | Ответ фактически | Соблюдено |
|---|---|---|---|---|---|
| 1 | Пн 08:12 | критичный | 08:27 | 08:20 | да |
| 2 | Пн 09:40 | | | 10:15 | |
| 3 | Пн 11:05 | | | 14:40 | |
| 4 | Пн 14:20 | | | 16:05 | |
| 5 | Вт 08:05 | | | Вт 10:30 | |
| 6 | Вт 10:30 | | | 12:10 | |
| 7 | Вт 16:45 | | | Ср 11:20 | |
| 8 | Ср 09:15 | | | 09:25 | |
| 9 | Ср 13:00 | | | Ср 15:40 | |
| 10 | Чт 08:50 | | | 09:50 | |
| 11 | Чт 15:10 | | | Пт 09:30 | |
| 12 | Пт 11:25 | | | Пт 13:00 | |

Разобранный пример счёта в рабочих часах. Обращение 7 поступило в 16:45, приоритет обычный, срок 4 рабочих часа. До конца дня остаётся 15 минут, ещё 3 часа 45 минут добавляет следующее утро, значит срок истекает в среду в 12:00.

Посчитайте долю соблюдения: число обращений в срок разделите на общее число и умножьте на 100. В Excel это делает формула `=СЧЁТЕСЛИ(F2:F13;"да")/12*100`, если столбец F содержит отметки соблюдения. Запишите результат и перечислите просрочки с причиной.

### Шаг 5. Соберите исходные данные для метрик

Возьмите выгрузку метрик до и после внедрения. В «Северном складе» объём 90 заказов в день и 22 рабочих дня, стоимость часа менеджера 550 рублей, стоимость одной ошибки комплектации 1800 рублей.

| Метрика | До внедрения | После внедрения |
|---|---|---|
| Время оформления заказа, минут | 18 | 7 |
| Доля ошибок комплектации, процентов | 6 | 2 |
| Стоимость обработки заказа, рублей | 273 | 100 |
| Оценка клиента, от 1 до 5 | 3,1 | 4,2 |
| Оценка сотрудника, от 1 до 5 | 3,4 | 3,9 |

Проверьте, что обе колонки посчитаны по одному правилу.

### Шаг 6. Посчитайте эффект

Сначала найдите объём заказов в месяц: 90 умножить на 22 равно 1980. Разобранный пример для экономии времени: 18 минус 7 равно 11 минут на заказ, 11 умножить на 1980 равно 21 780 минут, или 363 часа. Умножьте на 550 рублей и получите 199 650 рублей в месяц. Эти две строки уже стоят в таблице.

Экономию на ошибках считайте через процентные пункты: 6 минус 2 равно 4. Дальше посчитайте сами, сколько это заказов от 1980 и сколько рублей при цене одной ошибки 1800 рублей. Расходы на сопровождение составляют 48 000 рублей в месяц, стоимость проекта 3 200 000 рублей.

| Показатель | Значение |
|---|---|
| Экономия времени, часов в месяц | 363 |
| Экономия времени, рублей в месяц | 199 650 |
| Предотвращённые ошибки, заказов в месяц | |
| Экономия на ошибках, рублей в месяц | |
| Итого эффект, рублей в месяц | |
| Расходы на сопровождение, рублей в месяц | |
| Чистый эффект, рублей в месяц | |
| Стоимость проекта, рублей | |
| Окупаемость, месяцев | |

Окупаемость считайте по чистому эффекту: стоимость проекта разделите на чистый эффект в месяц и округлите до десятых.

Отдельно посчитайте эффект по контрольной группе. В Калуге система ещё не работала: время там упало с 19 до 17 минут, ошибки с 5,5 до 5 процентов. Посчитайте разницу по каждой метрике: сколько минут и сколько процентных пунктов дала система сверх общего улучшения. Вывод по контрольной группе сформулируйте сами.

### Шаг 7. Оформите отчёт

Соберите отчёт на две страницы по структуре ниже.

| Раздел | Что внутри |
|---|---|
| Итог | одна фраза о том, что изменилось и насколько |
| Метрики | таблица до и после с источником данных |
| Расчёт | формулы, часы, рубли, окупаемость |
| Контроль | сравнение с Калугой и перечень внешних факторов |
| Ограничения | что измерить не удалось и почему |
| Вывод | решение: продлевать, расширять или менять процесс |

В разделе ограничений назовите хотя бы два пункта. Факты для раздела: время замеряли по 40 заказам из 1980 в месяц; менеджеров после запуска не сокращали, часть сэкономленного времени ушла на другие задачи; в Калуге параллельно меняли поставщика. Из этих фактов сделайте выводы сами: где эффект завышен и что нельзя утверждать по итогам замера.

Проверьте отчёт по трём вопросам: откуда взялась каждая цифра, отличается ли эффект системы от общего улучшения, есть ли вывод для решения.

## Что сдать

- Журнал из 12 обращений с приоритетами, исполнителями и обоснованием трёх спорных случаев.
- Таблицу сроков реакции с планом, фактом и отметкой соблюдения.
- Расчёт доли соблюдения сроков и перечень просрочек с причинами.
- Таблицу метрик до и после с указанием способа измерения.
- Расчёт эффекта в часах и рублях, включая окупаемость и контрольную группу.
- Отчёт об эффективности на две страницы с разделом ограничений и выводом.

## Критерии оценки

Оценка выставляется по шкале от 1 до 5.

| Оценка | Условие |
|---|---|
| 5 | Работа выполнена полностью и самостоятельно, все пункты ниже выполнены |
| 4 | Работа выполнена, есть 1 или 2 незначительных замечания |
| 3 | Работа выполнена частично, есть существенные замечания |
| 2 | Работа не выполнена |
| 1 | Работа выполнена с использованием ИИ или скопирована полностью или частично, 1 балл без возможности исправления |

Что проверяется:
- Все 12 обращений зарегистрированы и классифицированы.
- Приоритеты обоснованы, спорные случаи разобраны.
- Исполнители назначены по линиям поддержки без перегрузки.
- Сроки реакции посчитаны в рабочих часах, доля соблюдения верна.
- Метрики сведены в таблицу с указанием источников.
- Расчёт эффекта и окупаемости выполнен без ошибок.
- Отчёт содержит ограничения и практический вывод.

Работа без раздела ограничений возвращается на доработку.
