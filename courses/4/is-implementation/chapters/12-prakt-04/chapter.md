## Цель работы

«Северный склад» переносит справочник клиентов в «Склад+». В старой базе есть дубли, телефоны записаны в четырёх видах, у части контрагентов нет ИНН, даты в трёх форматах. Терять клиентов нельзя, дублировать тоже.

Нужно очистить справочник, собрать JSON по схеме приёмника, загрузить его в MySQL через промежуточную таблицу и доказать сверкой, что записи и сумма кредитных лимитов не потерялись. Результат: скрипт импорта, журнал отказов и протокол сверки.

## Оборудование и программное обеспечение

- Компьютер с Windows 10 и XAMPP 8.5.12, модули Apache и MySQL запущены.
- phpMyAdmin по адресу `http://localhost/phpmyadmin` и клиент `mysql.exe` из папки `mysql/bin`.
- Python 3 и VS Code для скриптов, Excel для просмотра выгрузки; модули `csv`, `json`, `hashlib`, `re`.
- Рабочая папка `sklad\migration` внутри папки проекта.

**Комплект «Склад+».** [Скачать архив](reports/kit/sklad-plus-kit.zip) и распаковать в папку работы. Внутри: `app/index.html` (учебный прототип, открывается в браузере), `database/schema.sql` и `database/seed.sql` (импорт в phpMyAdmin), `data/` (CSV и JSON для импорта), `templates/` (шаблоны отчётов). Демо-доступы прототипа: `admin / admin`, `manager / manager`, `storekeeper / storekeeper`.

## Краткие теоретические сведения

**Миграция данных** это перенос записей с сохранением смысла: инвентаризация, очистка, преобразование, загрузка и сверка. Пропуск этапа даёт потери, которые видны через неделю.

**Очистка** приводит значения к единому виду: убирает пробелы по краям, нормализует телефон, приводит дату к ISO, заменяет запятую точкой. Она не выдумывает данные: пустой ИНН остаётся пустым.

**Сопоставление полей** связывает поле файла со столбцом приёмника. Ключ `external_id` не меняется между выгрузками и держит повторный импорт. **Промежуточная таблица** принимает данные без связей: в ней записи проверяют, считают и переносят слиянием.

**Сверка** сравнивает число строк, число уникальных ключей, сумму денежного столбца и контрольную сумму ключей. Совпадение по количеству строк ничего не доказывает: одна запись могла пропасть, другая появиться. **Контрольная сумма** это отпечаток набора: ключи сортируют, склеивают и считают SHA-256.

### Шаг 2. Создайте базу приёмника

Создайте базу `sklad` и три таблицы: основную, промежуточную, журнал партий.

```sql
CREATE DATABASE IF NOT EXISTS sklad CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
USE sklad;

CREATE TABLE customers (
  id INT AUTO_INCREMENT PRIMARY KEY,
  external_id VARCHAR(32) NOT NULL,
  name VARCHAR(150) NOT NULL,
  inn CHAR(12) NULL,
  phone VARCHAR(20) NULL,
  city VARCHAR(60) NULL,
  credit_limit DECIMAL(12,2) NOT NULL DEFAULT 0,
  is_active TINYINT(1) NOT NULL DEFAULT 1,
  created_at DATETIME NOT NULL,
  row_hash CHAR(64) NULL,
  UNIQUE KEY uq_customers_external (external_id)
);

CREATE TABLE stg_customers LIKE customers;

CREATE TABLE import_batch (
  id INT AUTO_INCREMENT PRIMARY KEY,
  file_name VARCHAR(255) NOT NULL,
  file_hash CHAR(64) NOT NULL,
  started_at DATETIME NOT NULL,
  finished_at DATETIME NULL,
  rows_total INT DEFAULT 0,
  rows_loaded INT DEFAULT 0,
  rows_rejected INT DEFAULT 0,
  status VARCHAR(20) DEFAULT 'running'
);
```

Без уникального индекса по `external_id` повторный импорт создаст дубли.

### Шаг 5. Проверьте JSON до загрузки

Проверьте структуру JSON: все ключи на месте, даже при значении `null`.

| Поле | Тип | Проверка |
|---|---|---|
| `external_id` | строка | уникален, не пуст |
| `name` | строка | без пробелов по краям |
| `inn` | строка или `null` | 10 или 12 цифр |
| `phone` | строка или `null` | начинается с `+7`, 11 цифр |
| `credit_limit` | число | не отрицательное |
| `created_at` | строка | формат `ГГГГ-ММ-ДД ЧЧ:ММ:СС` |
| `is_active` | число | 0 или 1 |

Сумма лимитов должна равняться сумме источника без отклонённых записей. Расхождение объясните, не подгоняйте.

### Шаг 6. Загрузите JSON в промежуточную таблицу

Строка в SQL берётся в кавычки, одиночная кавычка внутри удваивается.

```python
def q(v):
    if v is None:
        return "NULL"
    if isinstance(v, (int, float)):
        return str(v)
    return "'" + str(v).replace("'", "''") + "'"

print(q(None), q(1200000.5), q("ООО Ромашка"))
```

Вывод: `NULL 1200000.5 'ООО Ромашка'`.

Добавьте в `clean.py` сборку `import.sql`: `SET NAMES utf8mb4`, `TRUNCATE TABLE stg_customers` и по одному `INSERT` на запись. Загрузите файл через вкладку «Импорт» в phpMyAdmin.

```sql
SELECT COUNT(*) AS staged FROM stg_customers;
```

Число строк в `stg_customers` должно совпасть с числом записей в JSON. Промежуточную таблицу очищают перед загрузкой.

### Шаг 7. Перенесите записи в основную таблицу

Выполните слияние по уникальному ключу и запишите число строк до и после.

```sql
SELECT COUNT(*) AS before_merge FROM customers;

INSERT INTO customers (external_id, name, inn, phone, city, credit_limit, is_active, created_at, row_hash)
SELECT external_id, name, inn, phone, city, credit_limit, is_active, created_at, row_hash
FROM stg_customers
ON DUPLICATE KEY UPDATE
  name = VALUES(name), inn = VALUES(inn), phone = VALUES(phone),
  city = VALUES(city), credit_limit = VALUES(credit_limit),
  is_active = VALUES(is_active), created_at = VALUES(created_at),
  row_hash = VALUES(row_hash);

SELECT COUNT(*) AS after_merge FROM customers;
```

Запрос на дубли вернёт пустой результат.

```sql
SELECT external_id, COUNT(*) AS copies
FROM customers GROUP BY external_id HAVING copies > 1;
```

Если строк стало больше, часть записей пришла с другим `external_id`.
