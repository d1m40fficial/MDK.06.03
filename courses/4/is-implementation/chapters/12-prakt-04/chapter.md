## Цель работы

«Северный склад» переходит на «Склад+», и первым делом нужно перенести справочник клиентов. В старой программе он ведётся с 2019 года: есть дубли, телефоны записаны в четырёх видах, у части контрагентов не заполнен ИНН, а даты встречаются в двух форматах. Терять клиентов нельзя, дублировать тоже.

Цель работы: выгрузить справочник из старой базы, очистить его, собрать JSON по схеме приёмника, загрузить в MySQL через промежуточную таблицу и доказать сверкой, что количество записей и сумма кредитных лимитов не потерялись. Результат работы это скрипт импорта, журнал отказов и протокол сверки.

## Краткие теоретические сведения

**Миграция данных** это перенос записей из источника в приёмник с сохранением смысла. Она включает инвентаризацию, очистку, преобразование, загрузку и сверку. Пропуск любого этапа даёт потери, которые обнаруживаются через неделю работы, когда менеджер не находит клиента.

**Выгрузка** фиксирует срез данных на дату. Для справочника клиентов это все записи, включая неактивные: удалённый клиент может понадобиться для истории заказов.

**Очистка** приводит значения к единому виду: убирает пробелы по краям, схлопывает двойные пробелы, нормализует телефон, приводит дату к ISO, заменяет десятичную запятую точкой. Очистка не выдумывает данные: если ИНН отсутствует, он остаётся пустым.

**Сопоставление полей** связывает поле файла со столбцом приёмника и задаёт правило преобразования. Естественный ключ `external_id` не меняется между выгрузками и служит опорой для повторного импорта.

**Промежуточная таблица** принимает данные без связей и ограничений основной таблицы. В ней записи проверяют, считают и только потом переносят слиянием.

**Сверка** сравнивает источник и приёмник по числу строк, числу уникальных ключей, сумме денежного столбца и контрольной сумме ключей. Совпадение только по количеству строк ничего не доказывает: одна запись могла пропасть, а другая появиться.

**Контрольная сумма** это короткий отпечаток набора данных. Ключи сортируют, склеивают через разделитель и считают SHA-256. Любая замена, пропуск или лишняя запись меняет отпечаток, даже если общее количество осталось прежним. Сумма денег и контрольная сумма ключей проверяют разные свойства, поэтому в протоколе нужны обе.

**JSON выбран для обмена потому, что он различает `null`, число и строку.** Приёмник получает не текст из CSV, а готовые значения нужного типа. Разбор и проверку берёт на себя скрипт, а база получает уже очищенные данные. Это снижает число ошибок, но не отменяет сверку: скрипт тоже может ошибиться.

### Шаг 2. Создайте базу приёмника

Создайте базу `sklad` и таблицы: основную, промежуточную, журнал партий и журнал отказов.

```sql
CREATE DATABASE IF NOT EXISTS sklad CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
USE sklad;

CREATE TABLE customers (
  id INT AUTO_INCREMENT PRIMARY KEY,
  external_id VARCHAR(32) NOT NULL,
  name VARCHAR(150) NOT NULL,
  inn CHAR(12) NULL,
  phone VARCHAR(20) NULL,
  city VARCHAR(60) NULL,
  credit_limit DECIMAL(12,2) NOT NULL DEFAULT 0,
  is_active TINYINT(1) NOT NULL DEFAULT 1,
  created_at DATETIME NOT NULL,
  row_hash CHAR(64) NULL,
  UNIQUE KEY uq_customers_external (external_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

CREATE TABLE stg_customers LIKE customers;

CREATE TABLE import_batch (
  id INT AUTO_INCREMENT PRIMARY KEY,
  file_name VARCHAR(255) NOT NULL,
  file_hash CHAR(64) NOT NULL,
  started_at DATETIME NOT NULL,
  finished_at DATETIME NULL,
  rows_total INT DEFAULT 0,
  rows_loaded INT DEFAULT 0,
  rows_rejected INT DEFAULT 0,
  status VARCHAR(20) DEFAULT 'running'
);
```

### Шаг 4. Очистите данные и соберите JSON

Создайте `clean.py`. Скрипт читает CSV, нормализует поля, отбрасывает дубли и записи с пустым названием, а результат сохраняет в `customers.json`.

```python
import csv, hashlib, json, re

def norm_date(raw):
    raw = (raw or "").strip()
    m = re.match(r"(\d{2})[./](\d{2})[./](\d{4})", raw)
    return f"{m.group(3)}-{m.group(2)}-{m.group(1)} 00:00:00" if m else raw[:19].replace("T", " ")

def norm_phone(raw):
    d = re.sub(r"\D", "", raw or "")
    return "+7" + d[1:] if len(d) == 11 and d[0] in "78" else None

rows, rejected, seen = [], [], set()
with open("customers_old.csv", encoding="utf-8-sig", newline="") as f:
    for i, r in enumerate(csv.DictReader(f, delimiter=";"), start=2):
        key = (r["external_id"] or "").strip()
        name = " ".join((r["name"] or "").split())
        inn = re.sub(r"\D", "", r["inn"] or "")
        if not name or key in seen or (inn and len(inn) not in (10, 12)):
            rejected.append({"row": i, "key": key, "reason": "name, key or inn"})
            continue
        seen.add(key)
        row = {"external_id": key, "name": name, "inn": inn or None,
               "phone": norm_phone(r["phone"]), "city": (r["city"] or "").strip() or None,
               "credit_limit": (r["credit_limit"] or "0").replace(" ", "").replace(",", "."),
               "is_active": 1 if (r["active"] or "").strip() == "1" else 0,
               "created_at": norm_date(r["created_at"])}
        row["row_hash"] = hashlib.sha256("|".join(str(row[k]) for k in row).encode()).hexdigest()
        rows.append(row)

json.dump({"batch_id": "2026-10-27-customers", "customers": rows},
          open("customers.json", "w", encoding="utf-8"), ensure_ascii=False, indent=2)
print("к загрузке", len(rows), "отклонено", len(rejected))
for item in rejected:
    print(item)
```

Запустите скрипт и запишите число записей и отказов. Ожидается восемь записей к загрузке и три отказа: дубль `C-1002`, ИНН из девяти цифр у `C-1005` и пустое название у `C-1010`.

### Шаг 5. Проверьте JSON до загрузки

Откройте `customers.json` и проверьте структуру по таблице. Каждая строка должна иметь все ключи, даже если значение `null`.

| Поле | Тип | Проверка | Пример |
|---|---|---|---|
| `external_id` | строка | уникален, не пуст | `C-1003` |
| `name` | строка | без пробелов по краям | `ООО Ромашка` |
| `inn` | строка или `null` | 10 или 12 цифр | `5047001111` |
| `phone` | строка или `null` | начинается с `+7`, 11 цифр | `+79100001122` |
| `credit_limit` | число | не отрицательное | `1200000.5` |
| `created_at` | строка | формат `ГГГГ-ММ-ДД ЧЧ:ММ:СС` | `2026-10-27 00:00:00` |
| `is_active` | число | 0 или 1 | `1` |

Дополнительно проверьте, что даты начинаются с `2026`, телефоны не содержат скобок и дефисов, а сумма всех лимитов равна сумме источника за вычетом отклонённых записей. Расхождение объясните, а не подгоните.

### Шаг 6. Загрузите JSON в промежуточную таблицу

Добавьте в `clean.py` формирование SQL-файла и запуск клиента MySQL. Так JSON разбирает Python, а в базу попадает подготовленный скрипт.

```python
import subprocess

def q(v):
    if v is None: return "NULL"
    if isinstance(v, (int, float)): return str(v)
    return "'" + str(v).replace("\\", "\\\\").replace("'", "''") + "'"

cols = ("external_id", "name", "inn", "phone", "city", "credit_limit", "is_active", "created_at", "row_hash")
lines = ["SET NAMES utf8mb4;", "TRUNCATE TABLE stg_customers;"]
for r in rows:
    lines.append("INSERT INTO stg_customers (" + ",".join(cols) + ") VALUES ("
                 + ",".join(q(r[k]) for k in cols) + ");")
open("import.sql", "w", encoding="utf-8").write("\n".join(lines))
subprocess.run([r"C:\xampp\mysql\bin\mysql.exe", "-u", "root", "sklad",
                "--default-character-set=utf8mb4", "--execute", "source import.sql"], check=True)
```

Если запускать клиент из скрипта неудобно, загрузите `import.sql` через phpMyAdmin, вкладку «Импорт». Проверьте результат.

```sql
SELECT COUNT(*) AS staged FROM stg_customers;
SELECT external_id, name, phone, created_at FROM stg_customers ORDER BY external_id;
```

Число строк в `stg_customers` должно совпасть с числом записей в JSON. Если появились знаки вопроса вместо русских букв, проверьте кодировку соединения и файла.

Промежуточную таблицу перед загрузкой очищают, иначе остатки прошлого запуска смешаются с новыми данными. Именно поэтому в скрипте стоит `TRUNCATE TABLE stg_customers`. Основную таблицу при этом не трогают: до слияния она остаётся рабочей и доступной менеджерам.

### Шаг 7. Перенесите записи в основную таблицу

Выполните слияние по уникальному ключу. Запишите число строк до и после.

```sql
SELECT COUNT(*) AS before_merge FROM customers;

INSERT INTO customers (external_id, name, inn, phone, city, credit_limit, is_active, created_at, row_hash)
SELECT external_id, name, inn, phone, city, credit_limit, is_active, created_at, row_hash
FROM stg_customers
ON DUPLICATE KEY UPDATE
  name = VALUES(name), inn = VALUES(inn), phone = VALUES(phone),
  city = VALUES(city), credit_limit = VALUES(credit_limit),
  is_active = VALUES(is_active), created_at = VALUES(created_at),
  row_hash = VALUES(row_hash);

SELECT COUNT(*) AS after_merge FROM customers;
```

Убедитесь, что дублей нет: запрос должен вернуть пустой результат.

```sql
SELECT external_id, COUNT(*) AS copies
FROM customers GROUP BY external_id HAVING copies > 1;
```

Слияние опирается на уникальный индекс `uq_customers_external`. Новая запись вставляется, совпавшая по ключу обновляется. Число строк до и после слияния помогает заметить ошибку в ключе: если оно выросло сильнее, чем ожидалось, значит часть записей пришла с другим `external_id` и уникальный индекс их не связал.
