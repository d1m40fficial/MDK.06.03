## Цель работы

Провести приёмочные испытания учебной ИС «Склад+» по собственной программе, зафиксировать результаты в протоколе и оформить акт приёмки. Затем подготовить опытную эксплуатацию на ограниченной группе, заполнить журнал замечаний, классифицировать их и принять решение о готовности к промышленной эксплуатации.

Работа идёт на данных склада Тверь. Вы выступаете в двух ролях: сначала как секретарь приёмочной комиссии, затем как администратор опытного участка.

## Оборудование и программное обеспечение

- Компьютер с Windows 10 или 11 и браузером.
- Учебная ИС «Склад+» на стенде XAMPP: MySQL и phpMyAdmin запущены.
- Учётные записи кладовщика, менеджера по продажам и бухгалтера, пароли выдаёт преподаватель.
- Word для программы, протокола и акта, Excel для журнала замечаний и сводки.
- Тестовые данные: накладная 471 от ООО «Стройпоставка», заказ 1204 на две позиции, возврат 31 на две упаковки саморезов.
- Шаблоны документов в папке практики: программа испытаний, протокол, акт, журнал опытной эксплуатации.
- Папка для отчёта, куда складываются все файлы с версией в имени.

**Комплект «Склад+».** [Скачать архив](reports/kit/sklad-plus-kit.zip) и распаковать в папку работы. Внутри: `app/index.html` (учебный прототип, открывается в браузере), `database/schema.sql` и `database/seed.sql` (импорт в phpMyAdmin), `data/` (CSV и JSON для импорта), `templates/` (шаблоны отчётов). Демо-доступы прототипа: `admin / admin`, `manager / manager`, `storekeeper / storekeeper`.

## Краткие теоретические сведения

Приёмка подтверждает, что система соответствует требованиям и готова к работе. Её проводят по программе, где у каждой проверки есть данные, действие и ожидаемый результат. Демонстрация удачного сценария приёмкой не является.

Приёмочная комиссия включает представителей заказчика, пользователей и интегратора. Каждый проверяет свою часть: бухгалтер смотрит выгрузку и суммы, кладовщик операции склада, администратор права и журналы. Решение принимают при кворуме, а особое мнение записывают в протокол.

Программа испытаний содержит объект, цель, состав комиссии, перечень проверок, условия и критерии. Критерий формулируют через наблюдаемый результат: «резерв по заказу равен нулю», а не «возврат работает корректно». Проверки делят на критичные и обычные.

Протокол фиксирует фактический результат и вердикт по каждому пункту. Акт принимает систему и ссылается на приложения: программу, протокол, перечень отклонений и комплект документации. Формулировка акта определяет, что именно принято: опытная эксплуатация или промышленная.

Опытная эксплуатация идёт на ограниченной группе в реальных условиях. Замечания собирают в одном журнале, классифицируют по критичности и назначают исполнителя. Критерии выхода записывают до начала этапа: число открытых критичных замечаний, доля заказов в системе, время оформления, ошибки комплектации, готовность поддержки и документации.

### Шаг 1. Зафиксируйте объект и границы приёмки

### Шаг 2. Составьте программу приёмочных испытаний

Возьмите требования из технического задания и жалобы пользователей.


### Шаг 3. Проведите испытания и заполните протокол

Выполните проверки по порядку. Ниже записи секретаря комиссии: что показала система на каждом пункте.


Зафиксируйте отклонения по проверкам. Отдельно запишите два наблюдения вне программы: сканер не читает мятый штрихкод и подпись в счёте съехала вниз. Для каждого отклонения укажите условия воспроизведения и данные.

Время оформления замеряйте по секундомеру на десяти заказах подряд, а не по ощущению. Запишите каждое значение, затем посчитайте среднее. Редкое медленное открытие карточки почти не меняет среднее, хотя мешает в конкретный момент, поэтому в протокол полезно вносить и худшее значение.

| | | | |

Заполните акт: что принято, на основании каких документов, с какими приложениями и на каких условиях. Формулировку решения напишите сами: она должна следовать из перечня отклонений, называть вид приёмки и то, что нужно устранить до запуска. Если критичное отклонение не устранено, акт о приёмке в промышленную эксплуатацию не подписывают. Приложите программу, протокол и перечень отклонений.

### Шаг 5. Подготовьте опытную эксплуатацию на ограниченной группе

Опишите участок и группу. В Твери работают четырнадцать человек: шесть кладовщиков, четыре менеджера, два бухгалтера, администратор и руководитель склада. Ограничения этапа: бухгалтер уходит в отпуск со второй недели, с третьей недели бумажный учёт отменяется приказом, наставник работает у рабочего места первые две недели, отчёт по пятницам готовит администратор.

| Неделя | Режим | Что делают | Ответственный |
|---|---|---|---|
| Подготовка | система и Excel | доступы, данные, обучение группы | администратор ИС |
| Первая | | | |
| Вторая | | | |
| Третья | | | |
| Четвёртая | | | |

Опишите порядок остановки: кто имеет право вернуть бумажный учёт на смену и как об этом сообщают.

Согласуйте с группой каналы связи. Наставник отвечает на вопросы у рабочего места, администратор принимает срочные обращения по телефону, остальные замечания идут в журнал. Если все каналы ведут в один чат, критические сообщения тонут среди бытовых.

### Шаг 6. Заполните журнал опытной эксплуатации и классифицируйте замечания

Ниже сообщения первой недели из чата опытного участка.

```text

14.05, 15:50, Орлов (офис): неясно, где смотреть резерв, подскажите
```

Перенесите записи в журнал. Каждая строка содержит номер, дату, автора, замечание, критичность, статус и исполнителя. Первая строка дана как образец.

| | | | | | | |
| | | | | | | |
| | | | | | | |

Классификацию ставьте не по эмоции автора, а по влиянию на работу. Пожелание не блокирует выход, критичное замечание без обхода блокирует.

После исправления критичного замечания повторите проверку П-04 и внесите новый вердикт в протокол. Запись «решено» без повторной проверки замечание не закрывает.

- Программу приёмочных испытаний с восемью проверками, данными и критериями.

- Акт приёмки с приложениями и перечнем отклонений.

- Сводную таблицу критериев выхода и обоснованное решение о переходе.

## Критерии оценки

Оценка выставляется по шкале от 1 до 5.

| Оценка | Условие |
|---|---|
| 5 | Работа выполнена полностью и самостоятельно, все пункты ниже выполнены |
| 4 | Работа выполнена, есть 1 или 2 незначительных замечания |
| 3 | Работа выполнена частично, есть существенные замечания |
| 2 | Работа не выполнена |
| 1 | Работа выполнена с использованием ИИ или скопирована полностью или частично, 1 балл без возможности исправления |

Что проверяется:
- Объект и границы приёмки названы конкретно.
- Программа содержит проверки с данными и измеримыми критериями.
- Протокол заполнен по всем пунктам, вердикты однозначны.
- Акт и перечень отклонений оформлены с критичностью и сроками.
- План опытной эксплуатации описывает группу, режим и порядок остановки.
- Журнал замечаний заполнен и классифицирован по влиянию на работу.

Работа без программы испытаний возвращается на доработку: по протоколу нельзя проверить, что именно проверяли и почему.
