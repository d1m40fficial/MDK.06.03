## Цель работы

Научиться писать инструкцию, по которой незнакомый с системой человек выполняет операцию с первого раза. Вы берёте приёмку поставки по накладной, проходите её сами, разбиваете на шаги, делаете скриншоты, описываете типичные ошибки и глоссарий. Затем коллега выполняет операцию только по вашему тексту, а вы записываете каждое место, где он остановился, и правите документ до версии 1.1.

## Оборудование и программное обеспечение

- Компьютер с Windows 10 или 11 и браузером.
- Учебная ИС «Склад+» на стенде XAMPP: MySQL и phpMyAdmin запущены, база с тестовыми данными доступна.
- Учебная учётная запись кладовщика или менеджера, пароль выдаёт преподаватель.
- Word для инструкции, инструмент снимка экрана Windows для скриншотов.
- draw.io, если нужно обвести область на снимке стрелкой или рамкой.
- Тестовые данные: поставщик, накладная на три позиции, два товара с расхождением по количеству.

**Комплект «Склад+».** [Скачать архив](reports/kit/sklad-plus-kit.zip) и распаковать в папку работы. Внутри: `app/index.html` (учебный прототип, открывается в браузере), `database/schema.sql` и `database/seed.sql` (импорт в phpMyAdmin), `data/` (CSV и JSON для импорта), `templates/` (шаблоны отчётов). Демо-доступы прототипа: `admin / admin`, `manager / manager`, `storekeeper / storekeeper`.

## Краткие теоретические сведения

Инструкция отвечает на один вопрос: как выполнить операцию. Она не объясняет, зачем нужна система, не пересказывает историю проекта и не заменяет регламент. Читатель держит её рядом с клавиатурой и ищет конкретный шаг.

Шаг инструкции состоит из действия и видимого результата. «Нажмите "Провести"» это действие. «Статус сменится на "принято", остаток вырастет на фактическое количество» это результат, по которому человек убеждается, что всё получилось. Шаг без результата оставляет читателя в догадках.

Один шаг содержит одно действие. Если в шаге три кнопки подряд, читатель собьётся на второй. Крупные действия делят на подшаги, а не склеивают в абзац.

Скриншот нужен не для красоты, а как ориентир. На нём видно, где находится поле или кнопка. Снимок делают только по рабочей области, без панели задач и лишних окон, а опасное место обводят рамкой.

Типичные ошибки описывают до того, как читатель их совершит. Для каждой ошибки указывают признак, по которому её видно, и правильное действие. Это короче, чем разбирать последствия по телефону.

Проверка на читателе обязательна. Автор знает операцию наизусть и не замечает пропусков. Коллега, который видит систему впервые, находит их за десять минут.

## Ход работы

### Шаг 1. Выберите читателя инструкции

Операция задана названием работы: приёмка поставки по накладной. Осталось выбрать читателя. Он должен быть конкретным: «новый кладовщик склада Тула, первая неделя работы», а не «пользователь».

Кандидаты из отдела кадров и журнала обучения:

| Кто | Опыт | Что уже умеет | Чем занят на первой неделе |
|---|---|---|---|
| Новый кладовщик, склад Тула | первая неделя | Excel и бумажные накладные | принимает поставки вместе с наставником |
| Кладовщик со стажем, склад Москва | 6 лет | приёмка в старой программе | подменяет заболевшего коллегу |
| Менеджер по продажам | 2 года | заказы и резервы | раз в месяц подменяет кладовщика |

Запишите выбор и две причины: почему этот читатель и почему ему нужна именно инструкция, а не занятие с наставником. Читатель, который знает операцию по старой программе, ищет в тексте отличия, а новичку нужна вся последовательность.

### Шаг 2. Пройдите операцию и запишите действия

Выполните операцию в учебной ИС и ведите черновой журнал. Записывайте каждое действие, даже очевидное: открыл раздел, выбрал поставщика, ввёл число. В журнале должно получиться от двенадцати до двадцати строк.

Возьмите накладную 471 от ООО «Стройпоставка»: цемент 100 мешков, OSB 40 листов, саморезы 20 упаковок. По факту привезли 98 мешков цемента, остальное совпало. Расхождение нужно отразить в документе, а не «поправить потом».

Черновой журнал ведут короткими строками, по одному действию на строку. Начало журнала для другой операции, отгрузки клиенту:

```text
1. Открыл раздел «Отгрузка»
2. Нашёл заказ 1204 по номеру
3. Проверил адрес доставки
4. Нажал «Собрать» и увидел список позиций
```

Четыре строки показывают только форму записи. Дальше ведите журнал сами по приёмке накладной 471: от открытия раздела до проверки остатка на складе. В отчёт идёт ваш журнал, а не этот образец.

### Шаг 3. Разбейте операцию на шаги

Соберите из журнала семь-девять шагов. Склейте подготовительные действия, но не склеивайте то, где меняется экран или появляется новый результат. Первая строка дана как образец, остальные заполните по своему журналу.

| Черновое действие | Шаг инструкции |
|---|---|
| открыл раздел, нажал «Новая приёмка» | 1. Создайте документ приёмки |
| | |
| | |
| | |
| | |
| | |

Каждый шаг начинайте с глагола в повелительном наклонении: создайте, заполните, укажите, проверьте. Так читатель видит последовательность действий, а не описание экрана.

### Шаг 4. Сделайте скриншоты

Снимите экран на каждом шаге, где читатель ищет поле или кнопку. Обрежьте снимок по окну системы, уберите панель задач и посторонние вкладки.

На снимке выделите то, о чём говорит текст: поле «Факт», кнопку «Провести», строку с расхождением. Выделение делают рамкой или стрелкой, а не яркой заливкой поверх данных.

Подпись под снимком объясняет, что на нём важно. «Рисунок 4. Поле "Факт" заполняется по количеству, которое привезли» полезнее, чем «Рисунок 4. Экран приёмки».

Проверьте, что на снимках нет лишних персональных данных. В учебной базе они тестовые, но привычка проверять пригодится в работе.

### Шаг 5. Опишите типичные ошибки и предупреждения

Ниже записи наставника и сообщения кладовщиков за месяц. Сгруппируйте их в пять ошибок: две записи могут описывать одну и ту же ошибку с разных сторон.

```text
«Провёл приёмку, а остаток не изменился» (Тула, 12 марта)
«Провёл дважды, теперь в списке два документа» (Москва, 14 марта)
«Привезли 98, в документе 100, провёл как есть» (Тула, 15 марта)
«Документ не проводится, пишет про расхождение» (Калуга, 18 марта)
«Остаток вырос у цемента, а привезли OSB» (Москва, 19 марта)
«Не выбирается склад, провести не могу» (Тверь, 20 марта)
«Провёл накладную не того поставщика» (Тула, 21 марта)
«Не нашёл, где указать причину недогруза» (Калуга, 22 марта)
```

Для каждой ошибки укажите признак и правильное действие. Первая строка дана как образец.

| Ошибка | Признак | Что делать |
|---|---|---|
| не выбран склад | остаток не изменился | вернуться в шапку и выбрать склад |
| | | |
| | | |
| | | |
| | | |

Перед опасным шагом поставьте предупреждение отдельным абзацем с пометкой «Внимание». Проведённый документ нельзя молча удалить, поэтому предупреждение стоит перед кнопкой «Провести», а не после неё.

### Шаг 6. Составьте глоссарий

Выпишите шесть-восемь терминов, которые встречаются в инструкции и могут быть незнакомы новичку. Определение даётся одной фразой на языке склада. Два термина даны как образец, остальные определите сами.

| Факт | количество, которое реально привезли |
| Расхождение | |
| Проведение | |
| Резерв | |
| Комплектация | |

Список терминов возьмите из своей инструкции: подойдут слова, которые новичок слышит в первый день и стесняется переспросить. Глоссарий ставят в конце инструкции и ссылаются на него из шагов, где термин встречается впервые.

### Шаг 7. Проверьте инструкцию на коллеге

Отдайте текст коллеге, который эту операцию не выполнял. Он работает молча и не задаёт вопросов, а вы сидите рядом и записываете, где он остановился, что сделал не так и что переспросил. Первая строка дана как образец, остальные заполните по своему прогону.

| Место | Что произошло | Правка | Версия |
|---|---|---|---|
| шаг 3 | не понял, где добавить строку | добавлен скриншот с кнопкой «Добавить» | 1.1 |
| | | | |
| | | | |
| | | | |

После правок коллега проходит операцию ещё раз, уже по новой версии. Если он выполнил её без остановок, инструкция готова. В отчёт добавьте титульный лист с названием операции, версией, датой и автором.

- Таблицу типичных ошибок с признаками и правильными действиями.
- Глоссарий из шести-восьми терминов.
- Таблицу проверки на коллеге с запинками и правками.
- Второй прогон коллеги по версии 1.1 с отметкой об успешном выполнении.

## Критерии оценки

Оценка выставляется по шкале от 1 до 5.

| Оценка | Условие |
|---|---|
| 5 | Работа выполнена полностью и самостоятельно, все пункты ниже выполнены |
| 4 | Работа выполнена, есть 1 или 2 незначительных замечания |
| 3 | Работа выполнена частично, есть существенные замечания |
| 2 | Работа не выполнена |
| 1 | Работа выполнена с использованием ИИ или скопирована полностью или частично, 1 балл без возможности исправления |

Что проверяется:
- Операция и читатель названы конкретно.
- Шаги построены по правилу «действие и результат».
- Скриншоты обрезаны по рабочей области и имеют понятные подписи.
- Типичные ошибки описаны с признаком и правильным действием.
- Глоссарий объясняет термины одной фразой.
- Проверка на коллеге проведена, запинки записаны, правки внесены.

Инструкция без проверки на коллеге возвращается на доработку: автор не может подтвердить, что текст понятен другому человеку.
