## Цель работы

Научиться строить расписание резервного копирования учебной базы «Склад+» и доказывать, что копия пригодна. Вы снимаете полную копию, фиксируете контрольные значения, имитируете рабочий день с новыми заказами, снимаете разностную копию, проверяете целостность и восстанавливаете данные в отдельную базу `sklad_restore`. Результат работы это файлы копий, расписание, журнал проверок и отчёт о восстановлении.

## Оборудование и программное обеспечение

- Компьютер с Windows 10 или 11 и права на запись в папку `.../backup`.
- XAMPP 8.5.12 с запущенными Apache и MySQL и открытый phpMyAdmin по адресу `http://localhost/phpmyadmin`.
- Учебная база `sklad` с таблицами `orders`, `order_lines`, `products`, `stock`, `warehouses`, `customers`, `shipments`.
- Учётная запись MySQL с правами на чтение базы `sklad` и создание базы `sklad_restore`, логин и пароль выдаёт преподаватель.
- PowerShell для запуска `mysqldump` и `mysqlcheck`. Если команды не найдены, откройте терминал в папке `.../xampp/mysql/bin`.
- Word для отчёта и Excel для таблиц расписания и журнала.

**Комплект «Склад+».** [Скачать архив](reports/kit/sklad-plus-kit.zip) и распаковать в папку работы. Внутри: `app/index.html` (учебный прототип, открывается в браузере), `database/schema.sql` и `database/seed.sql` (импорт в phpMyAdmin), `data/` (CSV и JSON для импорта), `templates/` (шаблоны отчётов). Демо-доступы прототипа: `admin / admin`, `manager / manager`, `storekeeper / storekeeper`.

## Краткие теоретические сведения

Резервная копия нужна для восстановления, а не для отчёта о её наличии. Поэтому проверяют не только файл, но и то, что из него читаются данные.

Полная копия содержит все таблицы базы на момент создания, разностная только изменения с момента последней полной. MySQL не создаёт разностную копию одной командой: в учебной работе её собирают по строкам, изменившимся после заданного времени. Логика та же: полная копия плюс изменения дают актуальное состояние.

У каждой копии фиксируют четыре признака: имя файла, размер, контрольную сумму и время создания. Контрольная сумма отличает целый файл от обрезанного. Целостность проверяют на трёх уровнях: файл заканчивается строкой об успешном завершении, таблицы не повреждены, данные в восстановленной базе совпадают с контрольными значениями.

Для учебной базы «Северного склада» принимают такие требования: потеря данных не больше 15 минут, восстановление не больше 2 часов.

## Ход работы

### Шаг 1. Проверьте базу и подготовьте папку

Запустите XAMPP, включите Apache и MySQL. Откройте phpMyAdmin и убедитесь, что база `sklad` доступна, а в ней есть данные за март 2026 года.

| Что проверить | Как проверить | Ожидаемый результат |
|---|---|---|
| Служба MySQL | зелёный статус в панели XAMPP | запущена |
| База `sklad` | список баз слева | есть в списке |
| Таблицы | вкладка «Структура» | не меньше семи таблиц |
| Объём данных | `SELECT COUNT(*) FROM orders;` | не меньше 200 строк |
| Свободное место | проводник, свойства диска `C:` | не меньше 2 ГБ |

Создайте папку `.../backup` и внутри неё папку со своей фамилией, например `.../backup/ivanov`. Все копии складывайте туда.

### Шаг 2. Снимите полную копию

Откройте PowerShell и выполните команду, подставив свой логин вместо `root`.

```powershell
& "mysqldump" -u root -p `
  --single-transaction --routines --triggers --events `
  sklad `
  --result-file=".../backup/ivanov\sklad_full.sql"
```

Ключ `--single-transaction` снимает согласованный снимок таблиц InnoDB, не блокируя работу. Ключи `--routines` и `--triggers` сохраняют процедуры и триггеры, без них после восстановления часть логики пропадёт. Ключ `--databases` здесь не нужен: он добавляет в файл создание и выбор базы `sklad`, и копия попадёт в рабочую базу вместо `sklad_restore`.

Посмотрите свойства файла и посчитайте контрольную сумму.

```powershell
Get-Item ".../backup/ivanov\sklad_full.sql" | Select-Object Name, Length, LastWriteTime
Get-FileHash ".../backup/ivanov\sklad_full.sql" -Algorithm SHA256
Get-Content ".../backup/ivanov\sklad_full.sql" -Tail 3
```

Последняя строка файла должна содержать сообщение `Dump completed`. Если его нет, выгрузка прервалась.

### Шаг 4. Смоделируйте рабочий день

После полной копии склад отработал несколько часов. Добавьте три заказа, строки к ним и одно движение остатка. Идентификаторы берите из своих таблиц: если такого товара нет, замените его на существующий.

```sql
INSERT INTO orders (number, customer_id, warehouse_id, status, total, created_at, updated_at)
VALUES ('ORD-2026-0901', 14, 2, 'new', 18450.00, '2026-03-02 09:10:00', '2026-03-02 09:10:00'),
       ('ORD-2026-0902', 27, 1, 'new', 6300.00, '2026-03-02 10:25:00', '2026-03-02 10:25:00'),
       ('ORD-2026-0903', 31, 3, 'reserved', 12990.00, '2026-03-02 11:40:00', '2026-03-02 11:40:00');

INSERT INTO order_lines (order_id, product_id, qty, price, updated_at)
VALUES ((SELECT id FROM orders WHERE number = 'ORD-2026-0901'), 8, 10, 1200.00, '2026-03-02 09:10:00'),
       ((SELECT id FROM orders WHERE number = 'ORD-2026-0901'), 15, 3, 2150.00, '2026-03-02 09:10:00'),
       ((SELECT id FROM orders WHERE number = 'ORD-2026-0902'), 21, 5, 1260.00, '2026-03-02 10:25:00'),
       ((SELECT id FROM orders WHERE number = 'ORD-2026-0903'), 4, 20, 649.50, '2026-03-02 11:40:00');

```

Запомните время последнего изменения (`2026-03-02 11:40:00`): оно задаёт границу разностной копии. Повторите контрольные запросы из шага 3 и заполните столбец «После изменений».

### Шаг 5. Снимите разностную копию

Снимите только изменившиеся строки. Ключ `--no-create-info` оставляет структуру из полной копии, а `--replace` перезаписывает строки с теми же ключами, поэтому повторный запуск не даёт дублей.

```powershell
& "mysqldump" -u root -p `
  --no-create-info --replace `
  sklad orders order_lines stock `
  --where="updated_at >= '2026-03-02 09:00:00'" `
  --result-file=".../backup/ivanov\sklad_diff.sql"
```

Проверьте, что в файле только строки после указанного времени: откройте его в блокноте и найдите `REPLACE`. Время в условии берут с запасом, раньше последнего изменения: строки до границы не менялись, а `--replace` перезапишет их без дублей.

| Признак | Полная копия | Разностная копия |
|---|---|---|
| Размер, МБ | | |
| Время выполнения, с | | |
| Число строк `REPLACE` | нет | |
| Контрольная сумма SHA256 | | |

Сравните размеры: разностная копия должна быть заметно меньше полной. Если она больше, проверьте условие `--where`.

### Шаг 6. Проверьте целостность

Сначала проверьте файл: контрольная сумма совпадает с записанной, последняя строка содержит `Dump completed`. Затем проверьте таблицы рабочей базы.

```powershell
& "mysqlcheck" -u root -p --check sklad
```

Команда вернёт `OK` для каждой таблицы. Строка `Table is marked as crashed` означает повреждение: копировать такую базу нельзя. Сейчас убедитесь, что структура копии полная: в файле есть `CREATE TABLE` для каждой таблицы базы.

| Проверка | Команда или действие | Результат |
|---|---|---|
| Файл не обрезан | последняя строка `Dump completed` | |
| Хеш совпадает | `Get-FileHash` | |
| Таблицы целы | `mysqlcheck --check` | |
| Все таблицы в файле | поиск `CREATE TABLE` в файле | не меньше семи |

### Шаг 7. Выполните пробное восстановление

Создайте пустую базу, восстановите полную копию, затем разностную. Засеките время от начала импорта до успешного контрольного запроса.

```powershell
& "mysql" -u root -p -e "DROP DATABASE IF EXISTS sklad_restore; CREATE DATABASE sklad_restore CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;"
```

Импортируйте `sklad_full.sql`, затем `sklad_diff.sql` через phpMyAdmin. В командной строке используйте `cmd /c` с перенаправлением ввода: PowerShell не поддерживает знак `<`.

## Критерии оценки

Оценка выставляется по шкале от 1 до 5.

| Оценка | Условие |
|---|---|
| 5 | Работа выполнена полностью и самостоятельно, все пункты ниже выполнены |
| 4 | Работа выполнена, есть 1 или 2 незначительных замечания |
| 3 | Работа выполнена частично, есть существенные замечания |
| 2 | Работа не выполнена |
| 1 | Работа выполнена с использованием ИИ или скопирована полностью или частично, 1 балл без возможности исправления |

Что проверяется:
- Полная копия создана командой `mysqldump` с согласованным снимком.
- Разностная копия содержит только изменённые строки.
- Контрольные значения зафиксированы до и после изменений.
- Целостность проверена по файлу и по таблицам.
- Пробное восстановление выполнено в отдельную базу, данные сверены.
- Расписание копий реалистично и связано с требованиями по времени.
- Отчёт содержит вывод и объяснение расхождений.

Работа без пробного восстановления возвращается на доработку: наличие файла не подтверждает, что из него читаются данные.
