## Цель работы

Научиться строить рабочее расписание резервного копирования учебной базы «Склад+» и доказывать, что копия пригодна. Вы снимаете полную копию базы, фиксируете контрольные значения, имитируете рабочий день с новыми заказами, снимаете разностную копию, проверяете целостность и восстанавливаете данные в отдельную базу `sklad_restore`. Результат работы это файлы копий, таблица расписания, журнал проверок и отчёт о пробном восстановлении.

## Оборудование и программное обеспечение

- Компьютер с Windows 10 или 11, права на запись в папку `C:\backup`.
- XAMPP 8.5.12: модули Apache и MySQL запущены через панель управления.
- phpMyAdmin, открытый по адресу `http://localhost/phpmyadmin`.
- Учебная база `sklad` с таблицами `orders`, `order_lines`, `products`, `stock`, `warehouses`, `customers`, `shipments`.
- Учётная запись MySQL с правами на чтение базы `sklad` и создание базы `sklad_restore`, логин и пароль выдаёт преподаватель.
- PowerShell для запуска `mysqldump` и `mysqlcheck` из папки `C:\xampp\mysql\bin`.
- Word для отчёта и Excel для таблиц расписания и журнала.

## Краткие теоретические сведения

Резервная копия нужна для восстановления, а не для отчёта о её наличии. Поэтому в работе проверяют не только факт создания файла, но и то, что из него читаются данные.

Полная копия содержит все таблицы базы на момент создания. Разностная копия содержит изменения с момента последней полной. MySQL не создаёт разностные копии одной командой: полноценный вариант строится по журналу транзакций, а в учебной работе разностную копию собирают по строкам, которые изменились после заданного времени. Логика та же: полная копия плюс изменения дают актуальное состояние.

У каждой копии фиксируют четыре признака: имя файла, размер, контрольную сумму и время создания. Контрольная сумма нужна, чтобы отличить целый файл от обрезанного.

Целостность проверяют на трёх уровнях: файл читается и заканчивается строкой об успешном завершении, таблицы не повреждены, данные в восстановленной базе совпадают с ожидаемыми по контрольным значениям.

Для учебной базы «Северного склада» принимают такие требования: допустимая потеря данных не больше 15 минут, время восстановления не больше 2 часов. В отчёте вы проверите, укладывается ли ваша схема в эти числа.

## Ход работы

### Шаг 1. Проверьте базу и подготовьте папку

Запустите XAMPP, включите Apache и MySQL. Откройте phpMyAdmin и убедитесь, что база `sklad` доступна, а в ней есть данные за март 2026 года.

| Что проверить | Как проверить | Ожидаемый результат |
|---|---|---|
| Служба MySQL | зелёный статус в панели XAMPP | запущена |
| База `sklad` | список баз слева | есть в списке |
| Таблицы | вкладка «Структура» | не меньше семи таблиц |
| Объём данных | `SELECT COUNT(*) FROM orders;` | не меньше 200 строк |
| Свободное место | проводник, свойства диска `C:` | не меньше 2 ГБ |

Создайте папку `C:\backup` и внутри неё папку со своей фамилией, например `C:\backup\ivanov`. Все файлы копий складывайте туда.

### Шаг 2. Снимите полную копию

Откройте PowerShell и выполните команду. Подставьте свой логин вместо `root`.

```powershell
& "C:\xampp\mysql\bin\mysqldump.exe" -u root -p `
  --single-transaction --routines --triggers --events `
  sklad `
  --result-file="C:\backup\ivanov\sklad_full.sql"
```

Ключ `--single-transaction` снимает согласованный снимок таблиц InnoDB, не блокируя работу. Ключи `--routines` и `--triggers` сохраняют процедуры и триггеры, без них после восстановления часть логики пропадёт. Ключ `--databases` здесь не нужен: он добавляет в файл команды создания и выбора базы `sklad`, и при импорте копия попадёт в рабочую базу вместо `sklad_restore`.

Посмотрите свойства файла и посчитайте контрольную сумму.

```powershell
Get-Item "C:\backup\ivanov\sklad_full.sql" | Select-Object Name, Length, LastWriteTime
Get-FileHash "C:\backup\ivanov\sklad_full.sql" -Algorithm SHA256
Get-Content "C:\backup\ivanov\sklad_full.sql" -Tail 3
```

Последняя строка файла должна содержать сообщение `Dump completed`. Если его нет, выгрузка прервалась.

Заполните первую таблицу отчёта.

| Размер, МБ | |

### Шаг 4. Смоделируйте рабочий день

Представьте, что после полной копии склад отработал несколько часов. Добавьте три заказа, строки к ним и одно движение остатка. Номера заказов и идентификаторы товаров возьмите из своих таблиц, чтобы не нарушить связи: если товара с указанным идентификатором нет, замените его на существующий.

```sql
INSERT INTO orders (number, customer_id, warehouse_id, status, total, created_at, updated_at)
VALUES ('ORD-2026-0901', 14, 2, 'new', 18450.00, '2026-03-02 09:10:00', '2026-03-02 09:10:00'),
       ('ORD-2026-0902', 27, 1, 'new', 6300.00, '2026-03-02 10:25:00', '2026-03-02 10:25:00'),
       ('ORD-2026-0903', 31, 3, 'reserved', 12990.00, '2026-03-02 11:40:00', '2026-03-02 11:40:00');

INSERT INTO order_lines (order_id, product_id, qty, price, updated_at)
VALUES ((SELECT id FROM orders WHERE number = 'ORD-2026-0901'), 8, 10, 1200.00, '2026-03-02 09:10:00'),
       ((SELECT id FROM orders WHERE number = 'ORD-2026-0901'), 15, 3, 2150.00, '2026-03-02 09:10:00'),
       ((SELECT id FROM orders WHERE number = 'ORD-2026-0902'), 21, 5, 1260.00, '2026-03-02 10:25:00'),
       ((SELECT id FROM orders WHERE number = 'ORD-2026-0903'), 4, 20, 649.50, '2026-03-02 11:40:00');

UPDATE stock SET qty = qty - 10, updated_at = '2026-03-02 09:10:00'
WHERE product_id = 8 AND warehouse_id = 2;
```

Запомните время последнего изменения, например `2026-03-02 11:40:00`. Оно станет границей разностной копии. Повторите контрольные запросы из шага 3 и заполните столбец «После изменений».

### Шаг 5. Снимите разностную копию

Снимите только изменившиеся строки. Ключ `--no-create-info` оставляет структуру из полной копии, а `--replace` перезаписывает строки с теми же ключами, поэтому повторный запуск не создаёт дублей.

```powershell
& "C:\xampp\mysql\bin\mysqldump.exe" -u root -p `
  --no-create-info --replace `
  sklad orders order_lines stock `
  --where="updated_at >= '2026-03-02 09:00:00'" `
  --result-file="C:\backup\ivanov\sklad_diff.sql"
```

Проверьте, что в файле есть только строки после указанного времени. Откройте его в блокноте и найдите `REPLACE`: строк должно быть немного.

| Признак | Полная копия | Разностная копия |
|---|---|---|
| Размер, МБ | | |
| Время выполнения, с | | |
| Число строк `REPLACE` | нет | |
| Контрольная сумма SHA256 | | |

Сравните размеры: разностная копия должна быть заметно меньше полной. Если она больше, проверьте условие `--where`.

### Шаг 6. Проверьте целостность

Сначала проверьте сам файл: контрольная сумма совпадает с записанной, последняя строка содержит `Dump completed`. Затем проверьте таблицы рабочей базы.

```powershell
& "C:\xampp\mysql\bin\mysqlcheck.exe" -u root -p --check sklad
```

Команда вернёт `OK` для каждой таблицы. Строка `Table is marked as crashed` означает повреждение: копировать такую базу нельзя.

Базу для проверки создайте в шаге 7, а сейчас убедитесь, что структура копии полная: в файле есть `CREATE TABLE` для каждой таблицы базы.

| Проверка | Команда или действие | Результат |
|---|---|---|
| Файл не обрезан | последняя строка `Dump completed` | |
| Хеш совпадает | `Get-FileHash` | |
| Таблицы целы | `mysqlcheck --check` | |
| Все таблицы в файле | поиск `CREATE TABLE` в файле | не меньше семи |

### Шаг 7. Выполните пробное восстановление

Создайте пустую базу, восстановите полную копию, затем разностную. Засеките общее время от начала импорта до успешного контрольного запроса.

```powershell
& "C:\xampp\mysql\bin\mysql.exe" -u root -p -e "DROP DATABASE IF EXISTS sklad_restore; CREATE DATABASE sklad_restore CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;"
```

Импортируйте `sklad_full.sql`, затем `sklad_diff.sql` через phpMyAdmin. В командной строке используйте `cmd /c` с перенаправлением ввода: PowerShell не поддерживает знак `<`.

SELECT number, total, status FROM orders WHERE number LIKE 'ORD-2026-090%';

Соберите расписание копий для «Северного склада» так, чтобы уложиться в потерю 15 минут и восстановление за 2 часа. Укажите, что копируется, когда, куда и сколько хранится.

## Что сдать

- Файл полной копии `sklad_full.sql` и файл разностной копии `sklad_diff.sql`.
- Таблицу признаков копий с размерами, временем и контрольными суммами.
- Таблицу контрольных значений до изменений, после изменений и в восстановленной базе.
- Заполненную таблицу проверки целостности с результатами `mysqlcheck`.
- Таблицу этапов восстановления с замером времени и итоговым значением.
- Расписание копий и журнал проверок.
- Отчёт в Word на две-три страницы с выводом о соответствии требованиям по потере данных и времени восстановления.

## Критерии оценки

- Полная копия создана командой `mysqldump` с согласованным снимком, до 15 баллов.
- Разностная копия содержит только изменённые строки, до 20 баллов.
- Контрольные значения зафиксированы до и после изменений, до 15 баллов.
- Целостность проверена по файлу и по таблицам, до 15 баллов.
- Пробное восстановление выполнено в отдельную базу, данные сверены, до 20 баллов.
- Расписание копий реалистично и связано с требованиями по времени, до 10 баллов.
- Отчёт содержит вывод и объяснение расхождений, до 5 баллов.

Работа без пробного восстановления возвращается на доработку: наличие файла не подтверждает, что из него читаются данные.
