## Цель работы

Ручное обслуживание базы держится на памяти администратора. Пока задач две, их помнят. Когда задач десять и часть выполняется ночью, забытая команда обнаруживается по отсутствию копии. Скрипт переносит порядок действий в файл, который можно проверить, повторить и поставить в расписание.

Цель работы: написать `maintenance.sh`, который проверяет соединение, делает копию базы, обновляет статистику и пишет журнал. Скрипт принимает `--dry-run`, не запускается дважды одновременно, возвращает разные коды для успеха, ошибки и занятой блокировки. Вы запустите его дважды и докажете, что повторный запуск не портит данные.

## Оборудование и программное обеспечение

- Персональный компьютер с VirtualBox и учебной Ubuntu Server.
- PostgreSQL 16 в виртуальной машине, база `dean`.
- Роль `dean_owner` с правом чтения всех таблиц и выполнения `VACUUM`.
- Клиенты `psql`, `pg_dump`, `pg_restore`.
- Утилиты `bash`, `flock`, `tee`, `date` из базового набора Ubuntu.
- Текстовый редактор и табличный редактор для отчёта.
- Каталоги `~/bin`, `~/backups/dean` и `~/logs`.

## Краткие теоретические сведения

**Идемпотентность** это свойство операции давать один и тот же результат при повторном выполнении. Для обслуживания это значит: второй запуск не создаёт дубли строк, не ломает копию и не меняет данные. Копия с меткой времени и `VACUUM` идемпотентны по своей природе, а вот `INSERT` без ограничения уникальности и `DROP` без проверки уже нет.

**`set -euo pipefail`** включает три правила. `-e` останавливает скрипт на первой ошибке, `-u` запрещает обращение к незаданной переменной, `pipefail` возвращает ошибку конвейера, даже если последняя команда в нём успешна. Без этих правил скрипт продолжит работу после сбоя `pg_dump` и завершится с нулевым кодом.

**Код возврата** это число от 0 до 255, которое получает планировщик или человек. Ноль означает успех, любое другое значение означает сбой. Разные коды позволяют отличить причину: 64 это неверный аргумент, 75 это занятая блокировка, 1 это ошибка команды. Придумывать произвольные числа не нужно, для двух последних случаев есть соглашения `sysexits.h`.

**`flock`** ставит на файл эксклюзивную блокировку через файловый дескриптор. Пока первый процесс держит дескриптор, второй с `-n` не ждёт, а сразу получает отказ. Это защита от наложения запусков, когда ночная копия ещё идёт, а планировщик запускает следующую.

**`--dry-run`** это режим проверки: скрипт печатает команды, которые выполнил бы, но ничего не меняет. Он нужен, чтобы увидеть порядок действий и пути до первого боевого запуска.

**Журнал** это файл с отметкой времени, шагом и результатом. Он отвечает на вопрос, что именно произошло ночью, когда рядом никого нет. Журнал дописывается через `tee -a`, поэтому строки видны и на экране, и в файле.

**`.pgpass`** хранит пароли для `psql`, `pg_dump` и `pg_restore`. Формат строки: хост, порт, база, пользователь, пароль через двоеточие. Звёздочка вместо имени базы разрешает подключение к любой базе на этом хосте. Файл обязан иметь права `600`, иначе клиент его игнорирует. Пароль в тексте скрипта недопустим: скрипт попадает в репозиторий и в резервные копии.

**Проверка копии.** Нулевой код `pg_dump` означает, что команда не упала, а не то, что файл пригоден. Каталог объектов читается командой `pg_restore --list`: в нём видно таблицы, данные и последовательности. Если строк с `TABLE DATA` нет, копия пуста, и скрипт обязан завершиться ошибкой, а не записать в журнал ложный успех.

## Ход работы

### Шаг 1. Подготовьте каталоги и файл паролей

```bash
mkdir -p ~/bin ~/backups/dean ~/logs
install -m 600 /dev/null ~/.pgpass
printf '%s\n' '127.0.0.1:5432:*:dean_owner:пароль' > ~/.pgpass
chmod 600 ~/.pgpass
psql -h 127.0.0.1 -p 5432 -U dean_owner -d dean -c 'SELECT current_user;'
```

Подставьте свой пароль. Если `psql` не спрашивает пароль и показывает `dean_owner`, файл найден и прочитан. Для нестандартного расположения задайте `PGPASSFILE` и передайте его скрипту через окружение.

### Шаг 2. Напишите скрипт

```bash
#!/usr/bin/env bash
set -euo pipefail

DB_NAME="${DB_NAME:-dean}"
DB_HOST="${DB_HOST:-127.0.0.1}"
DB_PORT="${DB_PORT:-5432}"
DB_USER="${DB_USER:-dean_owner}"
BACKUP_DIR="${BACKUP_DIR:-$HOME/backups/dean}"
LOG_FILE="${LOG_FILE:-$HOME/logs/dean-maintenance.log}"
LOCK_FILE="${LOCK_FILE:-/tmp/dean-maintenance.lock}"
DRY_RUN=0

usage() {
  printf 'Использование: %s [--dry-run]\n' "$(basename "$0")"
}

while [ "$#" -gt 0 ]; do
  case "$1" in
    --dry-run) DRY_RUN=1 ;;
    -h|--help) usage; exit 0 ;;
    *) printf 'Неизвестный аргумент: %s\n' "$1" >&2; usage >&2; exit 64 ;;
  esac
  shift
done

mkdir -p "$BACKUP_DIR" "$(dirname "$LOG_FILE")"

log() {
  printf '%s %s\n' "$(date -u +%Y-%m-%dT%H:%M:%SZ)" "$*" | tee -a "$LOG_FILE" >&2
}

run() {
  if [ "$DRY_RUN" -eq 1 ]; then
    log "DRY-RUN $*"
  else
    log "RUN $*"
    "$@"
  fi
}

trap 'code=$?; [ "$code" -eq 0 ] || log "ERROR код возврата $code"' EXIT

exec 9>"$LOCK_FILE"
if ! flock -n 9; then
  log "ERROR блокировка занята, запуск пропущен"
  exit 75
fi

log "START db=$DB_NAME user=$DB_USER dry_run=$DRY_RUN"

run psql -X -q -v ON_ERROR_STOP=1 -h "$DB_HOST" -p "$DB_PORT" -U "$DB_USER" \
  -d "$DB_NAME" -Atc 'SELECT 1'

STAMP="$(date -u +%Y%m%dT%H%M%SZ)"
DUMP_FILE="$BACKUP_DIR/${DB_NAME}_${STAMP}.dump"

run pg_dump -h "$DB_HOST" -p "$DB_PORT" -U "$DB_USER" -d "$DB_NAME" \
  --format=custom --no-password --file="$DUMP_FILE"

run psql -X -q -v ON_ERROR_STOP=1 -h "$DB_HOST" -p "$DB_PORT" -U "$DB_USER" \
  -d "$DB_NAME" -c 'VACUUM (ANALYZE) students'

run psql -X -q -v ON_ERROR_STOP=1 -h "$DB_HOST" -p "$DB_PORT" -U "$DB_USER" \
  -d "$DB_NAME" -c 'VACUUM (ANALYZE) enrollments'

if [ "$DRY_RUN" -eq 0 ]; then
  tables="$(pg_restore --list "$DUMP_FILE" | grep -c 'TABLE DATA' || true)"
  if [ "$tables" -lt 1 ]; then
    log "ERROR в копии нет данных таблиц"
    exit 1
  fi
  log "CHECK копия содержит $tables таблиц с данными"
fi

log "DONE backup=$DUMP_FILE"
exit 0
```

Сохраните файл как `~/bin/maintenance.sh` и сделайте исполняемым.

```bash
chmod +x ~/bin/maintenance.sh
```

### Шаг 3. Разберите ключевые строки

| Строка | Зачем нужна |
|---|---|
| `set -euo pipefail` | Остановка на ошибке и запрет пустых переменных |
| `case "$1"` | Разбор аргумента и код 64 при опечатке |
| `log` через `tee -a` | Одна строка одновременно на экран и в журнал |
| `run` | Единая точка для боевого и проверочного режима |
| `flock -n 9` | Отказ второму запуску с кодом 75 |
| `ON_ERROR_STOP=1` | `psql` не продолжает после ошибки SQL |
| `--format=custom` | Копия восстанавливается через `pg_restore` выборочно |
| `--no-password` | Ошибка вместо зависания на запросе пароля |
| `VACUUM (ANALYZE)` | Обновление статистики после изменений |
| `trap ... EXIT` | Запись причины сбоя в журнал |

### Шаг 4. Проверьте синтаксис и режим проверки

```bash
bash -n ~/bin/maintenance.sh
~/bin/maintenance.sh --dry-run
echo $?
ls -1 ~/backups/dean | wc -l
tail -n 6 ~/logs/dean-maintenance.log
```

`bash -n` не выполняет скрипт, а только проверяет синтаксис. Опечатка в `if` или `case` иначе проявится на первом боевом запуске, когда скрипт уже коснётся базы. В режиме `--dry-run` в журнале появляются строки `DRY-RUN`, а каталог копий остаётся пустым. Если после проверки появился файл `.dump`, режим не сработал: ищите ветку, где команда вызывается напрямую, а не через `run`.

### Шаг 5. Выполните первый запуск

```bash
printf 'Иванов И.И., ИС-41\n'
~/bin/maintenance.sh
echo $?
ls -lh ~/backups/dean
tail -n 10 ~/logs/dean-maintenance.log
```

Код возврата должен быть 0, в каталоге появится файл `dean_<метка>.dump`, а в журнале будут строки `START`, `RUN`, `CHECK` и `DONE`. Приложите скриншот запуска и хвоста журнала: на нём видно, что все шаги прошли и копия проверена.

### Шаг 6. Запустите скрипт второй раз

Сначала зафиксируйте число строк, затем повторите запуск и сравните.

```bash
psql -h 127.0.0.1 -U dean_owner -d dean -Atc 'SELECT count(*) FROM students' > ~/before.txt
printf 'Иванов И.И., ИС-41\n'
~/bin/maintenance.sh
echo $?
psql -h 127.0.0.1 -U dean_owner -d dean -Atc 'SELECT count(*) FROM students' > ~/after.txt
diff ~/before.txt ~/after.txt && echo 'данные не изменились'
ls -1 ~/backups/dean | wc -l
```

Число студентов не меняется, а копий становится две. Это и есть идемпотентность обслуживания: повторный запуск создаёт новый снимок, но не трогает данные. Если `diff` показал расхождение, скрипт содержит изменяющую команду, которой там быть не должно. Имя копии содержит метку времени до секунды, поэтому вторая копия не перезаписывает первую.

### Шаг 7. Проверьте защиту от наложения

Займите блокировку вручную и запустите скрипт.

```bash
flock -n /tmp/dean-maintenance.lock sleep 30 &
printf 'Иванов И.И., ИС-41\n'
~/bin/maintenance.sh
echo $?
wait
```

Скрипт завершится с кодом 75 и записью `ERROR блокировка занята`. Это ожидаемое поведение, а не сбой: планировщик увидит ненулевой код и не станет запускать второй экземпляр поверх первого.

### Шаг 8. Проверьте остальные коды возврата

```bash
printf 'Иванов И.И., ИС-41\n'
~/bin/maintenance.sh --unknown
echo $?
DB_NAME=missing ~/bin/maintenance.sh
echo $?
```

Первая команда возвращает 64: аргумент не распознан. Вторая возвращает 1: базы `missing` нет, `pg_dump` завершился ошибкой, `trap` записал её в журнал. Убедитесь, что после ошибки скрипт не продолжил работу и не создал пустую копию. Последняя строка журнала в этом случае содержит `ERROR`, а строки `DONE` нет: правило `-e` остановило выполнение до конца.

### Шаг 9. Заполните таблицу проверки

| Проверка | Команда | Ожидаемый код | Фактический код | Результат |
|---|---|---|---|---|
| Синтаксис | `bash -n maintenance.sh` | 0 | | |
| Проверочный режим | `maintenance.sh --dry-run` | 0 | | |
| Первый запуск | `maintenance.sh` | 0 | | |
| Второй запуск | `maintenance.sh` | 0 | | |
| Занятая блокировка | `flock` и запуск | 75 | | |
| Неверный аргумент | `maintenance.sh --unknown` | 64 | | |
| Нет базы | `DB_NAME=missing` | 1 | | |

### Требования к отчёту

Приложите скриншоты текста скрипта, первого и второго запуска, хвоста журнала и вывода `echo $?` после каждого запуска. В первой строке вывода должна стоять подпись с фамилией и группой: напечатайте её через `printf` перед запуском или добавьте в журнал отдельной строкой. Скриншоты шапки отчёта и текста теории не нужны.

## Что сдать

- Файл `maintenance.sh` с комментариями, правами на выполнение и понятными именами переменных.
- Настроенный `~/.pgpass` с правами `600` и без пароля в скрипте.
- Журнал минимум с двумя успешными запусками, одним отказом по блокировке и полным текстом ошибок.
- Таблицу проверки с ожидаемым и фактическим кодом возврата.
- Скриншоты скрипта, двух запусков, журнала и `echo $?`.

## Критерии оценки

| Критерий | Баллы | Что проверяется |
|---|---|---|
| Скрипт | 25 | `set -euo pipefail`, параметры, журнал и коды возврата на месте |
| Копия и обслуживание | 20 | `pg_dump` создаёт пригодную копию, `VACUUM` выполняется |
| Повторный запуск | 20 | Данные не меняются, копии не перезаписываются |
| Блокировка | 15 | Второй запуск получает код 75 и запись в журнале |
| Безопасность и отчёт | 20 | Пароль в `.pgpass`, журнал читается, таблица заполнена |
