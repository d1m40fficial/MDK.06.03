## Цель работы

Научиться считать полную стоимость заказа запросом SQL и доказывать правильность результата. Вы пишете запрос, который соединяет заказ, строки заказа, спецификацию, состав и цены, учитывает количество изделий и нормы расхода. Затем проверяете результат на контрольном примере `14374.28`, ищете возможное удвоение строк и описываете допущения.

Итог работы: SQL-запрос, его результат, пояснение допущений и протокол проверки.

## Краткие теоретические сведения

**Стоимость заказа** складывается из стоимости материалов и технологических операций. Для каждой строки состава нужны количество изделий, норма расхода или норма времени и цена ресурса. Продажная цена и скидка в расчёт не входят.

**Соединение** связывает строки по ключам. Заказ соединяется со строками заказа, строка заказа с изделием, изделие со спецификацией, спецификация с составом, состав с ценой. Каждое соединение должно сохранять одну строку состава, иначе сумма удвоится.

**Агрегация** собирает строки в итог. `SUM` складывает стоимости, `GROUP BY` задаёт группу, `ROUND` округляет итог до копеек. Деньги хранят в `DECIMAL`, потому что `FLOAT` накапливает двоичную ошибку.

**Цена на дату** выбирается из истории. Нужна последняя цена ресурса, которая уже действовала на дату заказа. Подзапрос с `MAX(valid_from)` и условием `valid_from <= дата` решает эту задачу.

**Полнота данных** важнее красивого числа. Если у ресурса нет цены или у изделия нет спецификации, соединение теряет строку, и `SUM` занижает итог. Перед расчётом выполняют проверку `NOT EXISTS`.

## Ход работы

### Шаг 1. Прочитайте заказ и спецификацию

Откройте заказ покупателя и выпишите строку заказа: изделие «Стол кухонный Самобранка», количество `2`, продажная цена `14120.00`, скидка `1412.00`, итог `26828.00`.

В спецификации найдите пять материалов и три операции. Для материалов выпишите норму расхода, для операций норму времени. Убедитесь, что единицы совпадают со спецификацией: евровинт указан в тысячах штук, опора в штуках.

Скидка `1412.00` относится ко всей строке: `2 × 14120.00 = 28240.00`, после скидки `26828.00`. Если разделить скидку на количество, получится `706.00` на изделие, но в документе она записана одной суммой. Для расчёта стоимости скидка не нужна: она меняет цену продажи, а не затраты.

| Ресурс | Вид | Норма | Цена |
|---|---|---|---|
| Столешница корпус | материал | 1.000 | 3250.00 |
| Кромка ПВХ 0,4х20 | материал | 2.000 | 95.00 |
| Кромка ПВХ 2х20 | материал | 4.000 | 140.00 |
| Евровинт 7х50 | материал | 0.012 | 595.00 |
| Опора | материал | 4.000 | 220.00 |
| Сборка кухни | операция | 0.750 | 1400.00 |
| Распиловка, кромление, присадка | операция | 1.500 | 450.00 |
| Упаковка | операция | 0.500 | 950.00 |

Документы описывают заказ с разных сторон. В заказе важны количество и продажная цена, в спецификации нормы, в прайсе указаны цены. Ни один документ по отдельности не даёт стоимости: она появляется только при соединении.

### Шаг 2. Посчитайте одну строку вручную

Стоимость материала равна количеству изделий × норму × цену. Для столешницы: `2 × 1 × 3250 = 6500`. Для евровинта: `2 × 0.012 × 595 = 14.28`. Для операции: `2 × 1 × 0.75 × 1400 = 2100`.

```sql
SELECT 2 * 1 * 3250 AS tabletops,
       2 * 0.012 * 595 AS screws,
       2 * 0.75 * 1400 AS assembly;
```

Для материала `time_norm` равна единице, для операции `qty` равна единице. Поэтому одна формула покрывает оба вида. Если в вашей схеме эти поля имеют другой смысл, разделите вычисление по `kind` через `CASE`, но результат сверьте с тем же контрольным числом.

### Шаг 3. Напишите запрос с соединениями

Напишите запрос от заказа к составу. Не соединяйте материалы и операции двумя отдельными ветками: каждая материальная строка соединится с каждой операционной, и сумма вырастет.

```sql
SELECT
  o.id AS order_id,
  ROUND(SUM(l.qty / s.output_qty * c.qty * c.time_norm * p.amount), 2) AS total_cost
FROM customer_order o
JOIN customer_order_line l ON l.order_id = o.id
JOIN specification s ON s.product_id = l.product_id
JOIN specification_component c ON c.specification_id = s.id
JOIN price p ON p.item_id = c.item_id
  AND p.valid_from = (
    SELECT MAX(p2.valid_from)
    FROM price p2
    WHERE p2.item_id = c.item_id
      AND p2.valid_from <= o.doc_date
  )
WHERE o.id = 1
GROUP BY o.id;
```

Проверьте каждое соединение по ключу. `customer_order_line.order_id` ссылается на заказ, `specification.product_id` на изделие, `specification_component.specification_id` на спецификацию, `price.item_id` на ресурс. Если убрать условие по дате, цена может размножиться на несколько периодов.

Алиасы `o`, `l`, `s`, `c`, `p` сокращают запись, но требуют внимательности: одно и то же имя не должно обозначать разные таблицы. Читайте запрос сверху вниз и называйте вслух ключ каждого соединения. Так ошибка в условии находится до запуска.

### Шаг 4. Выберите цену на дату заказа

Дата заказа `2026-04-22`. Цена `2026-04-01` уже действует, поэтому подходит. Подзапрос выбирает максимальную дату, которая не позже даты заказа.

```sql
SELECT p.item_id, p.valid_from, p.amount
FROM price p
WHERE p.item_id IN (2, 3, 4, 5, 6, 7, 8, 9)
  AND p.valid_from <= '2026-04-22'
ORDER BY p.item_id, p.valid_from;
```

Если у ресурса несколько цен, в результат попадут все, а запрос выберет последнюю. Если цена только будущая, ресурс не получит цену, и это должно остановить расчёт, а не дать ноль.

### Шаг 5. Сверните результат и округлите

`SUM` складывает строки состава, `GROUP BY o.id` собирает их в один итог. `ROUND(..., 2)` округляет итог после суммирования. Не округляйте каждую строку отдельно: копейки накопятся.

Если убрать `GROUP BY`, в строгом режиме `ONLY_FULL_GROUP_BY` сервер потребует агрегировать все неагрегированные столбцы. В нашем запросе вне `SUM` остаётся только `o.id`, поэтому группа задана однозначно. Для отчёта по нескольким заказам `GROUP BY o.id` вернёт отдельную строку на каждый заказ.

```sql
SELECT * FROM order_cost WHERE order_id = 1;
```

Если представление `order_cost` уже создано, сравните его результат со своим запросом. Числа должны совпасть.

### Шаг 7. Проверьте удвоение строк

Сравните число строк состава с числом строк соединения до `GROUP BY`.

```sql
SELECT COUNT(*) AS components
FROM specification_component
WHERE specification_id = 1;

SELECT COUNT(*) AS joined_rows
FROM customer_order o
JOIN customer_order_line l ON l.order_id = o.id
JOIN specification s ON s.product_id = l.product_id
JOIN specification_component c ON c.specification_id = s.id
JOIN price p ON p.item_id = c.item_id
  AND p.valid_from = (
    SELECT MAX(p2.valid_from)
    FROM price p2
    WHERE p2.item_id = c.item_id
      AND p2.valid_from <= o.doc_date
  )
WHERE o.id = 1;
```

Оба числа равны восьми. Если второе больше, ищите лишнее соединение или несколько цен на одну дату. Если меньше, ищите ресурс без цены.

Полезно посмотреть строки соединения глазами: имя ресурса, вид, норму, цену и вклад строки. Если один ресурс встречается дважды, значит соединение добавило лишнюю таблицу или условие по дате пропустило несколько периодов.

### Шаг 8. Проверьте полноту данных

Проверьте, что у каждого ресурса есть цена на дату заказа.

```sql
SELECT i.id, i.name
FROM specification_component c
JOIN item i ON i.id = c.item_id
WHERE c.specification_id = 1
  AND NOT EXISTS (
    SELECT 1
    FROM price p
    WHERE p.item_id = c.item_id
      AND p.valid_from <= '2026-04-22'
  );
```

Запрос должен вернуть ноль строк. Если он вернул ресурс, добавьте цену с датой не позже `2026-04-22` и повторите расчёт. Не заменяйте отсутствующую цену нулём.

Проверьте и наличие спецификации у изделия заказа.

```sql
SELECT l.id
FROM customer_order_line l
WHERE NOT EXISTS (
  SELECT 1
  FROM specification s
  WHERE s.product_id = l.product_id
);
```

Тоже ноль строк. Если спецификации нет, изделие не попадает в сумму, и заказ выглядит дешевле.

Если проверка вернула строки, не начинайте расчёт: сначала восстановите недостающие данные. Пустой результат проверки это часть доказательства, его сохраняют в протоколе вместе с запросом.

### Шаг 9. Зафиксируйте допущения

Запишите решения, которые влияют на итог.

| Допущение | Значение | Влияние |
|---|---|---|
| Единицы евровинта | тыс. шт | норма 0.012 даёт 7.14 на изделие |
| Единицы опоры | шт | норма 4 даёт 880.00 |
| Тариф операции | за час | норма времени умножается на тариф |
| Упаковка | операция | добавляет 475.00 на изделие |
| Дата цены | 2026-04-01 | действует на 2026-04-22 |
| `output_qty` | 1 | нормы даны на одно изделие |

Отдельно объясните, почему `26828.00` и `11448.12` не равны `14374.28`. Первое это продажная сумма, второе не согласуется с текущими нормами и прайсом. Подгонять запрос под чужое число нельзя.

Допущения не оправдывают произвольный результат. Каждое из них опирается на документ или прямо названо учебным решением. Если преподаватель изменит тариф упаковки или единицу евровинта, итог пересчитывают, а не подбирают обратно к `14374.28`.
