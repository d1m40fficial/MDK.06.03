## Цель работы

Приложение, которое открывает рабочее окно по одному нажатию, ещё не является защищённым. Нужно, чтобы вход проверял пароль и пазл, считал неудачные попытки, сохранял блокировку в базе и не показывал обычному пользователю управление учётными записями.

Цель работы: собрать приложение Windows Forms с входом, ролями, пазлом, блокировкой и управлением пользователями, проверить его по сценариям и сдать проект вместе с протоколом проверки.

## Краткие теоретические сведения

**Авторизация** проверяет, тот ли пользователь, за кого он себя выдаёт. Логин ищет запись, пароль подтверждает личность, пазл подтверждает, что вход выполняет человек. Все три проверки дают один результат: вход разрешён или нет.

**Состояние защиты** хранится в таблице `users`: хеш пароля, соль, роль, счётчик `failed_attempts` и признак `is_locked`. Пока эти значения лежат в памяти формы, блокировка исчезает при перезапуске.

**Транзакция с `SELECT ... FOR UPDATE`** блокирует строку пользователя на время проверки. Две копии приложения не смогут одновременно прочитать один счётчик и записать каждая своё значение.

**Роль** определяет набор доступных действий. Проверка роли в интерфейсе скрывает лишние элементы, проверка в методе запрещает вызов операции. Для защиты нужны обе.

**Валидация** отсекает пустые поля, слишком короткий логин и недопустимую роль до записи. Уникальность логина обеспечивает ограничение `UNIQUE`, а приложение переводит ошибку ограничения в понятное сообщение.

**Сообщение об ошибке** это часть интерфейса, а не отладочный вывод. Оно называет действие, которое может выполнить человек: заполнить поле, собрать пазл, обратиться к администратору. Текст исключения, имя таблицы и строка подключения остаются в журнале и не попадают на экран.

### Шаг 1. Создайте таблицу пользователей

```sql
USE dkip2027_course;

CREATE TABLE IF NOT EXISTS users (
  id INT AUTO_INCREMENT PRIMARY KEY,
  login VARCHAR(64) NOT NULL UNIQUE,
  password_hash VARBINARY(32) NOT NULL,
  salt VARBINARY(16) NOT NULL,
  role ENUM('admin','user') NOT NULL DEFAULT 'user',
  failed_attempts INT NOT NULL DEFAULT 0,
  is_locked BOOLEAN NOT NULL DEFAULT FALSE,
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

Учебные записи `admin` и `student` создаёт само приложение при первом запуске, если таблица пуста. Пароль в открытом виде в скрипт не записывайте: приложение вычислит хеш и соль само.

Проверьте структуру и ограничение:

```sql
SHOW CREATE TABLE users;
SELECT id, login, role, failed_attempts, is_locked FROM users;
```

### Шаг 4. Сделайте пазл

Компонент `PuzzleControl` загружает `1.png`, масштабирует её до 200 на 200 и режет на четыре части. Слева показывается образец, справа сетка 2 на 2. Первое нажатие выбирает фрагмент, второе меняет его местами с выбранным.

```csharp
public bool IsSolved() => order.SequenceEqual(new[] { 0, 1, 2, 3 });

public void Shuffle()
{
    do { Random.Shared.Shuffle(order); } while (IsSolved());
    selected = -1;
    RefreshTiles();
}
```

Проверьте, что после перемешивания пазл никогда не собран сразу, а обмен двух фрагментов меняет только индексы в массиве `order`. Скриншот перемешанного пазла приложите как доказательство.

### Шаг 5. Проверьте вход и сообщения

Метод `SignIn` выполняет проверки по порядку: пустые поля, пазл, запись пользователя, блокировка, пароль.

```csharp
public static Account SignIn(string login, string password, bool solved)
{
    if (string.IsNullOrWhiteSpace(login) || string.IsNullOrWhiteSpace(password))
        throw new InvalidOperationException("Введите логин и пароль");
    if (!solved)
        throw new InvalidOperationException("Соберите изображение");
    // далее транзакция, SELECT ... FOR UPDATE и сверка хеша
}
```

Проверьте четыре случая: пустой логин, пустой пароль, несобранный пазл, неверный пароль. Каждый должен дать своё сообщение, а окно входа остаться открытым.

Хеш сравнивается не строкой, а побайтово с сохранённым значением. Из введённого пароля и сохранённой соли заново вычисляют PBKDF2 с тем же числом итераций. Если число итераций изменить, все прежние пароли перестанут подходить, поэтому значение фиксируют в одном месте и не дублируют по классам.

### Шаг 6. Настройте блокировку после трёх ошибок

Счётчик меняется в транзакции. При ошибке он увеличивается, при успехе обнуляется, после третьей ошибки ставится признак блокировки.

```csharp
using var tx = connection.BeginTransaction();
var select = new MySqlCommand(
  "SELECT id, password_hash, salt, role, failed_attempts, is_locked " +
  "FROM users WHERE login = @login FOR UPDATE", connection, tx);
select.Parameters.AddWithValue("@login", login);
// сверка хеша и ветки: успех, ошибка, блокировка
```

Проверьте сценарий: ошибитесь три раза подряд, закройте приложение, запустите снова и попробуйте войти с правильным паролем. Вход должен быть запрещён, а в таблице `is_locked` равно 1.

```sql
SELECT login, failed_attempts, is_locked FROM users WHERE login = 'student';
```

### Шаг 10. Заполните протокол проверки

Пройдите сценарии и запишите результат каждого.

| Сценарий | Ожидание | Факт | Вывод |
|---|---|---|---|
| Пустой логин | сообщение, окно открыто | | |
| Неверный пароль | сообщение, счётчик +1 | | |
| Несобранный пазл | сообщение, счётчик +1 | | |
| Третья ошибка | блокировка в базе | | |
| Перезапуск | блокировка сохранилась | | |
| Вход пользователя | нет вкладки «Пользователи» | | |
| Новый пользователь | запись создана | | |
| Повтор логина | сообщение о дубле | | |
| Снятие блокировки | вход разрешён | | |

Столбец «Факт» заполняют тем, что видно на экране: текст сообщения, значение `failed_attempts`, состояние `is_locked`. Запись «работает» ничего не доказывает, потому что не показывает, что именно проверяли.

Скриншоты делайте только как доказательства: окно входа, сообщение об ошибке, пазл, блокировка, таблица пользователей, снятие блокировки, рабочее окно.

### Шаг 11. Проверьте недоступную базу

Остановите MySQL в панели XAMPP и попробуйте войти. Приложение должно показать сообщение о подключении и остаться открытым. Затем запустите MySQL снова и повторите вход.

```powershell
Get-Process mysqld -ErrorAction SilentlyContinue
```

Пустой вывод означает, что сервер остановлен. Необработанное исключение в этот момент закрывает приложение и не даёт прочитать сообщение, поэтому проверка обязательна. Приложите скриншот сообщения об ошибке подключения.
