## Что делаем

В лекции 7 мы разобрали, как ОС управляет процессами, памятью, файлами и службами. Теперь соберём учебный серверный узел целиком. Результат работы это виртуальная машина с установленной серверной ОС, настроенная по чек-листу, и отчёт с доказательствами: скриншотами, командами и результатами проверок.

Работа рассчитана на 90 минут. Основная часть это установка Ubuntu Server 24.04 LTS, имя узла, обновления, время и проверка SSH. Статический адрес, ключи, firewall и служебный пользователь входят в расширенную часть: её выполняют на занятии при запасе времени или дома, чтобы собрать полный отчёт.

> [!NOTE] Что считается готовым результатом
> Виртуальная машина загружается, принимает вход по SSH, имеет понятное имя, синхронизированное время и установленные обновления. Для полного результата добавьте статический адрес, вход по ключу, firewall и снимок состояния. Все проверки записаны в отчёт.

## Подготовка

Для работы нужны:

- компьютер с гипервизором: VirtualBox, VMware Workstation, Hyper-V или KVM;
- образ **Ubuntu Server 24.04 LTS** с официального сайта;
- не менее 4 ГБ оперативной памяти для виртуальной машины, 2 процессорных ядра и 25 ГБ диска;
- доступ к интернету через NAT или мост;
- клиент SSH на рабочем компьютере: терминал Linux, PowerShell или PuTTY.

Создайте виртуальную машину со следующими параметрами:

| Параметр | Значение |
|---|---|
| Имя | `uifis-srv01` |
| Память | 4096 МБ |
| Процессоры | 2 |
| Диск | 25 ГБ, динамический или тонкий |
| Сеть | NAT или мост, как выдал преподаватель |
| ISO | Ubuntu Server 24.04 LTS |

Перед установкой сделайте снимок чистой машины с именем `before-install`. Если установка пойдёт не так, вы вернётесь к чистому состоянию, а не будете устанавливать систему заново.

## Установка

### Шаг 1. Загрузка установщика

Запустите виртуальную машину с ISO. Дождитесь меню загрузки и выберите установку Ubuntu Server. Если экран остаётся чёрным, проверьте, что ISO подключён к виртуальному приводу и что в настройках ВМ включена загрузка с него.

> [!SHOT] Скриншот 1
> Первый экран установщика с выбранным языком.

### Шаг 2. Язык и раскладка

Выберите английский язык установки и русскую раскладку клавиатуры, если преподаватель не указал другой вариант. Английский интерфейс удобнее для команд и сообщений об ошибках, а русская раскладка нужна для ввода текста.

### Шаг 3. Сеть

Установщик предложит настроить основной интерфейс. Для первого запуска достаточно DHCP. Запишите выданный адрес: он понадобится для SSH. Если DHCP не выдаёт адрес, проверьте, что виртуальный адаптер подключён и что в гипервизоре выбран правильный тип сети.

Не настраивайте статический адрес на этом шаге, если не уверены в шлюзе и DNS. Сначала получите рабочую сеть, затем измените настройки осознанно.

### Шаг 4. Диск

Выберите автоматическую разметку всего диска. Для учебного узла не нужны отдельные разделы под `/home` и `/var`, но запомните схему:

- `/` корневая файловая система;
- `/boot` загрузочные файлы;
- `/boot/efi` раздел EFI, если используется UEFI;
- swap файл или раздел.

Автоматическая разметка создаст нужные разделы. Не выбирайте шифрование диска, если преподаватель не выдал пароль и не требует этот режим: потеря ключа означает потерю данных.

### Шаг 5. Пользователь и SSH

Создайте административного пользователя:

| Поле | Значение |
|---|---|
| Имя | `student` |
| Имя сервера | `uifis-srv01` |
| Логин | `student` |
| Пароль | по указанию преподавателя, не менее 12 символов |

В списке дополнительных компонентов отметьте **Install OpenSSH server**. Если пропустили, SSH можно установить позже командой `sudo apt install openssh-server`.

### Шаг 6. Завершение установки

Дождитесь копирования пакетов. После предложения перезагрузиться извлеките ISO или отключите его в настройках ВМ, иначе установщик запустится снова. Войдите в систему под пользователем `student`.

> [!SHOT] Скриншот 2
> Приглашение входа после первой загрузки и вывод `hostnamectl`.

### Шаг 7. Первый вход и проверка

Выполните команды:

```bash
hostnamectl
ip -br a
ip route
df -h
free -h
```

Убедитесь, что имя узла `uifis-srv01`, интерфейс получил адрес, маршрут по умолчанию существует, корневой раздел смонтирован, память видна. Если имя другое, исправьте его на следующем шаге.

## Базовая настройка

### Шаг 8. Имя узла и локальная запись

Задайте имя и проверьте файл `/etc/hosts`:

```bash
sudo hostnamectl set-hostname uifis-srv01
sudo nano /etc/hosts
```

В файле должна быть строка:

```text
127.0.1.1 uifis-srv01
```

Она нужна, чтобы система быстро разрешала собственное имя. После изменения проверьте:

```bash
hostnamectl
hostname
```

### Шаг 9. Обновления

Обновите список пакетов и установите обновления:

```bash
sudo apt update
sudo apt full-upgrade -y
sudo apt autoremove -y
```

Если обновилось ядро, перезагрузите машину:

```bash
sudo reboot
```

После перезагрузки снова войдите и проверьте, что система загрузилась:

```bash
uname -r
systemctl --failed
```

`systemctl --failed` должен показать `0 loaded units listed`. Если есть сбойный юнит, откройте его журнал:

```bash
systemctl status <имя-юнита>
journalctl -u <имя-юнита> -n 50
```

### Шаг 10. Время и часовой пояс

Для Свердловской области:

```bash
sudo timedatectl set-timezone Asia/Yekaterinburg
sudo timedatectl set-ntp true
timedatectl
```

В выводе должно быть `System clock synchronized: yes` и правильный часовой пояс. Если синхронизация не работает, проверьте доступ к UDP-порту 123 и службу:

```bash
systemctl status systemd-timesyncd
```

> [!NOTE] Расширенная часть
> Шаги 11-14 можно выполнить дома или на занятии, если основная часть заняла меньше времени. Они нужны для полного отчёта, но не блокируют сдачу установленного и обновлённого узла.

### Шаг 11. Статический адрес

Статический адрес нужен, чтобы к серверу было удобно подключаться. Сначала узнайте имя интерфейса:

```bash
ip -br link
```

Пусть интерфейс называется `ens33`. Создайте отдельный файл netplan, чтобы не править файл, созданный установщиком:

```bash
sudo nano /etc/netplan/99-uifis.yaml
```

Пример для сети `192.168.56.0/24`:

```yaml
network:
  version: 2
  renderer: networkd
  ethernets:
    ens33:
      dhcp4: false
      addresses:
        - 192.168.56.10/24
      routes:
        - to: default
          via: 192.168.56.1
      nameservers:
        addresses: [192.168.56.1, 1.1.1.1]
```

Замените имя интерфейса, адрес, шлюз и DNS на значения, которые выдал преподаватель. Закройте файл, затем проверьте синтаксис и примените настройку с автоматическим откатом:

```bash
sudo chmod 600 /etc/netplan/99-uifis.yaml
sudo netplan try
```

`netplan try` ждёт подтверждения. Если связь потеряна, настройка откатится сама. После успешной проверки нажмите Enter. Затем проверьте:

```bash
ip -br a
ip route
ping -c 3 192.168.56.1
```

Если вы работаете через SSH, предупредите преподавателя: смена адреса разорвёт текущее подключение. Подключайтесь заново по новому адресу.

### Шаг 12. SSH и ключи

Проверьте, что служба SSH работает:

```bash
systemctl status ssh
sudo systemctl enable --now ssh
```

На рабочем компьютере создайте ключ, если его ещё нет:

```bash
ssh-keygen -t ed25519 -C "uifis-student"
```

Скопируйте открытый ключ на сервер:

```bash
ssh-copy-id student@192.168.56.10
```

Проверьте вход по ключу в новом окне терминала. Только после успешного входа отключайте пароль. Создайте отдельный файл настроек:

```bash
sudo nano /etc/ssh/sshd_config.d/99-uifis.conf
```

Содержимое:

```text
PermitRootLogin no
PasswordAuthentication no
PubkeyAuthentication yes
```

Проверьте конфигурацию и перезагрузите службу, не закрывая текущую сессию:

```bash
sudo sshd -t
sudo systemctl reload ssh
```

Если в новом окне вход по ключу не работает, вернитесь в открытую сессию и посмотрите журнал:

```bash
journalctl -u ssh -n 50
```

### Шаг 13. Firewall

Разрешите SSH до включения firewall, иначе можно потерять удалённый доступ:

```bash
sudo apt install ufw -y
sudo ufw allow OpenSSH
sudo ufw enable
sudo ufw status verbose
```

Для учебного узла достаточно SSH. Если позже появится веб-сервер, отдельно разрешат порт 80 или 443. Не открывайте все порты «на всякий случай».

### Шаг 14. Служебный пользователь и каталог

Приложение не должно работать от `student` или `root`. Создайте отдельного пользователя без входа в оболочку:

```bash
sudo adduser --system --group --home /srv/uifis --shell /usr/sbin/nologin uifis
sudo install -d -o uifis -g uifis -m 0750 /srv/uifis
ls -ld /srv/uifis
```

Права `0750` означают: владелец читает, пишет и заходит; группа читает и заходит; остальные не имеют доступа. Это минимальные права для каталога приложения.

### Шаг 15. Проверка и снимок

Выполните итоговые проверки:

```bash
hostnamectl
timedatectl
ip -br a
ip route
systemctl --failed
sudo ufw status verbose
ss -tulpn
df -h
df -i
free -h
lscpu
lsblk -f
journalctl -p 3 -b
```

`journalctl -p 3 -b` показывает сообщения уровня ошибки за текущую загрузку. Отдельные предупреждения допустимы, но повторяющиеся ошибки нужно объяснить.

Сделайте снимок виртуальной машины с именем `after-base-setup`. Снимок удобен для возврата стенда в учебное состояние, но он не заменяет резервную копию данных.

| Проверка | Команда | Ожидаемый результат | Отметка |
|---|---|---|---|

| Часовой пояс | `timedatectl` | `Asia/Yekaterinburg`, синхронизация включена | |
| Сеть | `ip -br a` | адрес из задания, интерфейс `UP` | |
| Маршрут | `ip route` | маршрут по умолчанию есть | |
| SSH | `systemctl status ssh` | `active (running)` | |
| Вход по ключу | `ssh student@адрес` | вход без пароля | |
| Firewall | `sudo ufw status verbose` | активен, разрешён только SSH | |
| Службы | `systemctl --failed` | нет сбойных юнитов | |
| Диск | `df -h`, `df -i` | есть свободное место и inode | |
| Память | `free -h` | память видна, swap не перегружен | |

| Снимок | интерфейс гипервизора | снимок `after-base-setup` существует | |

## Отчёт

В отчёте должны быть:

1. Параметры виртуальной машины: имя, память, процессоры, диск, сеть.
2. Схема разделов из вывода `lsblk -f` или `df -h`.
3. Заполненный чек-лист с фактическими результатами.
4. Скриншоты: первый экран установщика, вход после загрузки, вывод `ip -br a`, `systemctl --failed`, `sudo ufw status verbose`, успешный вход по SSH.
5. Один абзац о том, какая настройка вызвала трудности и как вы её проверили.
6. Ответы на контрольные вопросы.

Не вставляйте пароли, закрытые ключи и полные серийные номера. Для отчёта достаточно имени пользователя, адреса стенда и версии ОС.

1. Почему обновления устанавливают до настройки служб, а не после?

3. Зачем приложению отдельный пользователь `uifis`, если уже есть `student` с правами `sudo`?
4. Что проверить, если после смены статического адреса SSH перестал подключаться?
