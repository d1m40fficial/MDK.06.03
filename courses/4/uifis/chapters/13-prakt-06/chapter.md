## Цель работы

Собрать учебный серверный узел целиком. В лекции 7 мы разобрали, как ОС управляет процессами, памятью, файлами и службами. Результат работы это виртуальная машина с установленной серверной ОС, настроенная по чек-листу, и отчёт с доказательствами: скриншотами, командами и результатами проверок.

Основная часть это установка Ubuntu Server 24.04 LTS, имя узла, обновления, время и проверка SSH. Проброс порта SSH входит в базовую часть. Ключи, firewall и служебный пользователь входят в расширенную часть: её выполняют на занятии при запасе времени или дома в той же виртуальной машине, чтобы собрать полный отчёт.

> [!NOTE] Что считается готовым результатом
> Виртуальная машина загружается, принимает вход по SSH, имеет понятное имя, синхронизированное время и установленные обновления. Для полного результата добавьте проброс порта 2222, вход по ключу, firewall и снимок состояния. Все проверки записаны в отчёт.

## Оборудование и программное обеспечение

- VirtualBox 7.x на учебном компьютере; настройки хоста не меняем, все действия идут внутри виртуальной машины.
- ISO Ubuntu Server 24.04 LTS amd64: файл `ubuntu-24.04-live-server-amd64.iso`, страница загрузки https://releases.ubuntu.com/24.04/.
- 4096 МБ оперативной памяти, 2 процессорных ядра и 25 ГБ диска для виртуальной машины.
- Сеть VirtualBox: адаптер 1 в режиме NAT.
- PowerShell с командой `ssh` на рабочем компьютере.
- Шаблон отчёта и чек-лист проверок, скачанные в начале занятия.

Если ISO уже лежит на учебном компьютере, скачивать его не нужно.

> [!NOTE] Ограничения учебного компьютера
> Настройки Windows и системные параметры компьютера не меняем: их ограничивает администратор. Все действия выполняются внутри VirtualBox и виртуальной машины.

## Краткие теоретические сведения

**Серверная операционная система** управляет процессами, памятью, файлами и службами и обычно работает без графической оболочки. Администрирование идёт через терминал и удалённый вход, поэтому все проверки выполняются командами, а результат виден в их выводе.

**Имя узла** это постоянное имя машины в сети. Его задаёт `hostnamectl`, а строка `127.0.1.1` в `/etc/hosts` позволяет системе быстро разрешать собственное имя, не обращаясь к внешнему DNS.

**Сеть в режиме NAT** выдаёт адрес по DHCP и даёт выход в интернет через хост. Маршрут по умолчанию ведёт через шлюз NAT, а доступ с рабочего компьютера к гостю настраивают пробросом порта: хост слушает свой порт и передаёт соединение на порт гостя.

**Обновления** закрывают уязвимости и исправляют ошибки. Их ставят до настройки служб, чтобы не проверять firewall и SSH на устаревшей системе. После обновления ядра нужна перезагрузка, а `systemctl --failed` показывает, не осталось ли сбойных юнитов.

**Синхронизация времени** нужна для журналов, сертификатов и протоколов. Служба `systemd-timesyncd` получает время по NTP, а `timedatectl` показывает часовой пояс и признак синхронизации.

**SSH** даёт удалённый вход. Вход по ключу безопаснее пароля: закрытый ключ остаётся на рабочем компьютере, а на сервере лежит только открытый. Пароль отключают только после успешной проверки входа по ключу, иначе можно потерять доступ.

**Firewall** по умолчанию закрывает входящие соединения. Сначала разрешают SSH, затем порт службы и только после этого включают firewall, иначе текущая сессия закроется и новая не откроется.

**Служебный пользователь** запускает приложение без прав администратора. Каталог с правами `0750` доступен владельцу и группе, а остальные пользователи в него не попадают. **Снимок** виртуальной машины возвращает стенд в учебное состояние, но не заменяет резервную копию данных.

## Ход работы

Работа идёт в VirtualBox. Сначала создайте машину и установите систему, затем настройте узел и проверьте его по чек-листу. Все действия выполняются внутри виртуальной машины.

### Шаг 1. Создайте виртуальную машину

Создайте виртуальную машину со следующими параметрами:

| Параметр | Значение |
|---|---|
| Имя | `uifis-srv01` |
| Память | 4096 МБ |
| Процессоры | 2 |
| Диск | 25 ГБ, динамический или тонкий |
| Сеть | Адаптер 1: NAT; проброс TCP 2222 с хоста на 22 в госте |
| ISO | Ubuntu Server 24.04 LTS |

Перед установкой сделайте снимок чистой машины с именем `before-install`. Если установка пойдёт не так, вы вернётесь к чистому состоянию, а не будете устанавливать систему заново.

### Шаг 2. Запустите установщик

Запустите виртуальную машину с ISO. Дождитесь меню загрузки и выберите установку Ubuntu Server. Если экран остаётся чёрным, проверьте, что ISO подключён к виртуальному приводу и что в настройках ВМ включена загрузка с него. Скриншот экрана установщика не нужен: установленную систему доказывают проверки после первой загрузки.

### Шаг 3. Выберите язык и раскладку

Выберите английский язык установки и русскую раскладку клавиатуры. Английский интерфейс удобнее для команд и сообщений об ошибках, а русская раскладка нужна для ввода текста.

### Шаг 4. Настройте сеть

Установщик предложит настроить основной интерфейс. Оставьте DHCP: NAT выдаст адрес, а SSH с хоста будет подключаться через проброс порта 2222. Адрес внутри виртуальной машины записывать не нужно. Если DHCP не выдаёт адрес, проверьте, что виртуальный адаптер подключён и что в гипервизоре выбран режим NAT.

Не меняйте режим NAT на этом шаге. Сначала получите рабочую сеть и доступ к обновлениям, затем настройте проброс порта.

### Шаг 5. Разметьте диск

Выберите автоматическую разметку всего диска. Для учебного узла не нужны отдельные разделы под `/home` и `/var`, но запомните схему:

- `/` корневая файловая система;
- `/boot` загрузочные файлы;
- `/boot/efi` раздел EFI, если используется UEFI;
- swap файл или раздел.

Автоматическая разметка создаст нужные разделы. Не включайте шифрование диска: для учебного стенда оно не требуется, а потеря ключа означает потерю данных.

### Шаг 6. Создайте пользователя и включите SSH

Создайте административного пользователя:

| Поле | Значение |
|---|---|
| Имя | `student` |
| Имя сервера | `uifis-srv01` |
| Логин | `student` |
| Пароль | `UifisLab2026!` (только для этой учебной ВМ, не используйте его в других системах) |

В списке дополнительных компонентов отметьте **Install OpenSSH server**. Если пропустили, SSH можно установить позже командой `sudo apt install openssh-server`.

### Шаг 7. Завершите установку

Дождитесь копирования пакетов. После предложения перезагрузиться извлеките ISO или отключите его в настройках ВМ, иначе установщик запустится снова. Войдите в систему под пользователем `student`.

### Шаг 8. Войдите и проверьте систему

Выполните команды:

```bash
echo "Фамилия И.О., группа"
hostnamectl
ip -br a
ip route
df -h
free -h
```

Вместо строки с фамилией подставьте свои данные: она нужна как доказательство авторства на скриншоте. Убедитесь, что имя узла `uifis-srv01`, интерфейс получил адрес, маршрут по умолчанию существует, корневой раздел смонтирован, память видна. Если имя другое, исправьте его на следующем шаге.

Приложите скриншот вывода, в первой строке которого видны фамилия и группа, а ниже вывод `hostnamectl` и `ip -br a`.

### Шаг 9. Задайте имя узла и локальную запись

Задайте имя и проверьте файл `/etc/hosts`:

```bash
sudo hostnamectl set-hostname uifis-srv01
sudo nano /etc/hosts
```

В файле должна быть строка:

```text
127.0.1.1 uifis-srv01
```

Она нужна, чтобы система быстро разрешала собственное имя. После изменения проверьте:

```bash
hostnamectl
hostname
```

### Шаг 10. Установите обновления

Обновите список пакетов и установите обновления:

```bash
sudo apt update
sudo apt full-upgrade -y
sudo apt autoremove -y
```

Если обновилось ядро, перезагрузите машину:

```bash
sudo reboot
```

После перезагрузки снова войдите и проверьте, что система загрузилась:

```bash
uname -r
systemctl --failed
```

`systemctl --failed` должен показать `0 loaded units listed`. Если есть сбойный юнит, откройте его журнал:

```bash
systemctl status <имя-юнита>
journalctl -u <имя-юнита> -n 50
```

Приложите скриншот вывода `uname -r` и `systemctl --failed`.

### Шаг 11. Настройте время и часовой пояс

Для Свердловской области:

```bash
sudo timedatectl set-timezone Asia/Yekaterinburg
sudo timedatectl set-ntp true
timedatectl
```

В выводе должно быть `System clock synchronized: yes` и правильный часовой пояс. Если синхронизация не работает, проверьте доступ к UDP-порту 123 и службу:

```bash
systemctl status systemd-timesyncd
```

Приложите скриншот вывода `timedatectl`.

> [!NOTE] Расширенная часть
> Проброс порта обязателен для SSH. Шаги 13-15 нужны для полного отчёта, но не блокируют сдачу установленного и обновлённого узла.

### Шаг 12. Настройте проброс SSH-порта в VirtualBox

Выключите виртуальную машину. В VirtualBox откройте **Настройки → Сеть → Адаптер 1 → Дополнительно → Проброс портов** и добавьте правило:

| Имя | Протокол | Адрес хоста | Порт хоста | Адрес гостя | Порт гостя |
|---|---|---|---|---|---|
| ssh | TCP | 127.0.0.1 | 2222 | (оставьте пустым) | 22 |

Включите машину и проверьте подключение с рабочего компьютера в PowerShell:

```powershell
ssh -p 2222 student@127.0.0.1
```

Первый вход спросит подтверждение ключа хоста и пароль `UifisLab2026!`. Если подключение не открывается, проверьте, что виртуальная машина запущена, служба SSH включена, а правило проброса сохранено.

Приложите скриншот правила проброса в VirtualBox и окна PowerShell с успешным входом: после входа выполните `hostname` и `whoami`, чтобы на снимке было видно, куда вы попали.

### Шаг 13. Настройте SSH и ключи

Проверьте, что служба SSH работает:

```bash
systemctl status ssh
sudo systemctl enable --now ssh
```

На рабочем компьютере создайте ключ, если его ещё нет:

```bash
ssh-keygen -t ed25519 -C "uifis-student"
```

Скопируйте открытый ключ на сервер. В PowerShell выполните одну команду; пароль `UifisLab2026!` она спросит один раз:

```powershell
type $env:USERPROFILE\.ssh\id_ed25519.pub | ssh -p 2222 student@127.0.0.1 "mkdir -p ~/.ssh && chmod 700 ~/.ssh && cat >> ~/.ssh/authorized_keys && chmod 600 ~/.ssh/authorized_keys"
```

Проверьте вход по ключу в новом окне терминала:

```bash
ssh -p 2222 student@127.0.0.1
```

Только после успешного входа отключайте пароль. Создайте отдельный файл настроек:

```bash
sudo nano /etc/ssh/sshd_config.d/99-uifis.conf
```

Содержимое:

```text
PermitRootLogin no
PasswordAuthentication no
PubkeyAuthentication yes
```

Проверьте конфигурацию и перезагрузите службу, не закрывая текущую сессию:

```bash
sudo sshd -t
sudo systemctl reload ssh
```

Если в новом окне вход по ключу не работает, вернитесь в открытую сессию и посмотрите журнал:

```bash
journalctl -u ssh -n 50
```

Приложите скриншот входа по ключу без запроса пароля.

### Шаг 14. Включите firewall

Разрешите SSH до включения firewall, иначе можно потерять удалённый доступ:

```bash
sudo apt install ufw -y
sudo ufw allow OpenSSH
sudo ufw enable
sudo ufw status verbose
```

Для учебного узла достаточно SSH. Если позже появится веб-сервер, отдельно разрешат порт 80 или 443. Не открывайте все порты «на всякий случай».

Приложите скриншот вывода `sudo ufw status verbose`.

### Шаг 15. Создайте служебного пользователя и каталог

Приложение не должно работать от `student` или `root`. Создайте отдельного пользователя без входа в оболочку:

```bash
sudo adduser --system --group --home /srv/uifis --shell /usr/sbin/nologin uifis
sudo install -d -o uifis -g uifis -m 0750 /srv/uifis
ls -ld /srv/uifis
```

Права `0750` означают: владелец читает, пишет и заходит; группа читает и заходит; остальные не имеют доступа. Это минимальные права для каталога приложения. Приложите скриншот вывода `ls -ld /srv/uifis`.

### Шаг 16. Выполните итоговые проверки и снимок

Выполните итоговые проверки:

```bash
hostnamectl
timedatectl
ip -br a
ip route
systemctl --failed
sudo ufw status verbose
ss -tulpn
df -h
df -i
free -h
lscpu
lsblk -f
journalctl -p 3 -b
```

`journalctl -p 3 -b` показывает сообщения уровня ошибки за текущую загрузку. Отдельные предупреждения допустимы, но повторяющиеся ошибки нужно объяснить.

Приложите скриншоты вывода `df -h` и `free -h`, а также `journalctl -p 3 -b`. Сделайте снимок виртуальной машины с именем `after-base-setup`. Снимок удобен для возврата стенда в учебное состояние, но он не заменяет резервную копию данных.

### Шаг 17. Заполните чек-лист приёмки

| Проверка | Команда | Ожидаемый результат | Отметка |
|---|---|---|---|
| Имя узла | `hostnamectl` | `Static hostname: uifis-srv01` | |
| Часовой пояс | `timedatectl` | `Asia/Yekaterinburg`, синхронизация включена | |
| Сеть | `ip -br a` | адрес получен по DHCP, интерфейс `UP` | |

### Шаг 18. Оформите отчёт

В отчёте должны быть:

1. Параметры виртуальной машины: имя, память, процессоры, диск, сеть.
2. Схема разделов из вывода `lsblk -f` или `df -h`.
3. Заполненный чек-лист с фактическими результатами.
4. Скриншоты: `hostnamectl` и `ip -br a`, `uname -r` и `systemctl --failed`, `timedatectl`, правило проброса и вход по SSH, вход по ключу, `sudo ufw status verbose`, `ls -ld /srv/uifis`, `df -h`, `free -h`, `journalctl -p 3 -b`.
5. Один абзац о том, какая настройка вызвала трудности и как вы её проверили.
6. Ответы на контрольные вопросы.

Не вставляйте пароли, закрытые ключи и полные серийные номера. Для отчёта достаточно имени пользователя, адреса стенда и версии ОС.

Скриншот самого документа не нужен: отчёт сдаётся файлом DOCX.

### Шаг 19. Сохраните и сдайте отчёт

Перед сдачей закройте лишние окна, проверьте, что в отчёте нет паролей и что все скриншоты читаются без увеличения. Сохраните файл в DOCX.

## Критерии оценки

- **5**: система установлена и обновлена, имя, время и сеть настроены, SSH работает через проброс порта, вход по ключу проверен, firewall и служебный пользователь настроены, чек-лист заполнен фактическими результатами.
- **4**: узел работает, но одна из проверок расширенной части не выполнена или в чек-листе указан ожидаемый результат вместо фактического.
- **3**: система установлена, но имя, время или SSH настроены частично, firewall не проверен, отчёт без скриншотов проверок.
