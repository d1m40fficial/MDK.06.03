# fig-11-http: один запрос, пять причин

## Инсайт

Код состояния это не «ошибка есть или нет», а ответ на вопрос, где запрос остановился.
Один и тот же запрос `GET /api/schedule?group=ИС-21` проходит пять проверок: аутентификация
(401), права (403), маршрут (404), параметры (400), база (500). Пока замок не пройден,
запрос не идёт дальше; когда все пройдены, диск ставит `200 OK` и ответ уходит клиенту.
Верстать лишнее не нужно: одна причина отказа на карточку.

## Модель правды (числа из главы)

- Запрос клиента: метод `GET`, путь `/api/schedule`, параметры `group=ИС-21&date=2026-10-22`,
  заголовки `Host: uifis.local`, `Authorization: Bearer <token>`, `Accept: application/json`.
- Ответ при успехе: строка `HTTP/1.1 200 OK`, заголовок `Content-Type: application/json;
  charset=utf-8`, тело `{"group":"ИС-21","lessons":[{"time":"09:00","subject":"Базы данных"}]}`.
- Порядок проверок на сервере: `1 Сам токен → 401`, `2 Права → 403`, `3 Путь → 404`,
  `4 Параметры → 400`, `5 База → 500`. Первая проваленная проверка останавливает запрос
  и определяет код.
- Учебный сервер в VirtualBox, доступ с хоста через проброс порта 8080 на порт 80.

## Объект (машина, чья работа и есть концепт)

**Печная рамка с пятью штампами на верстаке.** По рельсу едет каретка с бланком запроса
(GET на бланке это одна гравировка, не текстовая строка). Пять штампных станций висят
на раме над рельсом: токен, права, путь, данные, база. Когда каретка проходит станцию,
штамп опускается и оставляет на бланке **принт** (мелкая печать, не слово), если проверка
пройдена. Когда модель выбрана «отказом», каретка останавливается под соответствующей
станцией: стрелка диска-кодировщика (то же самое, что цифровой код ответа) лежит на коде
(401/403/404/400/500), а лента журнала печатает строку. При успехе все пять штампов
опущены, диск ставит `200`, у каретки внизу появляется приёмный лоток ответа.

**Табло и лента**: дисковая шкала с насечками по шести кодам (200 / 201 / 400 / 401 /
403 / 404 / 500 слишком много, оставляем 200 / 400 / 401 / 403 / 404 / 500, шесть позиций,
шесть насечек), стрелка реально ездит. Readout внизу карточки именует вердикт:
`200 · все проверки пройдены`, `401 · нет токена`, `403 · прав недостаточно`,
`404 · нет пути`, `400 · неверные параметры`, `500 · ошибка базы`.

Важно: это не конвейер со станциями-фонариками. Смысл в штампах и реакции диска:
каретка лишь несёт бланк, а история написана принтами.

## Взаимодействие

- `→`, `↑`: следующая причина (по кругу: успех, токен, права, путь, параметры, база).
- `←`, `↓`: предыдущая причина.
- `Home` возврат к успеху, `End` к базе (500).
- Наведение/свайп: каретка едет к выбранной причине по рельсу, штампы опускаются
  последовательно, диск переехал на соответствующий код.
- Несколько секунд без действий: каретка сама идёт по всем шести сценариям.

## Карточка

- Fig 1.
- Заголовок: `Один запрос, пять причин`.
- Подсказка: `Выберите сценарий: штампы покажут, на какой проверке запрос остановился.`
- Табло: `200 · все проверки пройдены`.
- Ключи: штамп пройденной проверки, каретка с бланком запроса, стрелка кода ответа.
- Подпись: один и тот же запрос останавливается на первой непройденной проверке;
  код состояния говорит, какая это проверка. При успехе все штампы сработали и ответ
  уходит клиенту.

  плавное движение; при `prefers-reduced-motion` всё замирает.
