## Краткие теоретические сведения

Цикл тестирования это последовательность этапов от планирования до вывода о готовности. У каждого этапа есть результат и критерий выхода. План без критерия выхода превращается в список задач, который нельзя закрыть. Прогон без протокола нельзя повторить, а значит, нельзя и защитить.

Объём цикла задают требования и риски. В учебном наборе 18 требований, в модуль «Отгрузка» входят шесть. Их проверяют полностью, а остальные требования системы остаются за границей цикла. Граница записывается в плане: что проверено, что не проверено и почему.

Матрица покрытия связывает требование с проверками. Она показывает не число тестов, а ответ на вопрос, есть ли хотя бы одна проверка на каждое требование и какие требования остались без неё. Требование без проверки это не «мелкий недочёт», а неизвестный риск.

Дефект описывают так, чтобы его можно было воспроизвести: шаги, данные, ожидание, факт и окружение. В журнале у дефекта есть серьёзность, приоритет, владелец и статус. Без владельца дефект висит в статусе «Новый» неделями, а без статуса невозможно понять, исправлен он или нет.

Метрики цикла считают по протоколу: покрытие требований, выполнение плана, долю успешных проверок, число открытых дефектов и число критических открытых. Вывод о готовности делают по совокупности метрик, а не по одной цифре.

### Шаг 1. Разверните стенд и изучите данные

Ниже схема базы и учебный модуль. В нём есть создание отгрузки, проведение, отмена и проверка права на печать накладной. Модуль работает с файлом `sklad.db`, товары хранятся с остатком по площадке, заказы имеют статус.

```sql
CREATE TABLE products (sku TEXT PRIMARY KEY, site TEXT NOT NULL, stock INTEGER NOT NULL CHECK (stock >= 0));
CREATE TABLE orders (order_id TEXT PRIMARY KEY, sku TEXT NOT NULL, qty INTEGER NOT NULL, status TEXT NOT NULL);
CREATE TABLE shipments (shipment_id TEXT PRIMARY KEY, order_id TEXT NOT NULL, sku TEXT NOT NULL, qty INTEGER NOT NULL, status TEXT NOT NULL);

INSERT INTO products VALUES
  ('SKU-0142', 'Тверь', 12),
  ('SKU-0087', 'Москва', 0),
  ('SKU-0311', 'Калуга', 3),
  ('SKU-0205', 'Тула', 7);

INSERT INTO orders VALUES
  ('З-501', 'SKU-0142', 5, 'ready'),
  ('З-502', 'SKU-0142', 8, 'ready'),
  ('З-503', 'SKU-0087', 2, 'ready'),
  ('З-504', 'SKU-0311', 3, 'ready'),
  ('З-505', 'SKU-0205', 7, 'ready'),
  ('З-506', 'SKU-0205', 1, 'ready'),
  ('З-507', 'SKU-0142', 4, 'new');
```

Сохраните схему как `.../module-project/seed.sql`. Скрипт создания базы читает файл и выполняет его целиком.

```python
import sqlite3

with open("seed.sql", encoding="utf-8") as source:
    script = source.read()

with sqlite3.connect("sklad.db") as db:
    db.executescript(script)
print("база создана")
```

`executescript` выполняет несколько команд за один вызов, а `with sqlite3.connect` фиксирует изменения при успешном выходе. Сохраните скрипт как `.../module-project/init_db.py` и запустите `python init_db.py`. Для повторного прогона удалите `sklad.db` и выполните команду снова.

Модуль для проверки сохраните как `.../module-project/shipment.py`.

```python
import sqlite3

DB = "sklad.db"


def connect():
    return sqlite3.connect(DB)


def create_shipment(order_id, qty):
    with connect() as db:
        row = db.execute(
            "SELECT sku, qty, status FROM orders WHERE order_id = ?", (order_id,)
        ).fetchone()
        if row is None:
            return {"ok": False, "code": "order_not_found"}
        sku, ordered, status = row
        if status != "ready":
            return {"ok": False, "code": "order_not_ready"}
        if qty > ordered:
            return {"ok": False, "code": "qty_exceeds_order"}
        shipment_id = f"S-{order_id}"
        db.execute(
            "INSERT INTO shipments (shipment_id, order_id, sku, qty, status) "
            "VALUES (?, ?, ?, ?, 'draft')",
            (shipment_id, order_id, sku, qty),
        )
        return {"ok": True, "shipment_id": shipment_id}


def post_shipment(shipment_id):
    with connect() as db:
        row = db.execute(
            "SELECT sku, qty, status FROM shipments WHERE shipment_id = ?",
            (shipment_id,),
        ).fetchone()
        if row is None:
            return {"ok": False, "code": "not_found"}
        sku, qty, status = row
        if status != "draft":
            return {"ok": False, "code": "already_posted"}
        db.execute("UPDATE products SET stock = stock - ? WHERE sku = ?", (qty, sku))
        db.execute("UPDATE shipments SET status = 'posted' WHERE shipment_id = ?", (shipment_id,))
        stock = db.execute("SELECT stock FROM products WHERE sku = ?", (sku,)).fetchone()[0]
        return {"ok": True, "stock_after": stock}


def cancel_shipment(shipment_id):
    with connect() as db:
        row = db.execute(
            "SELECT sku, qty, status FROM shipments WHERE shipment_id = ?",
            (shipment_id,),
        ).fetchone()
        if row is None:
            return {"ok": False, "code": "not_found"}
        sku, qty, status = row
        if status == "cancelled":
            return {"ok": False, "code": "already_cancelled"}
        db.execute("UPDATE products SET stock = stock + ? WHERE sku = ?", (qty, sku))
        db.execute("UPDATE shipments SET status = 'cancelled' WHERE shipment_id = ?", (shipment_id,))
        return {"ok": True}


def invoice_allowed(shipment_id):
    with connect() as db:
        row = db.execute(
            "SELECT status FROM shipments WHERE shipment_id = ?", (shipment_id,)
        ).fetchone()
    return row is not None and row[0] in ("posted", "draft")
```

Проверьте стенд двумя вызовами. Функция `run` перехватывает исключение и печатает его, чтобы одна ошибка не останавливала весь прогон.

```python
from shipment import create_shipment, post_shipment


def run(name, call):
    try:
        print(f"{name}: {call()}")
    except Exception as error:
        print(f"{name}: исключение {type(error).__name__}: {error}")


run("C-01 создание из готового заказа", lambda: create_shipment("З-501", 5))
run("C-02 проведение отгрузки", lambda: post_shipment("S-З-501"))
```

Сохраните пример как `.../module-project/checks.py` и запустите `python checks.py`. Убедитесь, что после проведения остаток товара `SKU-0142` уменьшился с 12 до 7. Дальше добавляйте в файл свои вызовы, по одному на проверку.

### Шаг 4. Выполните прогон

Запустите `python checks.py` и выполняйте проверки по протоколу. После каждой проверки записывайте фактический результат, а не только слово «работает». Если функция вернула словарь, скопируйте код ответа. Если возникло исключение, запишите его тип и текст.

Порядок проверок влияет на данные. Проведение уменьшает остаток, отмена возвращает его, повторное создание может изменить состояние базы. Поэтому перед сценарием, который требует чистых данных, удаляйте `sklad.db` и выполняйте `python init_db.py` заново. В протоколе отмечайте, с какого состояния начата проверка.

Проверьте не только ответ функции, но и базу. После проведения отгрузки выполните запрос к `products` и убедитесь, что остаток изменился на нужное число. После отмены проверьте, что остаток вернулся к исходному. Расхождение между ответом функции и базой это отдельный дефект.

## Требования к отчёту

Отчёт в DOCX объёмом четыре-шесть страниц. Формат: A4, поля 3 см слева, 1,5 см справа, 2 см сверху и снизу, Times New Roman 14 пт, интервал 1,5, отступ первой строки 1,25 см. Заголовки Heading 1 и Heading 2, таблицы Table Grid с шапкой по центру, название таблицы под таблицей.

## Критерии оценки

Оценка выставляется по шкале от 1 до 5.

- **5**: план содержит пять этапов с критериями выхода, матрица покрывает все шесть требований, выполнено не менее четырнадцати проверок, дефекты описаны воспроизводимо, метрики посчитаны по протоколу, вывод опирается на критические дефекты.
- **4**: работа выполнена полностью, но одна группа проверок неполная или один дефект описан без шагов воспроизведения.
- **3**: план и матрица составлены формально, проверки ограничены успешными сценариями, дефекты описаны общими словами, вывод не связан с метриками.
- **2**: работа не выполнена.
- **1**: работа выполнена с использованием ИИ или скопирована полностью или частично, 1 балл без возможности исправления.
