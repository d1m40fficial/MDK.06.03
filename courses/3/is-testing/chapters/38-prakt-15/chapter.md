## Краткие теоретические сведения

Обмен с внешней системой почти всегда асинхронный по смыслу, даже если запрос выглядит синхронным. «Склад+» отправляет документ и ждёт ответ. Бухгалтерия принимает документ, проверяет поля и отвечает кодом. Между отправкой и ответом есть сеть, таймаут и очередь, и в этом промежутке документ может оказаться в неопределённом состоянии.

Таймаут это не отказ. Клиент перестал ждать через 10 секунд, но сервер мог принять документ и продолжить обработку. Если после таймаута отправить документ ещё раз, в бухгалтерии появятся две записи об одной продаже. Защита от этого называется идемпотентностью: повтор с тем же ключом не создаёт новую запись, а возвращает результат первой операции.

Ключ идемпотентности должен быть стабильным. В «Склад+» это `doc_id`, который присваивается документу при создании и не меняется при повторной отправке. Если ключ генерировать заново на каждую попытку, защита не работает: бухгалтерия увидит два разных документа.

Повторная отправка бывает нужна. Сеть моргнула, сервис вернул 503, соединение оборвалось. Политика повторов задаёт число попыток и паузы. Повторяют только те ошибки, которые могут исчезнуть сами: таймаут, обрыв соединения, 503. Ошибку валидации 400 повторять бессмысленно: документ не станет правильным от второй попытки.

Очередь хранит документы, которые не удалось отправить. Она нужна, чтобы работа склада не останавливалась из-за недоступной бухгалтерии. У очереди есть порядок, предел объёма и правило повторной отправки. Если очередь потеряет документ, склад отгрузит товар без документа в учёте. Если очередь отправит документ дважды, в бухгалтерии появится дубль.

Контракт обмена фиксирует адрес, метод, заголовки, поля, типы, обязательность и коды ответов. Проверка контракта идёт первой: пока не ясно, что считать правильным запросом и ответом, проверять таймауты и повторы рано.

### Шаг 2. Поднимите заглушку бухгалтерии

Заглушка принимает документы, проверяет поля и хранит список принятых идентификаторов. Параметры `delay` и `fail` в адресе позволяют смоделировать медленный ответ и недоступность.

```python
import time

from flask import Flask, jsonify, request

app = Flask(__name__)
seen = set()
SITES = {"Москва", "Тверь", "Тула", "Калуга"}


@app.post("/api/documents")
def receive():
    if request.args.get("reset") == "1":
        seen.clear()
        return jsonify({"status": "reset"}), 200
    time.sleep(float(request.args.get("delay", 0)))
    fail = request.args.get("fail")
    if fail:
        return jsonify({"code": "unavailable", "message": "сервис недоступен"}), int(fail)
    doc = request.get_json(silent=True) or {}
    fields = {}
    for name in ("doc_id", "doc_type", "doc_date", "site", "counterparty_inn", "lines", "total"):
        if not doc.get(name):
            fields[name] = "обязательное поле"
    if doc.get("site") and doc["site"] not in SITES:
        fields["site"] = "неизвестная площадка"
    if doc.get("counterparty_inn") and len(str(doc["counterparty_inn"])) != 12:
        fields["counterparty_inn"] = "ожидается 12 цифр"
    if doc.get("lines"):
        amount = sum(line["qty"] * line["price"] for line in doc["lines"])
        if abs(amount - doc.get("total", 0)) > 0.01:
            fields["total"] = f"ожидается {amount:.2f}"
    if fields:
        return jsonify({"code": "validation_error", "fields": fields}), 400
    if doc["doc_id"] in seen:
        return jsonify({"code": "duplicate", "doc_id": doc["doc_id"]}), 409
    seen.add(doc["doc_id"])
    return jsonify({"status": "accepted", "doc_id": doc["doc_id"]}), 201


@app.get("/api/documents")
def list_documents():
    return jsonify({"documents": sorted(seen)})


if __name__ == "__main__":
    app.run(port=8099)
```

`@app.post` связывает адрес с функцией, `request.get_json` читает тело, `jsonify` собирает JSON, а второй элемент кортежа задаёт код ответа. `time.sleep` задерживает ответ, `fail` возвращает заданный код до проверки полей. Список `seen` играет роль таблицы бухгалтерии: по нему видно, какие документы уже приняты.

Скрипт отправки читает документы из `docs.json`, делает попытки с паузами и складывает неудачные документы в `queue.jsonl`.

```python
import json
import sys
import time
import urllib.error
import urllib.request

BASE = "http://localhost:8099/api/documents"
TIMEOUT = 10
PAUSES = [1, 2, 4]


def post(doc):
    data = json.dumps(doc, ensure_ascii=False).encode("utf-8")
    request = urllib.request.Request(
        BASE,
        data=data,
        headers={"Content-Type": "application/json", "X-Api-Key": "sklad-test-key"},
        method="POST",
    )
    try:
        with urllib.request.urlopen(request, timeout=TIMEOUT) as response:
            return response.status, json.loads(response.read().decode("utf-8"))
    except urllib.error.HTTPError as error:
        return error.code, json.loads(error.read().decode("utf-8"))


def send(doc):
    for attempt, pause in enumerate([0] + PAUSES, 1):
        time.sleep(pause)
        try:
            status, body = post(doc)
        except (urllib.error.URLError, TimeoutError) as error:
            print(f"{doc['doc_id'][:8]} попытка {attempt}: нет ответа ({error})")
            continue
        print(f"{doc['doc_id'][:8]} попытка {attempt}: {status} {body.get('status') or body.get('code')}")
        if status in (200, 201, 409):
            return True
    return False


def main():
    path = "queue.jsonl" if len(sys.argv) > 1 and sys.argv[1] == "--flush" else "docs.json"
    with open(path, encoding="utf-8") as source:
        if path.endswith(".jsonl"):
            docs = [json.loads(line) for line in source if line.strip()]
        else:
            docs = json.load(source)
    queue = []
    for doc in docs:
        if not send(doc):
            queue.append(doc)
    with open("queue.jsonl", "w", encoding="utf-8") as target:
        for doc in queue:
            target.write(json.dumps(doc, ensure_ascii=False) + "\n")
    print(f"в очереди: {len(queue)}")


if __name__ == "__main__":
    main()
```

`urllib.request.Request` собирает запрос, `urlopen` ограничивает ожидание параметром `timeout`. Исключение `HTTPError` содержит код и тело ответа, поэтому его разбирают отдельно от обрыва соединения. Функция `send` считает успехом коды 200, 201 и 409: дубль означает, что документ уже принят. Функция `main` читает либо исходный файл, либо очередь при запуске с ключом `--flush`.
