## Краткие теоретические сведения

Профиль нагрузки описывает, кто и как нагружает систему. В него входят число одновременных пользователей, распределение ролей, доли операций, паузы между запросами, длительность прогона и критерии приёмки. Для «Склад+» критерий такой: при 40 пользователях 95 процентов запросов быстрее 2 секунд, ошибок сервера не больше 1 процента, пропускная способность не ниже 12 запросов в секунду. Для отчёта по остаткам отдельный порог: p95 не выше 3 секунд.

Время отклика оценивают перцентилями. p50 это медиана, p95 означает, что 95 процентов запросов быстрее указанного времени. Среднее значение скрывает редкие медленные ответы, поэтому в отчёт идут p50, p95 и p99. Пропускная способность показывает, сколько запросов система выполняет за секунду. По закону Литтла число запросов в работе равно пропускной способности, умноженной на среднее время отклика.

Узкое место это ресурс, который исчерпывается первым. Это может быть процессор приложения, число обработчиков, пул соединений с базой, блокировки SQLite или диск. Редкая тяжёлая операция способна забрать больше половины мощности, даже если её доля в запросах невелика.

Проверка доступа отвечает на три вопроса: кто пользователь, что ему разрешено и принадлежит ли ему объект. Роль проверяют по матрице операций, включая запреты. Владение проверяют подменой номера документа, площадки или поля в теле запроса. Скрытая кнопка защитой не является, потому что запрос можно отправить напрямую.

Валидация проверяет тип, диапазон, длину и список допустимых значений. Основная проверка стоит на сервере, клиентская только подсказывает пользователю. Секреты это пароли, ключи API и строки подключения. Их место в переменных окружения, а не в коде, git и журналах.

### Шаг 3. Запустите прогон по ступеням

Ниже пример генератора нагрузки на Python. Он открывает пять потоков, каждый делает запрос к списку товаров, ждёт секунду и повторяет. Результаты сохраняются в `results.csv`.

```python
import csv
import time
from concurrent.futures import ThreadPoolExecutor
from urllib.parse import quote
from urllib.request import Request, urlopen

BASE = "http://127.0.0.1:5000"
TOKEN = "store-token"
USERS = 5
DURATION = 20
PAUSE = 1.0


def one_request():
    started = time.perf_counter()
    request = Request(
        f"{BASE}/api/products?site={quote('Тверь')}",
        headers={"Authorization": f"Bearer {TOKEN}"},
    )
    with urlopen(request, timeout=10) as response:
        code = response.status
        response.read()
    return code, (time.perf_counter() - started) * 1000


def user_loop(stop_at):
    rows = []
    while time.perf_counter() < stop_at:
        rows.append(one_request())
        time.sleep(PAUSE)
    return rows


with ThreadPoolExecutor(max_workers=USERS) as pool:
    stop_at = time.perf_counter() + DURATION
    parts = list(pool.map(lambda _: user_loop(stop_at), range(USERS)))

rows = [row for part in parts for row in part]
with open("results.csv", "w", newline="", encoding="utf-8") as f:
    writer = csv.writer(f)
    writer.writerow(["code", "ms"])
    writer.writerows(rows)

codes = [code for code, _ in rows]
times = sorted(ms for _, ms in rows)
p95 = times[int(len(times) * 0.95) - 1]
print(f"запросов: {len(rows)}, ошибок: {sum(1 for c in codes if c >= 400)}")
print(f"p50: {times[len(times) // 2]:.0f} мс, p95: {p95:.0f} мс")
```

На учебном стенде пример дал такой результат. Числа зависят от машины и сети, поэтому сравнивать нужно не с этими значениями, а между своими ступенями.

```text
запросов: 95, ошибок: 0
p50: 70 мс, p95: 76 мс
```

Разберите строки, которые понадобятся при изменении. `ThreadPoolExecutor(max_workers=USERS)` задаёт число одновременных пользователей. `PAUSE` задаёт паузу между запросами. `DURATION` задаёт длительность ступени. `quote('Тверь')` кодирует кириллицу в адресе, иначе запрос не отправится.

Теперь выполните вариацию: подставьте адрес стенда и токен, который выдал преподаватель, и запустите ступени 10, 20, 40 и 60 пользователей по 60 секунд. Для каждой ступени сохраните отдельный файл `results_10.csv`, `results_20.csv`, `results_40.csv` и `results_60.csv`. Перед каждой ступенью восстанавливайте базу из копии, иначе предыдущий прогон изменит данные.

Если генератор работает на той же машине, что и стенд, отметьте это в отчёте как ограничение: клиент и сервер делят процессор, поэтому время отклика завышено.

### Шаг 4. Снимите метрики

Файл результатов содержит две колонки: код ответа и время в миллисекундах. Одна строка выглядит так.

```text
code,ms
200,143
```

Скрипт ниже читает файл и считает перцентили. Сначала проверьте его на небольшом файле `sample.csv`, где десять строк, затем запустите на своих результатах.

```python
import csv

with open("sample.csv", encoding="utf-8") as f:
    rows = list(csv.DictReader(f))

times = sorted(int(row["ms"]) for row in rows)
errors = sum(1 for row in rows if int(row["code"]) >= 400)


def pct(p):
    k = (len(times) - 1) * p
    lo, hi = int(k), min(int(k) + 1, len(times) - 1)
    return times[lo] + (times[hi] - times[lo]) * (k - lo)


print(f"запросов: {len(rows)}")
print(f"ошибок: {errors} ({errors / len(rows):.1%})")
print(f"p50: {pct(0.5):.0f} мс")
print(f"p95: {pct(0.95):.0f} мс")
print(f"p99: {pct(0.99):.0f} мс")
print(f"дольше 2000 мс: {sum(1 for t in times if t > 2000) / len(times):.1%}")
```

На десяти строках с одной ошибкой и одним медленным ответом скрипт печатает:

```text
запросов: 10
ошибок: 1 (10.0%)
p50: 152 мс
p95: 2152 мс
p99: 2350 мс
дольше 2000 мс: 10.0%
```

Замените имя файла на свой и заполните таблицу по ступеням. Пропускную способность посчитайте отдельно: число запросов разделите на длительность ступени в секундах.

| Ступень | Пользователи | Запросов | Ошибки, % | p50, мс | p95, мс | p99, мс | Дольше 2 с, % | Запросов в секунду |
|---|---|---|---|---|---|---|---|---|
| 1 | 10 |  |  |  |  |  |  |  |
| 2 | 20 |  |  |  |  |  |  |  |
| 3 | 40 |  |  |  |  |  |  |  |
| 4 | 60 |  |  |  |  |  |  |  |

Отдельно снимите метрики по операциям на ступени 40. Для этого запустите короткий прогон по каждому адресу или разделите запросы в сценарии и сохраните операцию в колонку `path`. Для операции отчёта используйте `GET /api/report`, для приёмки `POST /api/acceptance` с телом `{"supply_id": 505, "qty": 12}`. В примере меняются метод, адрес и тело в `one_request`, остальная логика остаётся прежней. В отчёт войдут p50 и p95 для списка товаров, приёмки, отгрузки, отчёта и входа.

### Шаг 8. Соберите отчёт
