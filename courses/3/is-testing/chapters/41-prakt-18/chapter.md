## Цель работы

Подготовить и провести защиту результатов тестирования модуля «Отгрузка»: собрать тезисы доклада, свернуть отчёт в семь слайдов, сверить числа и ответить на вопросы по объёму проверок, дефектам и выводу о готовности.

Результат работы это доклад, презентация, лист сверки чисел и протокол ответов. Защита показывает, что решения по проверкам приняты осознанно, а не переписаны из шаблона.

## Краткие теоретические сведения

Защита это короткий разговор о решениях. Слушателю не нужен пересказ отчёта: отчёт у него есть. Ему нужно понять, какой риск закрывали проверки, что нашли, что осталось открытым и почему вывод о готовности именно такой.

Доклад строится от вопроса к доказательству. Сначала цель и объём, затем подход и риски, потом результаты и дефекты, в конце вывод и ограничения. Каждая часть опирается на число из отчёта. Фраза «мы всё проверили» не доказательство, а число проверок и покрытие требований доказательство.

Ответ на вопрос тоже строится по схеме: факт, причина, решение. Факт это число или наблюдение из данных. Причина объясняет, почему так получилось. Решение говорит, что сделано или что предлагается. Ответ без факта звучит как мнение, ответ без решения оставляет вопрос открытым.

Вопросы на защите проверяют не память, а понимание. Могут спросить, почему требований шесть, а проверок восемнадцать, почему покрытие 100 процентов при заблокированной проверке и почему критический дефект не закрыт до выпуска. Ответ «так получилось» показывает, что решения не принадлежат автору.

Ограничения называют сами. Если о них не сказать, их найдут в вопросах, и тогда защита превратится в оправдание. Честно названное ограничение с планом проверки звучит сильнее, чем обещание, что всё идеально.

Отчёт и защита решают разные задачи. Отчёт хранит доказательства и позволяет перепроверить расчёты. Защита показывает, что автор понимает свои решения и может объяснить их без документа. Поэтому на защите не читают отчёт, а отвечают на вопросы, которые он вызывает.

## Ход работы

### Шаг 1. Соберите тезисы доклада

Доклад состоит из семи частей. Для каждой запишите вопрос, на который она отвечает, и три-пять чисел или фактов из отчёта. Первая строка дана как образец.

| Часть | Вопрос слушателя | Факты из проекта |
|---|---|---|
| Цель и объём | что проверяли и что осталось за границей | 6 требований из 18, модуль «Отгрузка», 4 площадки |
| Подход и риски | почему выбрали такую глубину |  |
| Результаты | что показал прогон |  |
| Дефекты | что нашли и что осталось |  |
| Готовность | можно ли передавать модуль |  |
| Ограничения | чего не проверяли и почему |  |
| Следующий шаг | что делать после защиты |  |

Тезисы пишут короткими фразами, а не абзацами. Одна часть доклада содержит одну мысль. Если в части появляются две мысли, её делят или переносят вторую в следующий слайд.

Для каждой части выберите один главный факт и одно следствие. Главный факт отвечает, что произошло. Следствие объясняет, почему это важно для склада. Например, факт «три дефекта открыты» сам по себе ничего не говорит, а следствие «один из них критический, поэтому остаток может стать отрицательным» говорит. Пары «факт и следствие» достаточно для устного доклада, остальные числа остаются в отчёте.

### Шаг 2. Подготовьте презентацию

Презентация состоит из семи слайдов. На каждом слайде одна мысль, не больше двух чисел и подпись, объясняющая, что эти числа значат.

| Слайд | Содержание | Что показать |
|---|---|---|
| 1 | Титул | модуль, период цикла, автор |
| 2 | Цель и объём | 6 требований, 18 проверок, граница цикла |
| 3 | Подход и риски | реестр рисков, выбранная глубина |
| 4 | Результаты | покрытие, выполнение, доля успешных |
| 5 | Дефекты | 8 дефектов, 3 открытых, 1 критический |
| 6 | Готовность | критерии и факт, вывод |
| 7 | Ограничения и шаги | что не проверено, кто и когда закроет |

Слайд не дублирует абзац отчёта. Вместо текста на слайде таблица, диаграмма или три короткие строки. Подпись под диаграммой отвечает, что из неё следует, а не пересказывает подписи осей.

Проверьте читаемость: основной текст не меньше 18 пунктов, на слайде не больше семи строк, цвета не заменяют подписи. Слайд, который нельзя прочитать с последнего ряда, не работает.

Диаграмму ставят там, где нужно сравнить, а таблицу там, где нужно назвать точное значение. Для семи слайдов хватает одной диаграммы динамики дефектов и одной таблицы критериев. Если диаграмм больше, слушатель перестаёт понимать, какая из них главная.

### Шаг 3. Сверьте числа

Перед защитой числа в отчёте, презентации и тезисах должны совпадать. Заполните лист сверки. Первая строка дана как образец.

| Показатель | В отчёте | На слайде | В тезисах | Источник | Совпадает |
|---|---|---|---|---|---|
| Всего проверок | 18 | 18 | 18 | `run.csv` | да |
|  |  |  |  |  |  |
|  |  |  |  |  |  |
|  |  |  |  |  |  |
|  |  |  |  |  |  |

В лист входят покрытие требований, доля успешных проверок, число дефектов, число открытых дефектов, число критических открытых и число заблокированных проверок. Для каждого показателя укажите источник: файл, лист или журнал.

Расхождение в числе разрушает доверие ко всему докладу. Если в отчёте 71 процент, а на слайде 70, слушатель решит, что числа взяты из разных прогонов. Округление допустимо только одинаковое во всех документах, с пояснением в подписи.

### Шаг 4. Проведите репетицию

Репетиция нужна не для заучивания текста, а для проверки структуры. Проговорите доклад по слайдам, не подглядывая в отчёт. Отметьте места, где приходится останавливаться и вспоминать число: их нужно переписать или вынести на слайд.

Попросите слушателя задать три вопроса из списка ниже. Ответьте по схеме «факт, причина, решение» и запишите ответ. Если ответ занимает больше трёх предложений, его нужно сократить.

```text
1. Почему выбраны именно эти шесть требований?
2. Почему покрытие 100 процентов при заблокированной проверке?
3. Почему доля успешных 71 процент, а вывод «не готов»?
4. Как проверяли отрицательный остаток?
5. Почему дефект D-02 критический?
6. Какие дефекты можно принять и почему?
7. Как убедились, что исправление не сломало соседние функции?
8. Что бы вы проверили при наличии ещё одного дня?
9. Какие риски остались вне цикла?
10. Почему в журнале 8 дефектов, а в выгрузке 5?
11. Что изменится при 40 одновременных пользователях?
12. Как связаны 18 проверок и 6 требований?
```

Отдельно подготовьте ответ на вопрос, на который нет данных. Честный ответ звучит так: «Этого мы не проверяли, риск остался в таком состоянии, предлагаю проверить так». Он лучше выдуманного числа.

### Шаг 5. Проведите защиту

Защита идёт по регламенту, который объявляет преподаватель. Сначала доклад по семи слайдам, затем вопросы. Во время доклада держите перед собой тезисы, а не полный текст отчёта: чтение с листа разрушает контакт со слушателем.

На вопрос отвечайте после короткой паузы. Сначала назовите факт, затем причину, затем решение. Если вопрос непонятен, переформулируйте его своими словами и получите подтверждение. Если ответа нет, скажите об этом прямо и предложите способ проверить.

Вопрос может содержать скрытое утверждение. «Почему вы не проверили нагрузку?» предполагает, что нагрузку обязаны были проверить. Ответ начинается с границы цикла: «нагрузка не входила в шесть требований модуля, риск остался вне цикла». Затем называются причина и следующий шаг. Спорить с формулировкой вопроса бесполезно, полезно вернуть разговор к объёму и данным.

| Вопрос | Факт | Причина | Решение |
|---|---|---|---|
|  |  |  |  |
|  |  |  |  |
|  |  |  |  |

В протокол записывайте вопросы дословно и ответы кратко. Протокол нужен не для отчёта, а для разбора: по нему видно, какие темы доклад не объяснил.

### Шаг 6. Заполните лист оценки

Оцените свою защиту по пяти критериям. Для каждого балла приведите доказательство: слайд, число или ответ.

| Критерий | Что оценивают | Балл | Доказательство |
|---|---|---|---|
| Полнота | объём, требования, дефекты |  |  |
| Обоснованность | вывод по метрикам |  |  |
| Ответы | точность и ссылка на данные |  |  |
| Презентация | структура и читаемость |  |  |
| Ограничения | честность и следующий шаг |  |  |

Лист оценки не заменяет оценку преподавателя. Он показывает, какие части доклада автор считает сильными, а какие требуют доработки.

Балл без доказательства не считается. Если поставлена оценка 5 за ответы, рядом указывают вопрос и ответ, который её подтверждает. Если балл ниже, указывают, чего не хватило: факта, причины или решения. Такой лист помогает готовиться к следующей защите, а не только фиксирует результат.

### Шаг 7. Разберите замечания

После защиты выпишите замечания и вопросы, на которые ответ был слабым. Для каждого замечания укажите, что исправить и где: в отчёте, на слайде, в тезисах или в самом наборе проверок.

| Замечание | Что исправить | Где | Срок |
|---|---|---|---|
|  |  |  |  |
|  |  |  |  |
|  |  |  |  |

Разбор завершает цикл. Если замечание относится к проверкам, его вносят в план следующего цикла. Если к формулировке вывода, правят отчёт. Если к докладу, переделывают слайд и репетируют заново.

Протокол и разбор хранят вместе с отчётом. Через месяц по ним видно, какие вопросы задавали и что было исправлено. Без такой записи замечания теряются, а следующая защита повторяет те же ошибки.

## Требования к отчёту

Отчёт по проекту оформляется в DOCX объёмом пять-семь страниц. Формат: A4, поля 3 см слева, 1,5 см справа, 2 см сверху и снизу, Times New Roman 14 пт, интервал 1,5, отступ первой строки 1,25 см. Заголовки Heading 1 и Heading 2, таблицы Table Grid с шапкой по центру, название таблицы под таблицей.

К отчёту прилагается презентация из семи слайдов в PPTX или ODP. В отчёте есть раздел «Ограничения и следующий шаг», где перечислены непроверенные требования и риски, оставшиеся вне цикла. Тезисы доклада оформляются отдельным файлом на одну-две страницы.

## Что сдать

- тезисы доклада с фактами по семи частям;
- презентацию из семи слайдов;
- заполненный лист сверки чисел;
- протокол вопросов и ответов;
- лист самооценки с доказательствами;
- разбор замечаний с планом исправлений.

## Критерии оценки

Оценка выставляется по шкале от 1 до 5.

- **5**: доклад опирается на числа из отчёта, все показатели совпадают, вывод о готовности обоснован критериями, ответы содержат факт, причину и решение, ограничения названы честно, разбор замечаний содержит конкретные действия.
- **4**: работа выполнена полностью, но один показатель расходится между отчётом и слайдом или один ответ дан без ссылки на данные.
- **3**: доклад пересказывает отчёт, числа приведены без источников, вывод не связан с критериями, ограничения не названы.
- **2**: работа не выполнена.
- **1**: работа выполнена с использованием ИИ или скопирована полностью или частично, 1 балл без возможности исправления.
