## Цель работы

Собрать учебную базу SQLite для ИС «Склад+» и убедиться, что связи между таблицами работают. В базе будут площадки, товарные категории, товары и остатки. Первичные ключи не дадут появиться двум одинаковым записям, внешние ключи не дадут остатку сослаться на несуществующий товар или площадку.

Результат работы это три файла и отчёт. Файл `schema.sql` содержит команды создания таблиц, файл `seed.sql` содержит исходные данные, файл `sklad.db` это сама база. Отчёт показывает, что схема собрана, данные загружены, а ограничения действительно срабатывают.

## Краткие теоретические сведения

Таблица состоит из строк и колонок. Колонка задаёт имя и тип данных, строка хранит одно значение каждого типа. В SQLite типы гибкие, но ограничения `NOT NULL`, `UNIQUE` и `CHECK` работают строго: они не дают сохранить строку, которая нарушает правило.

Первичный ключ однозначно определяет строку. В таблице `warehouses` это `id`, в таблице `products` тоже `id`, а в таблице `stock` ключ составной: пара `warehouse_id` и `product_id`. Один товар на одной площадке хранится одной строкой, и повторная пара не появится.

Внешний ключ связывает колонку дочерней таблицы с первичным ключом родительской. В `products` колонка `category_id` ссылается на `categories.id`, в `stock` колонки `warehouse_id` и `product_id` ссылаются на `warehouses.id` и `products.id`. Связь защищает от двух ошибок: нельзя добавить товар в несуществующую категорию и нельзя удалить категорию, пока в ней есть товары.

В SQLite проверка внешних ключей по умолчанию выключена. Её включают командой `PRAGMA foreign_keys = ON` в каждом соединении. Это частая причина удивления: схема выглядит правильной, а база принимает остаток с площадкой номер 9. Команда действует на текущее соединение, поэтому её ставят в начало скрипта и в код, который открывает базу.

Схему можно прочитать из служебной таблицы `sqlite_master`, а ограничения через команды `PRAGMA table_info` и `PRAGMA foreign_key_list`. Эти команды не заменяют документацию, но показывают, что на самом деле лежит в файле.

Схема это договор между базой и программой. Пока договор соблюдается, код может считать, что у остатка всегда есть товар и площадка, а у товара всегда есть категория. Как только в базе появляется строка без родителя, все отчёты начинают либо терять данные, либо падать на соединении. Поэтому ограничения ставят не для красоты, а чтобы ошибка обнаруживалась в момент записи, а не через неделю в отчёте.

## Ход работы

### Шаг 1. Создайте папку и файл схемы

В папке проекта `sklad-plus` создайте подпапку `db` и перейдите в неё в терминале.

```text
mkdir db
cd db
```

Создайте файл `schema.sql`. Начните с команды включения внешних ключей и таблицы площадок. Эта таблица дана как образец: остальные таблицы вы напишете по её образцу и по требованиям следующих шагов.

```sql
PRAGMA foreign_keys = ON;

CREATE TABLE warehouses (
    id    INTEGER PRIMARY KEY,
    code  TEXT NOT NULL UNIQUE,
    title TEXT NOT NULL
);
```

Слово `INTEGER PRIMARY KEY` в SQLite делает колонку псевдонимом внутреннего номера строки. Значение можно не указывать при вставке, база назначит его сама. `UNIQUE` не даст создать две площадки с одинаковым кодом, `NOT NULL` не даст оставить название пустым.

### Шаг 2. Добавьте категории, товары и остатки

Допишите в `schema.sql` три таблицы. Требования к ним перечислены ниже, имена колонок и типы нужно выбрать самостоятельно, а связи оформить через `REFERENCES`.

| Таблица | Колонки | Ограничения |
|---|---|---|
| `categories` | `id`, `title` | `id` первичный ключ, `title` уникально и обязательно |
| `products` | `id`, `sku`, `title`, `category_id`, `price` | `id` первичный ключ, `sku` уникален и обязателен, `title` обязателен, `category_id` обязателен и ссылается на `categories.id`, `price` целое число копеек и не меньше нуля |
| `stock` | `warehouse_id`, `product_id`, `qty`, `cell` | составной первичный ключ из `warehouse_id` и `product_id`, `warehouse_id` ссылается на `warehouses.id`, `product_id` ссылается на `products.id`, `qty` не меньше нуля, `cell` обязательна |

Таблица `categories` связана с товарами через `products.category_id`. Это связь «один ко многим»: у категории много товаров, у товара ровно одна категория. Название категории хранится один раз, а не повторяется в каждой строке товара.

Схема повторяет четыре таблицы из лекции 13 и добавляет два поля проекта: `products.price` для стоимости и `stock.cell` для ячейки хранения. Цена хранится целым числом копеек, как советует лекция 13, поэтому 18990 рублей в данных записаны как 1899000. В базе из лекции 13 этих полей не было, потому что она показывала только связи. В рабочей базе склада они нужны каждый день: без цены не построить отчёт по стоимости, без ячейки кладовщик не найдёт товар.

Составной ключ в `stock` записывают отдельной строкой `PRIMARY KEY (warehouse_id, product_id)`, а не рядом с колонками. Внешние ключи можно объявить прямо в описании колонки через `REFERENCES` или отдельными строками `FOREIGN KEY`. Выберите один способ и держите его во всей схеме.

### Шаг 3. Выполните схему и проверьте список таблиц

Создайте рядом файл `init_db.py`. Он читает `schema.sql` и выполняет все команды за один раз.

```python
import sqlite3
from pathlib import Path

schema = Path("schema.sql").read_text(encoding="utf-8")
con = sqlite3.connect("sklad.db")
con.executescript(schema)
con.close()
print("База создана")
```

Запустите его командой `python init_db.py`. Затем проверьте, что в файле появились четыре таблицы. Создайте файл `check.py` с таким кодом.

```python
import sqlite3

con = sqlite3.connect("sklad.db")
for row in con.execute("SELECT name FROM sqlite_master WHERE type = 'table' ORDER BY name"):
    print(row[0])
con.close()
```

Ожидаемый вывод:

```text
categories
products
warehouses
stock
```

Если список пуст, `executescript` не нашёл файл или в схеме есть синтаксическая ошибка. Проверьте, что терминал открыт в папке `db` и что имя файла совпадает.

### Шаг 5. Прочитайте схему командами PRAGMA

Создайте файл `inspect.py` и выведите описание таблицы товаров и список внешних ключей таблицы остатков.

```python
import sqlite3

con = sqlite3.connect("sklad.db")
print("Колонки products:")
for row in con.execute("PRAGMA table_info(products)"):
    print(row)
print("Внешние ключи stock:")
for row in con.execute("PRAGMA foreign_key_list(stock)"):
    print(row)
con.close()
```

В строке `PRAGMA foreign_key_list` первые поля означают номер связи, номер строки, таблицу-родителя, колонку дочерней таблицы и колонку родительской. Сравните вывод с вашей схемой. Если вместо `products` и `warehouses` стоит `None` или список пуст, внешний ключ не объявлен.

Отдельно проверьте, что ограничение включено в текущем соединении:

```python
import sqlite3

con = sqlite3.connect("sklad.db")
con.execute("PRAGMA foreign_keys = ON")
print(con.execute("PRAGMA foreign_keys").fetchone())
con.close()
```

Вывод `(1,)` означает, что проверка включена. Без этой команды вывод будет `(0,)`, и внешние ключи перестанут защищать данные.

### Шаг 6. Проверьте данные запросом с соединением таблиц

Напишите запрос, который для каждой площадки и категории показывает число позиций и общее количество единиц товара. Колонки результата: название площадки, название категории, число строк остатка, сумма количества. Отсортируйте по площадке и категории.

Запрос соединяет четыре таблицы: `stock`, `products`, `categories` и `warehouses`. Соединение идёт по ключам, а не по названиям, потому что название может измениться, а ключ останется. Группировка нужна по двум колонкам, иначе строки разных площадок смешаются.

Проверьте результат по трём признакам. Число строк в результате должно быть не больше числа строк в `stock`. Сумма всех количеств в результате должна совпасть с `SELECT sum(qty) FROM stock`. В результате не должно быть площадок или категорий, которых нет в справочниках.

Если применить обычное соединение `JOIN`, строка остатка без товара или без площадки исчезнет из результата. Это удобно для отчёта, но опасно для проверки: потеря данных останется незамеченной. Для поиска нарушений используют `LEFT JOIN` и условие `WHERE p.id IS NULL` или `WHERE w.id IS NULL`. Такой запрос покажет остатки, у которых нет родителя. В правильной базе он возвращает ноль строк, и это ещё одно доказательство, что внешние ключи работают.

### Шаг 7. Нарушьте связь и убедитесь, что база её отклонит

Откройте базу и попробуйте добавить остаток с площадкой номер 9, которой нет в справочнике.

```python
import sqlite3

con = sqlite3.connect("sklad.db")
con.execute("PRAGMA foreign_keys = ON")
try:
    con.execute(
        "INSERT INTO stock (warehouse_id, product_id, qty, cell) VALUES (?, ?, ?, ?)",
        (9, 1, 5, "Z-01-01"),
    )
except sqlite3.IntegrityError as exc:
    print(type(exc).__name__, exc)
con.close()
```

Ожидаемое сообщение:

```text
IntegrityError FOREIGN KEY constraint failed
```

Теперь попробуйте удалить категорию, в которой есть товары:

```python
import sqlite3

con = sqlite3.connect("sklad.db")
con.execute("PRAGMA foreign_keys = ON")
try:
    con.execute("DELETE FROM categories WHERE id = 1")
except sqlite3.IntegrityError as exc:
    print(type(exc).__name__, exc)
con.close()
```

База снова откажет. Это не ошибка программы, а работа ограничения: сначала нужно перенести товары в другую категорию или удалить их, и только потом удалять категорию. Запишите в отчёт, какое поведение вы ожидали и что получили.

## Критерии оценки

Оценка выставляется по шкале от 1 до 5.
- **5**: созданы все четыре таблицы, первичные и внешние ключи объявлены верно, данные загружены в правильном порядке, запрос с соединением даёт осмысленный результат, обе ошибки воспроизведены и объяснены, отчёт полный.
- **4**: схема и данные верны, но один внешний ключ объявлен без проверки или в отчёте не объяснено одно из сообщений об ошибке.
- **3**: таблицы созданы частично, составной ключ или внешняя связь отсутствует, данные загружены с нарушением порядка, запрос не проверен.
- **2**: работа не выполнена.
- **1**: работа выполнена с использованием ИИ или скопирована полностью или частично, 1 балл без возможности исправления.
