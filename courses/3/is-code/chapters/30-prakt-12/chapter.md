## Цель работы

Собрать веб-сервис на ASP.NET Core, который читает и записывает позиции склада учебной системы «Склад+». Сервис получает список остатков, отдаёт одну позицию по коду, принимает новую запись и меняет количество. Хранилище подключается к контроллеру через внедрение зависимостей, а результат проверяется запросами в Postman.

Результат работы это запущенный сервис, коллекция запросов с проверками и отчёт. Контроллер не должен содержать данные: он принимает запрос, вызывает хранилище и возвращает ответ с правильным кодом состояния.

## Краткие теоретические сведения

Контроллер это класс, который принимает запросы определённого вида. Атрибут `[ApiController]` включает автоматическую проверку модели и ответы в формате ProblemDetails. Атрибут `[Route("api/stock")]` задаёт общий префикс, а атрибуты `[HttpGet]`, `[HttpPost]` и `[HttpPut]` связывают метод с HTTP-методом и шаблоном адреса.

Действие контроллера возвращает `ActionResult<T>`: либо данные с кодом 200, либо результат с другим кодом. Для чтения одной записи удобен код 404, для создания 201 с заголовком `Location`, для изменения без тела 204, для неверных данных 400. Клиент различает ситуации по коду, поэтому одинаковый ответ 200 на все случаи делает API неудобным.

Хранилище скрывается за интерфейсом. Контроллер зависит от интерфейса, а конкретный класс регистрируется в `Program.cs`. В этой работе хранилище хранит данные в памяти, поэтому переживает запросы, но исчезает при перезапуске. Замена на SQLite позже не потребует менять контроллер: достаточно зарегистрировать другую реализацию.

Postman хранит запросы в коллекции. Коллекция позволяет повторить проверку на другой машине и служит доказательством работы. Тесты Postman проверяют код состояния и структуру ответа, а не только то, что запрос выполнился.

Значения в действие приходят из разных источников. Номер записи берётся из маршрута, фильтр из строки запроса, объект из тела. Атрибут `[FromQuery]` указывает на строку запроса, `[FromBody]` на тело, а для простых параметров из маршрута отдельный атрибут не нужен. Если источник перепутан, параметр окажется пустым, и действие вернёт неверный результат без ошибки сборки.

Проверка модели дополняет коды состояния. Атрибут `[ApiController]` сам возвращает 400, если тело не удалось разобрать или обязательное поле отсутствует. Ручная проверка нужна для правил, которые не выражаются типом: количество не меньше нуля, площадка входит в список допустимых, ячейка соответствует формату.

## Ход работы

### Шаг 1. Создайте проект Web API

Шаблон создаёт проект с контроллером погоды. Команда выполняется в папке, где будет лежать проект:

```powershell
dotnet new webapi -n SkladPlus.Api --use-controllers
```

Ключ `--use-controllers` выбирает шаблон с контроллерами, а не с минимальными маршрутами. После создания перейдите в папку `.../SkladPlus.Api` и запустите проект:

```powershell
dotnet run
```

В строке запуска появится адрес вида `http://localhost:<порт>`. Откройте в браузере `http://localhost:<порт>/WeatherForecast` и убедитесь, что шаблон отвечает списком записей. Порт у каждой машины свой, его берут из строки запуска.

Изучите файлы проекта: `Program.cs` собирает приложение, папка `Controllers` содержит контроллер, `appsettings.json` хранит настройки, `Properties/launchSettings.json` задаёт адрес и среду. Контроллер погоды и класс `WeatherForecast` в этой работе не нужны, их удаляют после проверки запуска.

### Шаг 2. Опишите модель и хранилище

Модель позиции содержит код, название, категорию, площадку, ячейку и количество. Создайте папку `Models` и файл `StockItem.cs` с таким шаблоном:

```csharp
namespace SkladPlus.Api.Models;

public class StockItem
{
    public int Id { get; set; }
    public string Item { get; set; } = "";
    public string Category { get; set; } = "";
    public string Site { get; set; } = "";
    public string Cell { get; set; } = "";
    public int Quantity { get; set; }
}
```

Ниже сырые данные для наполнения хранилища. Это пять позиций из 4800, которые есть на складе. Категории взяты из двенадцати товарных категорий, площадки из четырёх складов.

| Код | Товар | Категория | Площадка | Ячейка | Количество |
|---|---|---|---|---|---|
| 1 | Кабель UTP cat5e | Кабель | Москва | A-01-03 | 120 |
| 2 | Коробка 400x300x200 | Упаковка | Тверь | B-02-11 | 80 |
| 3 | Стрейч-плёнка 500 мм | Упаковка | Тула | C-01-07 | 240 |
| 4 | Паллета EUR | Тара | Калуга | D-03-02 | 60 |
| 5 | Маркер перманентный | Канцелярия | Москва | A-04-05 | 35 |

Создайте папку `Storage` и опишите интерфейс хранилища:

```csharp
using SkladPlus.Api.Models;

namespace SkladPlus.Api.Storage;

public interface IStockRepository
{
    IReadOnlyList<StockItem> GetAll(string? site);
    StockItem? Find(int id);
    StockItem Add(StockItem item);
    bool UpdateQuantity(int id, int quantity);
}
```

Реализацию `InMemoryStockRepository` напишите сами. Внутри нужен список `List<StockItem>`, заполненный строками из таблицы, счётчик следующего кода и объект для блокировки. Метод `GetAll` показан как образец:

```csharp
public IReadOnlyList<StockItem> GetAll(string? site)
{
    lock (_lock)
    {
        return _items
            .Where(i => string.IsNullOrWhiteSpace(site) || i.Site == site)
            .ToList();
    }
}
```

Остальные методы сделайте по образцу. `Find` возвращает позицию или `null`. `Add` присваивает новый код, добавляет запись и возвращает её. `UpdateQuantity` меняет количество и сообщает, нашлась ли запись. Блокировка нужна потому, что несколько запросов могут прийти одновременно.

### Шаг 3. Зарегистрируйте хранилище

Откройте `Program.cs` и добавьте регистрацию после `AddControllers`. Образец показывает регистрацию простого сервиса:

```csharp
builder.Services.AddSingleton(TimeProvider.System);
```

Для хранилища выберите время жизни самостоятельно и объясните выбор в отчёте. Подсказка: данные в памяти должны сохраняться между запросами, но при переходе на SQLite время жизни изменится. После регистрации запустите проект и убедитесь, что он собирается без предупреждений.

Сравните варианты. При transient каждый запрос получает новый пустой список, и созданная позиция исчезнет до следующего чтения. При singleton список проживёт до остановки приложения, но такое же время жизни получит подключение к базе при переходе на SQLite. При scoped экземпляр живёт один запрос. Выбор зависит от того, что именно хранит сервис и что должно пережить следующий запрос.

### Шаг 4. Создайте контроллер чтения

Удалите контроллер погоды и создайте `Controllers/StockController.cs`. Начало класса:

```csharp
using Microsoft.AspNetCore.Mvc;
using SkladPlus.Api.Models;
using SkladPlus.Api.Storage;

namespace SkladPlus.Api.Controllers;

[ApiController]
[Route("api/stock")]
public class StockController : ControllerBase
{
    private readonly IStockRepository _repository;

    public StockController(IStockRepository repository)
    {
        _repository = repository;
    }
}
```

Действие `GetAll` принимает необязательный фильтр по площадке и возвращает список:

```csharp
[HttpGet]
public ActionResult<IEnumerable<StockItem>> GetAll([FromQuery] string? site)
{
    var items = _repository.GetAll(site);
    return Ok(items);
}
```

Добавьте действие `GetById` с маршрутом `[HttpGet("{id:int}")]`. Если позиция не найдена, верните `NotFound()`, иначе `Ok(item)`. Ограничение `:int` в шаблоне не пропустит строку вместо числа. Проверьте оба случая в браузере: `api/stock/3` и `api/stock/999`.

### Шаг 5. Добавьте запись и изменение

Создание принимает объект из тела запроса. Метод `CreatedAtAction` возвращает код 201 и заголовок `Location` с адресом новой записи:

```csharp
[HttpPost]
public ActionResult<StockItem> Create(StockItem item)
{
    var created = _repository.Add(item);
    return CreatedAtAction(nameof(GetById), new { id = created.Id }, created);
}
```

Код 200 на создание тоже вернул бы данные, но клиент не понял бы, что появилась новая запись, и не получил бы её адрес. Код 201 вместе с `Location` сообщает и факт создания, и место, где запись можно прочитать. Этим API отличается от страницы, которая просто перерисовывает список.

Добавьте проверку: количество не может быть отрицательным. При ошибке верните `BadRequest` с понятным сообщением или добавьте ошибку в `ModelState`. Затем сделайте изменение количества отдельным действием `[HttpPut("{id:int}/quantity")]`. Оно принимает новое число, возвращает `NoContent()` при успехе и `NotFound()` для отсутствующей записи.

Проверьте чтение в браузере, а запись и изменение на следующем шаге в Postman. Если сервис отвечает 500, прочитайте текст ошибки в консоли запуска: чаще всего причина в незарегистрированном хранилище или в неверном имени свойства JSON.

### Шаг 6. Проверьте сервис в Postman

Создайте коллекцию `SkladPlus API` и переменную коллекции `baseUrl` со значением `http://localhost:<порт>`. В каждом запросе используйте `{{baseUrl}}`, чтобы коллекция работала на другой машине после смены одной переменной.

Ниже журнал запросов. Первая строка дана как образец, остальные заполните сами по своим маршрутам.

| Метод | Адрес | Тело | Ожидаемый код | Что проверить |
|---|---|---|---|---|
| GET | `{{baseUrl}}/api/stock` | нет | 200 | массив из пяти позиций |
|  |  |  |  |  |
|  |  |  |  |  |
|  |  |  |  |  |
|  |  |  |  |  |

В каждом запросе добавьте тесты на вкладке Tests. Образец проверяет код и тип ответа:

```javascript
pm.test("Код 200", function () {
    pm.response.to.have.status(200);
});

pm.test("Ответ содержит массив", function () {
    pm.expect(pm.response.json()).to.be.an("array");
});
```

Для создания записи проверьте код 201 и наличие заголовка `Location`. Для отсутствующей позиции проверьте 404. Для отрицательного количества проверьте 400 и наличие названия поля в ответе. Сохраните коллекцию в файл `SkladPlus.postman_collection.json` через меню Export.

Переменная коллекции избавляет от правки каждого запроса. Если адрес записан прямо в запросах, при смене порта придётся менять шесть строк и легко пропустить одну. С переменной достаточно изменить одно значение. Коллекцию можно прогнать целиком через Collection Runner: он выполнит запросы по порядку и покажет, какие тесты прошли.

Сделайте снимки экрана для четырёх ответов: список 200, создание 201, отсутствие 404 и неверные данные 400. На снимке должны быть видны метод, адрес, код состояния и тело ответа.

### Шаг 7. Соберите отчёт

Опишите в отчёте цель работы, версии .NET и Postman, структуру проекта и назначение каждого файла. Приведите таблицу маршрутов с методами, адресами, кодами ответов и краткими пояснениями. Вставьте журнал запросов и снимки экрана. В выводах объясните, почему хранилище зарегистрировано с выбранным временем жизни и что изменится при переходе на SQLite.

## Критерии оценки

Оценка выставляется по шкале от 1 до 5.
- **5**: работают все четыре маршрута, коды состояния соответствуют ситуации, хранилище подключено через внедрение зависимостей, коллекция содержит тесты на 200, 201, 404 и 400, отчёт оформлен по требованиям и объяснение времени жизни обосновано.
- **4**: маршруты работают, но один код состояния неверен или в коллекции нет теста для одного случая; отчёт полный, объяснение времени жизни краткое.
- **3**: работают только чтение и создание, изменение или обработка ошибок отсутствует, коллекция содержит запросы без тестов, отчёт неполный.
- **2**: работа не выполнена или сервис не запускается.
- **1**: работа выполнена с использованием ИИ или скопирована полностью или частично, 1 балл без возможности исправления.
