## Цель работы

Настроить два рабочих места для проекта `sklad-plus` и убедиться, что оба запускают код и останавливаются на точках останова. В VS Code настраиваются расширение Python, интерпретатор из виртуального окружения и параметры рабочей папки. В Visual Studio 2022 создаётся консольный проект C#, проверяются отладка и сборка Release.

Результат работы это заполненный протокол настроек и два подтверждённых запуска: Python-скрипт останавливается на точке останова, приложение C# запускается из Visual Studio и из готовой сборки. Протокол должен позволить повторить настройку на другом компьютере.

## Краткие теоретические сведения

Рабочее окружение это набор инструментов, которые превращают текст в работающую программу. Для Python нужны интерпретатор, редактор и библиотеки проекта. Для C# нужны SDK, среда сборки и среда исполнения. Если хотя бы один элемент отсутствует или выбран неверно, код выглядит правильным, но не запускается.

Интерпретатор Python это конкретный файл `python.exe`. На компьютере их может быть несколько: системный, из поставки Microsoft Store, из отдельной установки. VS Code не угадывает, какой из них использовать, поэтому интерпретатор выбирают явно. Выбранный путь сохраняется в настройках рабочей папки.

Команда `python` в терминале тоже не указывает на конкретный файл напрямую. Система ищет его по списку каталогов в переменной `PATH` и берёт первый найденный. Поэтому на двух компьютерах одна и та же команда может запускать разные версии, а внутри VS Code с выбранным окружением версия отличается от терминала. Протокол настроек фиксирует не только версию, но и путь, чтобы расхождение было видно сразу.

Виртуальное окружение это отдельная папка с копией интерпретатора и своими библиотеками. Проект получает собственный набор пакетов, который не смешивается с системным. Окружение создают командой `python -m venv .venv`, а подключают выбором файла `.../.venv/Scripts/python.exe`.

Настройки рабочей папки хранятся в каталоге `.vscode`. Файл `settings.json` задаёт параметры редактора для этого проекта, файл `launch.json` описывает запуск и отладку. Эти файлы полезно хранить в Git: тогда настройки переходят на другой компьютер вместе с кодом.

Настройки бывают двух уровней. Пользовательские действуют во всех проектах, которые открывает человек, настройки папки только в этом проекте. В аудитории за одним компьютером работают несколько человек, поэтому личные настройки могут не совпадать с ожиданиями проекта. Настройки папки решают эту проблему: проект несёт свои параметры с собой, а редактор применяет их при открытии.

Отладчик останавливает программу на точке останова и показывает состояние: значения переменных, путь вызовов, текущую строку. В Python отладчик запускается через панель Run and Debug, в Visual Studio через F5. Без отладчика ошибку ищут печатью промежуточных значений, с ним видят причину сразу.

Сборка Release отличается от Debug. Debug хранит отладочные символы и не оптимизирует код. Release оптимизирует код и убирает лишние сведения, поэтому её используют для передачи. Файлы двух конфигураций лежат в разных каталогах, и путать их при запуске нельзя.

## Ход работы

### Шаг 1. Проверьте версии инструментов

Начните с проверки того, что установлено. Команда `python --version` печатает версию интерпретатора, который первым находится в пути поиска. Разберите её на примере: если в ответ пришло `Python 3.13.14`, значит, в терминале доступен Python 3.13.

```powershell
python --version
dotnet --list-sdks
git --version
```

Команда `dotnet --list-sdks` показывает установленные пакеты SDK и их версии. Для проекта нужна версия 10. Команда `git --version` подтверждает, что Git доступен из терминала.

### Шаг 2. Создайте виртуальное окружение

Окружение создают в корне проекта, рядом с каталогами `src`, `tests` и `docs`. Сначала перейдите в корень проекта, затем выполните команду.

```powershell
cd .../sklad-plus
python -m venv .venv
```

Ключ `-m` запускает модуль `venv`, а `.venv` задаёт имя каталога. После выполнения в проекте появляется папка с интерпретатором и служебными файлами. Каталог `.venv` уже добавлен в `.gitignore` на предыдущей практике, поэтому в репозиторий он не попадёт.

Откройте папку проекта в VS Code: `File` → `Open Folder`. Затем вызовите палитру команд сочетанием Ctrl+Shift+P и выберите `Python: Select Interpreter`. В списке найдите путь, который заканчивается на `.../.venv/Scripts/python.exe`, и выберите его.

Откройте новый терминал в VS Code. В начале строки приглашения должно появиться `(.venv)`: это признак того, что окружение активировано. Проверьте, что команда `python --version` в этом терминале показывает ту же версию, а команда `python -c "import sys; print(sys.prefix)"` печатает путь к папке `.venv`.

Запишите в протокол путь к выбранному интерпретатору и способ, которым убедились в активации окружения.

### Шаг 3. Настройте рабочую папку VS Code

Расширение Python устанавливается из панели Extensions по имени `Python`. Вместе с ним ставится Pylance, который проверяет код и подсказывает типы. После установки перезапустите VS Code, если редактор попросит.

Настройки проекта хранятся в файле `.../sklad-plus/.vscode/settings.json`. Создайте каталог `.vscode` и файл с параметрами:

```json
{
  "python.defaultInterpreterPath": "${workspaceFolder}/.venv/Scripts/python.exe",
  "python.analysis.typeCheckingMode": "basic",
  "editor.rulers": [88],
  "files.trimTrailingWhitespace": true,
  "editor.formatOnSave": true
}
```

Параметр `defaultInterpreterPath` указывает интерпретатор по умолчанию для этой рабочей папки. `typeCheckingMode` включает базовую проверку типов. `editor.rulers` рисует вертикальную линию на 88 символах, чтобы длинные строки были видны. `files.trimTrailingWhitespace` удаляет пробелы в конце строк при сохранении. `editor.formatOnSave` запускает форматирование, если в окружении установлен форматтер.

Проверьте настройки на практике. Откройте файл `.../sklad-plus/src/sklad/service/storage.py`, добавьте лишние пробелы в конце строки и сохраните файл. Пробелы должны исчезнуть. Затем допустите намеренную ошибку в имени функции и посмотрите панель `Problems`: Pylance должен подчеркнуть неизвестное имя до запуска.

Добавьте в `settings.json` ещё два параметра на выбор: длину табуляции, отображение пробелов или исключение папки из поиска. Объясните в протоколе, зачем нужен каждый параметр.

### Шаг 4. Проверьте отладчик Python

Ниже скрипт, который считает паллеты для отгрузки. Он запускается и печатает результат, но результат неверный: груз занимает больше одной паллеты, а программа показывает одну.

```python
"""Расчёт паллет для отгрузки."""

import math

PALLET_VOLUME_M3 = 1.44


def box_volume(length_cm, width_cm, height_cm):
    return length_cm * width_cm * height_cm / 1_000_000


def pallets_needed(total_volume_m3):
    return round(total_volume_m3 / PALLET_VOLUME_M3)


def main():
    volume = box_volume(40, 30, 25) * 24
    volume += box_volume(60, 40, 30) * 12
    volume += box_volume(30, 20, 20) * 40
    print(f"Объём: {round(volume, 3)} м3")
    print(f"Паллет: {pallets_needed(volume)}")


if __name__ == "__main__":
    main()
```

Сохраните скрипт как `.../sklad-plus/docs/debug_pallets.py`. Запустите его обычным способом и запишите вывод: объём должен быть 2,064 кубического метра, а паллет программа покажет меньше, чем нужно.

Поставьте точку останова на строку с вызовом `pallets_needed`. Откройте панель Run and Debug, выберите `Python File` и запустите отладку. Когда выполнение остановится, посмотрите в разделе `Variables` значение `volume` и результат деления `volume / PALLET_VOLUME_M3`. Добавьте выражение в `Watch` и выполните шаг с заходом в функцию.

Найдите строку, из-за которой результат занижен. В отчёте объясните, что показывает отладчик и почему выбранная функция округления не подходит для паллет. Исправьте строку и проверьте, что вывод изменился.

### Шаг 5. Создайте проект C# в Visual Studio 2022

Если решение `sklad-plus` уже создано по материалам лекции, откройте его файл. Если решения ещё нет, создайте проект: `File` → `New` → `Project`, шаблон `Console App`, язык C#. Укажите имя `SkladPlus.App`, расположение `.../sklad-plus/src` и имя решения `sklad-plus`. Целевую платформу выберите `net10.0`.

После создания откроется файл `Program.cs`. Замените его содержимое на две строки:

```csharp
Console.WriteLine("Склад+ : проверка среды");
Console.WriteLine("Позиций на складе: 4800");
```

Запустите проект сочетанием Ctrl+F5 и убедитесь, что в консоли появились обе строки. Окно консоли останется открытым до нажатия клавиши, это нормально для запуска без отладки.

Изучите окно `Solution Explorer`. В нём видны решение `sklad-plus`, проект `SkladPlus.App`, узел `Dependencies` и файл `Program.cs`. Разверните проект и найдите каталоги `bin` и `obj`: они созданы автоматически и не предназначены для правки.

### Шаг 6. Проверьте отладку и сборку Release

Поставьте точку останова на вторую строку вывода и запустите проект клавишей F5. Программа остановится до выполнения строки. Откройте окно `Call Stack` и найдите метод, в котором находится выполнение. Выполните шаг с обходом, затем шаг с заходом в `Console.WriteLine`. Если отладчик не заходит в библиотеку, причина в настройке `Just My Code`: она скрывает чужой код. Завершите отладку.

Теперь соберите Release. В верхней панели выберите конфигурацию `Release` вместо `Debug` и выполните `Build` → `Build Solution`. Найдите в `Solution Explorer` путь к сборке: он заканчивается на `bin/Release/net10.0/`. Запустите файл `SkladPlus.App.exe` из проводника и убедитесь, что он работает без Visual Studio.

Запишите в протокол два пути, `bin/Debug/net10.0` и `bin/Release/net10.0`, и объясните, чем отличаются файлы в них. Проверьте, что при запуске из терминала команда `dotnet .../bin/Release/net10.0/SkladPlus.App.dll` даёт тот же вывод.

## Критерии оценки

Оценка выставляется по шкале от 1 до 5.

- **5**: оба инструмента настроены, интерпретатор выбран из `.venv`, настройки сохранены в `.vscode`, точка останова в Python и в C# работает, ошибка найдена через отладчик и объяснена, Release собран и запущен отдельно, протокол позволяет повторить настройку.
- **4**: работа выполнена полностью, но интерпретатор выбран системный, либо в протоколе нет одной проверки, либо снимок не показывает нужный элемент, либо объяснение ошибки сводится к «так было в коде».
- **3**: запуск работает, но отладка не проверена, настройки не сохранены в проекте, Release не собран, протокол содержит только список версий.
- **2**: работа не выполнена или хотя бы один инструмент не запускается.
- **1**: работа выполнена с использованием ИИ или скопирована полностью или частично, 1 балл без возможности исправления.
