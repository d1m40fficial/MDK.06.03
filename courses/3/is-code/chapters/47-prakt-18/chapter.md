## Цель работы

Подготовить `sklad-plus` к запуску вне машины разработчика. Вы вынесете параметры в файл настроек, соберёте артефакт, установите его на учебную машину, запустите сервис и проверите здоровье и данные. Отдельный результат работы это инструкция запуска, по которой другой человек повторит те же шаги без ваших объяснений.

Критерий готовности: приложение открылось на другой машине по инструкции и показало 4800 позиций. Поэтому результаты фиксируются командами и ответами, а не пересказом.

## Оборудование и программное обеспечение

- Персональный компьютер с Python 3.11 или новее, VS Code и Git.
- Виртуальная машина VirtualBox с учебным образом Linux.
- Виртуальное окружение Python на учебной машине.
- Пакет `flask`, установленный в окружение проекта.
- Браузер или `curl` для проверки HTTP-ответов.
- Текстовый редактор для инструкции запуска и отчёта.

Права администратора на основной машине не нужны. Сеть виртуальной машины настраивается через NAT, а доступ к сервису проверяется пробросом порта.

## Краткие теоретические сведения

Настройка это значение, которое отличает один запуск от другого: путь к базе, порт, уровень журнала, секрет. Настройки читают из значений по умолчанию, файла и переменных окружения. Переменная окружения важнее файла, файл важнее значения по умолчанию. Секреты хранят вне репозитория, а в репозитории держат только пример `.env.example` с условными значениями.

Артефакт это собранный результат с версией. Для Python-проекта это колесо `.whl`, для C# папка `publish` после `dotnet publish`. Артефакт собирают один раз и переносят на машины без повторной сборки. Исходники, база, журналы и секреты в артефакт не входят: они лежат отдельно и переживают замену версии.

Окружение разработки и учебная машина различаются пользователями, данными, правами и адресами. Совпадать должны версия Python, набор зависимостей, структура каталогов и способ запуска. Если на учебной машине нет пакета, который случайно стоял на машине разработчика, приложение упадёт при импорте. Поэтому зависимости фиксируют в файле проекта, а не устанавливают вручную по памяти.

Проверка здоровья это запрос к служебному адресу, который сообщает состояние сервиса и базы. Код 200 и поле `positions` со значением 4800 означают, что приложение видит полный склад. Код 503 означает, что база недоступна.

Инструкция запуска это документ для человека, который не присутствовал при настройке. В ней есть предусловия, команды, ожидаемый результат каждого шага, проверка, остановка и действия при ошибке. Инструкцию проверяют на чистом окружении: если для запуска нужны устные пояснения, документ неполон.

| Понятие | Что означает в этой работе |
|---|---|
| Настройка | значение, которое меняется между машинами |
| Артефакт | колесо `sklad_plus-1.0.0-py3-none-any.whl` |
| Учебная машина | виртуальная машина с Linux и NAT |
| Проверка здоровья | запрос `/api/health` с кодом 200 |
| Инструкция запуска | документ с шагами и ожидаемым результатом |

## Ход работы

### Шаг 1. Найдите настройки в коде

Перед вами упрощённое приложение `sklad-plus` в файле `src/sklad_plus/api.py`. Оно уже работает, но все параметры записаны прямо в файле.

```python
import sqlite3
from flask import Flask, jsonify, request

app = Flask(__name__)
DB_PATH = "data/sklad.db"
API_PORT = 8000
SECRET_KEY = "dev-secret"

def count_positions():
    with sqlite3.connect(DB_PATH) as conn:
        return conn.execute("SELECT COUNT(*) FROM positions").fetchone()[0]

@app.get("/api/health")
def health():
    return jsonify({"status": "ok", "db": DB_PATH, "positions": count_positions()})

@app.get("/api/stock")
def stock():
    limit = request.args.get("limit", default=3, type=int)
    with sqlite3.connect(DB_PATH) as conn:
        rows = conn.execute(
            "SELECT sku, qty FROM positions ORDER BY id LIMIT ?", (limit,)
        ).fetchall()
    return jsonify({"total": count_positions(), "items": [{"sku": s, "qty": q} for s, q in rows]})

if __name__ == "__main__":
    app.run(host="127.0.0.1", port=API_PORT)
```

Создайте таблицу `positions` и заполните её 4800 строками. Скрипт ниже создаёт базу и не дублирует данные при повторном запуске.

```python
import sqlite3
from pathlib import Path

Path("data").mkdir(exist_ok=True)
with sqlite3.connect("data/sklad.db") as conn:
    conn.execute("CREATE TABLE IF NOT EXISTS positions (id INTEGER PRIMARY KEY, sku TEXT, qty INTEGER)")
    count = conn.execute("SELECT COUNT(*) FROM positions").fetchone()[0]
    if count == 0:
        conn.executemany(
            "INSERT INTO positions (sku, qty) VALUES (?, ?)",
            [(f"SKU-{i:05d}", 10 + i % 40) for i in range(1, 4801)],
        )
    conn.commit()
    total = conn.execute("SELECT COUNT(*) FROM positions").fetchone()[0]
print("positions:", total)
```

Запустите скрипт и убедитесь, что он печатает `positions: 4800`.

Заполните таблицу: какой параметр где используется и что должно измениться на учебной машине. Первая строка дана как образец.

| Параметр | Где используется | Значение сейчас | Значение на учебной машине |
|---|---|---|---|
| `DB_PATH` | подключение к SQLite | `data/sklad.db` | `data/sklad.db` в каталоге приложения |
| `API_PORT` | запуск Flask | 8000 | 8080 |
| `SECRET_KEY` | подпись данных | `dev-secret` | собственное значение |

### Шаг 2. Вынесите настройки в модуль

## Требования к отчёту

Отчёт оформляется в Word или LibreOffice Writer на 3-5 страниц. В нём должны быть титульная часть с названием работы, цель, исходные данные, ход выполнения, результаты проверок и вывод. Таблицы оформляются с заголовками и пояснением под каждой таблицей.

Инструкцию запуска приложите отдельным разделом или файлом. Она должна быть самодостаточной: человек, который не видел вашу машину, повторяет шаги и получает тот же ответ.

## Что сдать

- файл `config.py` с настройками, которые читаются из окружения;
- файл `.env.example` и подтверждение, что `.env` не попадает в Git;
- колесо `dist/sklad_plus-1.0.0-py3-none-any.whl`;
- инструкцию запуска с командами, ожидаемыми результатами и разделом ошибок;
- отчёт с таблицами настроек, проверок и расхождений;
- снимок ответа `/api/health` с кодом 200 и числом позиций.

## Критерии оценки

Оценка выставляется по шкале от 1 до 5.

- **5**: настройки вынесены полностью, секрет не попадает в репозиторий, артефакт собран и установлен на учебной машине, сервис запускается по инструкции, health check возвращает 200 и 4800 позиций, инструкция проверена на чистом окружении, расхождения исправлены, отчёт полный.
- **4**: работа выполнена, но одна настройка осталась в коде или инструкция проверена только автором; проверки здоровья и данных пройдены, отчёт содержит все таблицы.
- **3**: артефакт собран, но запуск зависит от устных пояснений; health check выполнен, настройки вынесены частично; в инструкции нет раздела ошибок или отката.
- **2**: работа не выполнена или сервис не запускается на учебной машине.
