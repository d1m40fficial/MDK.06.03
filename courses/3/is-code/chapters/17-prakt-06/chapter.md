## Цель работы

Складская система должна помнить не только текущий остаток, но и то, как он получился. Кладовщик принял 48 упаковок перчаток, менеджер отгрузил 12 рулонов плёнки, товар переместили между площадками. Если эти события хранить только в базе, при сбое или спорной накладной восстановить картину трудно. Текстовый журнал даёт простую и независимую копию событий: его можно открыть блокнотом, передать другой программе и сравнить с базой.

Цель работы: написать на Python модуль, который дописывает операции в текстовый файл, читает журнал построчно, пропускает пустые строки, сообщает о битых записях и считает сводку по типам операций. Журнал ведётся для ИС «Склад+» ООО «Северный склад»: четыре площадки, 4800 позиций и 120 сотрудников.

Результат работы это программа `src/journal.py`, файл `data/operations.log` с записями и короткий отчёт с выводом программы. Отдельно проверяются два отказа: отсутствие файла и строка, которую невозможно разобрать.

## Краткие теоретические сведения

**Режим открытия** задаёт, что программа собирается делать с файлом. Режим `"r"` открывает файл только на чтение и выбрасывает `FileNotFoundError`, если файла нет. Режим `"w"` создаёт файл заново и стирает прежнее содержимое. Режим `"a"` открывает файл для добавления в конец и создаёт его, если файла ещё нет. Режим `"x"` создаёт новый файл и падает, если файл уже существует. Буква `"b"` добавляет двоичный режим, а `"+"` разрешает и чтение, и запись.

**Кодировка** определяет, как байты превращаются в символы. Для журнала с русскими названиями площадок используют UTF-8. Если открыть файл в другой кодировке, программа либо выбросит `UnicodeDecodeError`, либо прочитает кириллицу неверными символами. Кодировку указывают явно при каждом открытии: полагаться на настройки Windows нельзя, на другом компьютере они другие.

**Контекстный менеджер** `with open(...) as file` закрывает файл даже при исключении. Это важно для записи: пока файл не закрыт, часть данных может оставаться в буфере и не попасть на диск. Явный вызов `close()` тоже работает, но его легко пропустить в ветке с ошибкой.

**Журнал операций** это файл, в котором одна строка описывает одно событие. В учебном проекте поля разделены вертикальной чертой: время, тип операции, артикул, площадка и количество. Вертикальная черта выбрана потому, что она не встречается в названиях площадок и артикулах. Если разделитель может появиться внутри значения, формат усложняют: заключают поле в кавычки или переходят на JSON Lines.

**Построчное чтение** позволяет обрабатывать файл, который больше оперативной памяти. Цикл `for line in file` читает одну строку за раз. Метод `read()` загружает весь файл целиком и для журнала за несколько лет может оказаться слишком дорогим.

**Ошибки разбора** делятся на три вида. Строка может быть пустой, и её пропускают. В строке может оказаться неверное число полей, и её пропускают с сообщением. Поле количества может не преобразоваться в целое число, и строку тоже пропускают. Хороший журнал не останавливает импорт из-за одной плохой записи, но и не скрывает её: номер строки и причина попадают в отчёт.

**Дописывание** отличается от перезаписи. Режим `"a"` не трогает прежние записи и добавляет новую в конец. Это свойство важно для аудита: журнал нельзя незаметно переписать целиком. Повторный запуск программы с тем же событием создаст дубль, поэтому уникальность операции обеспечивает отдельное правило, например номер документа.

## Ход работы

### Шаг 1. Создайте файл журнала

Создайте в проекте каталог `.../sklad-plus/data` и файл `operations.log`. В файле уже есть записи за 5 октября, включая одну пустую строку и две повреждённые записи. Они нужны, чтобы проверить устойчивость программы.

```text
2026-10-05T09:14|RECEIPT|SKU-1042|Москва|48
2026-10-05T09:31|SHIPMENT|SKU-2210|Тверь|12

2026-10-05T10:02|RECEIPT|SKU-0871|Тула|96
2026-10-05T10:40|MOVE|SKU-1042|Калуга|6
2026-10-05T11:05|RECEIPT|SKU-2210|Москва|сорок
2026-10-05T11:20|SHIPMENT|SKU-0871|Тула
```

Сохраните файл в кодировке UTF-8 без BOM. Проверьте, что в конце последней строки есть перевод строки: иначе следующая запись приклеится к последней и получится строка с шестью полями.

Поля журнала описаны в таблице. Заполнять её не нужно, это справочник формата.

| Поле | Что означает | Пример |
|---|---|---|
| Время | дата и время операции в формате ISO 8601 | `2026-10-05T09:14` |
| Тип | `RECEIPT`, `SHIPMENT` или `MOVE` | `RECEIPT` |
| Артикул | идентификатор товара, всегда строка | `SKU-1042` |
| Площадка | город, где выполнена операция | `Москва` |
| Количество | целое число единиц товара | `48` |

### Шаг 2. Прочитайте журнал построчно

Сначала разберите маленький пример. Он открывает файл, перебирает строки и печатает номер и содержимое.

```python
from pathlib import Path

path = Path(".../sklad-plus/data/operations.log")

with path.open(encoding="utf-8") as file:
    for number, line in enumerate(file, 1):
        print(number, repr(line))
```

Фрагмент вывода:

```text
1 '2026-10-05T09:14|RECEIPT|SKU-1042|Москва|48\n'
2 '2026-10-05T09:31|SHIPMENT|SKU-2210|Тверь|12\n'
3 '\n'
```

`enumerate(file, 1)` нумерует строки с единицы, как в текстовом редакторе. `repr` показывает служебные символы: перевод строки `\n` виден, а глазами его нет. Третья строка пустая, и её нужно пропустить.

Теперь напишите функцию `read_operations(path)`, которая возвращает список словарей. Требования к функции:

- если файла нет, вернуть пустой список, а не падать;
- пустые строки пропускать без сообщения;
- строку с неверным числом полей пропускать с сообщением и номером строки;
- количество преобразовывать в `int`, при ошибке пропускать строку с сообщением;
- остальные поля сохранять строками.

Для проверки длины списка используйте `len(parts)`, для преобразования `int(parts[4])`. Обработку ошибки преобразования оформите через `try` и `except ValueError`.

### Шаг 3. Разберите строку на поля

Разбор одной строки удобно проверить отдельно, до чтения файла.

```python
line = "2026-10-05T09:14|RECEIPT|SKU-1042|Москва|48"
parts = line.strip().split("|")
print(len(parts), parts[2], parts[4])
```

```text
5 SKU-1042 48
```

Метод `strip()` убирает пробелы и перевод строки по краям. Без него последнее поле будет содержать `\n`, и `int("48\n")` всё равно сработает, но при выводе и сравнении строк появится лишний символ. Метод `split("|")` режет строку по разделителю и возвращает список.

Добавьте в функцию разбор и проверку. Ниже каркас, в котором пропущены строки обработки ошибок. Допишите их самостоятельно.

```python
def read_operations(path):
    if not path.exists():
        return []

    operations = []
    with path.open(encoding="utf-8") as file:
        for number, line in enumerate(file, 1):
            line = line.strip()
            if not line:
                continue

            parts = line.split("|")
            if len(parts) != 5:
                # сообщение о неверном числе полей
                continue

            try:
                qty = int(parts[4])
            except ValueError:
                # сообщение о неверном количестве
                continue

            operations.append(
                {
                    "at": parts[0],
                    "kind": parts[1],
                    "sku": parts[2],
                    "warehouse": parts[3],
                    "qty": qty,
                }
            )
    return operations
```

После запуска на исходном файле программа должна сообщить о двух плохих строках и вернуть четыре операции. Числа в сообщениях зависят от того, как вы нумеруете строки, поэтому проверьте их по файлу, а не по образцу.

### Шаг 4. Допишите операцию в конец файла

Режим `"a"` добавляет данные в конец и не стирает прежние записи. Сначала пример на одном событии.

```python
record = ("2026-10-05T12:00", "RECEIPT", "SKU-1042", "Москва", 24)
line = "|".join(str(part) for part in record) + "\n"

with open(".../sklad-plus/data/operations.log", "a", encoding="utf-8", newline="") as file:
    file.write(line)
```

`join` собирает строку из кортежа, а `str(part)` приводит число к тексту. Перевод строки добавляется вручную, потому что `write` не делает этого сам. Параметр `newline=""` отключает преобразование перевода строки на Windows: в файле останется ровно `\n`, а не `\r\n`.

Оформите функцию `append_operation(path, record)`. Затем добавьте три операции из списка.

```text
2026-10-05T12:10|RECEIPT|SKU-3305|Калуга|60
2026-10-05T12:25|SHIPMENT|SKU-0871|Москва|18
2026-10-05T12:40|MOVE|SKU-2210|Тверь|9
```

Проверьте хвост файла и общее число строк. Если запустить добавление дважды, появятся дубли: журнал не проверяет уникальность сам. Запишите в отчёт, какое поле могло бы защитить от повтора и почему в учебном журнале его нет.

### Шаг 5. Обработайте отсутствие файла

Прочитайте несуществующий файл `.../sklad-plus/data/missing.log`. Функция должна вернуть пустой список и не создавать файл. Проверка `path.exists()` это один из двух способов. Второй способ ловит исключение.

```python
path = Path(".../sklad-plus/data/missing.log")

try:
    with path.open(encoding="utf-8") as file:
        text = file.read()
except FileNotFoundError:
    print("журнал ещё не создан")
    text = ""
```

Первый способ короче для чтения, второй надёжнее в момент между проверкой и открытием: файл могут удалить другой программой. В учебном проекте достаточно первого, но в отчёте объясните разницу одним предложением.

### Шаг 6. Соберите сводку

Сводка показывает, сколько единиц товара прошло по каждому типу операции. Напишите функцию `summarize(operations)`, которая возвращает словарь вида `{"RECEIPT": 204, "SHIPMENT": 30, "MOVE": 15}`.

Алгоритм простой: для каждой операции взять поле `kind`, найти текущее значение в словаре и прибавить `qty`. Если типа ещё нет, начать с нуля. Не используйте для этого три отдельных цикла по каждому типу: при появлении нового типа операций программа должна работать без правок.

Проверьте сводку на данных после трёх добавленных операций. Битые строки в подсчёт не входят, поэтому сумма должна сходиться с числом успешно прочитанных записей. Если сводка расходится с ожиданием, найдите строку, которая попала в список или выпала из него.

### Шаг 7. Проверьте кодировку и перевод строки

Откройте журнал с неверной кодировкой.

```python
with open(".../sklad-plus/data/operations.log", encoding="cp1251") as file:
    print(file.readline())
```

На русском тексте программа выбросит `UnicodeDecodeError` или покажет бессмысленные символы. Это доказательство, что кодировку нужно указывать явно и одинаково при записи и чтении.

Затем проверьте три свойства файла:

- последний символ файла это `\n`;
- число строк в файле больше числа успешно прочитанных операций на количество пустых и битых строк;
- повторное чтение сразу после записи возвращает добавленные операции.

```python
text = Path(".../sklad-plus/data/operations.log").read_text(encoding="utf-8")
print(repr(text[-1]))
print(text.count("\n"))
```

Если последний символ не `\n`, следующая запись приклеится к последней. Если число строк не сходится, проверьте, не потерялась ли пустая строка при сохранении файла редактором.

### Шаг 8. Соберите программу

Соберите функции в файл `.../sklad-plus/src/journal.py`. Внизу добавьте блок запуска, который читает журнал, печатает количество операций и сводку. Запустите программу из терминала.

```powershell

```

Ожидаемый вывод начинается с сообщений о двух повреждённых строках, затем идут количество и сводка. Точные номера строк зависят от файла, поэтому сверяйте не текст целиком, а смысл: две строки пропущены, семь операций прочитаны, суммы по типам сходятся.

## Критерии оценки

Оценка выставляется по шкале от 1 до 5.

- **5**: программа читает журнал, пропускает пустые и битые строки с указанием номера, дописывает операции, обрабатывает отсутствие файла и считает сводку; вывод совпадает с файлом, отчёт объясняет выбор режима и кодировки.
- **4**: работа выполнена полностью, но одно сообщение о битой строке не содержит номера или сводка не проверена на повторном запуске.
- **3**: программа читает файл, но падает на отсутствующем файле или неверном количестве, запись выполнена без `newline=""`, сводка считается только для одного типа операции.
- **2**: работа не выполнена или программа не запускается на исходном файле.
- **1**: работа выполнена с использованием ИИ или скопирована полностью или частично, 1 балл без возможности исправления.
