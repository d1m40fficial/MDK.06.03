## Краткие теоретические сведения

Каркас проекта это набор каталогов и файлов, который задаёт места для кода, проверок и документации. Пока в проекте один модуль, каркас кажется избыточным. Через несколько занятий в нём появятся работа с файлами, база SQLite, API и тесты, и каждый новый файл должен попасть на своё место без перестройки всего проекта.

Каталог `src` хранит исходный код, `tests` проверки, `docs` документы, `data` учебные данные и будущую базу. Внутри `src` лежит пакет `sklad`, а в нём слой `service` для правил расчёта. Файл `README.md` описывает проект для человека, который видит его впервые: что это, как запустить, что должно появиться на экране. Файл `pyproject.toml` хранит имя проекта, версию и зависимости. Файл `.gitignore` перечисляет то, что не нужно хранить в репозитории: кеш Python, виртуальное окружение, временные файлы редактора.

Пакет в Python это каталог с файлом `__init__.py`. Пакет позволяет разложить код по файлам и обращаться к нему по имени: `from sklad.service.storage import box_volume`. Приложение запускают командой `python -m sklad`: Python находит пакет и выполняет файл `__main__.py`. Прямой запуск `python src/sklad/__main__.py` работает иначе, потому что Python ищет модули в папке самого файла, и пакет `sklad` там не находится.

Функция это именованный блок кода с параметрами и результатом. Параметры описывают, какие данные нужны функции, а `return` возвращает результат вызывающему коду. Функция, которая только печатает на экран, не годится для проверки: результат нельзя сравнить, сохранить или передать дальше. Поэтому расчёт отделяют от вывода.

Разделение расчёта и вывода даёт три выгоды. Функцию можно вызвать из проверки и сравнить число с ожидаемым. Её можно вызвать из другого модуля, например из отчёта или API, не переписывая формулу. И её можно заменить, не трогая остальную программу: если завтра паллета станет другого размера, меняется одна константа. Функция, которая печатает внутри себя, не даёт ни одной из этих возможностей.

Имена функций в Python пишут строчными буквами с подчёркиваниями и начинают с глагола: `box_volume`, `pallets_needed`. Имя параметра отвечает на вопрос «что это», имя функции на вопрос «что она делает». Такое правило кажется вкусовым, пока в проекте не появляется третий файл и не приходится угадывать, что делает `data2`.

Паллета в учебном кейсе имеет размеры 1,2 на 0,8 метра и высоту штабеля 1,5 метра. Её объём равен 1,44 кубического метра. Объём коробки считают в кубических метрах: произведение сторон в сантиметрах делят на миллион.

Округлять промежуточные значения нельзя. Коробка 30 на 30 на 25 сантиметров имеет объём 0,0225 кубического метра. Если округлить его до тысячных, получится 0,022, и сорок таких коробок дадут 0,88 вместо 0,9 кубического метра. Ошибка в две сотых кубометра кажется мелочью, пока она не превращается в лишнюю или недостающую паллету. Округляют только итог, перед выводом.

## Ход работы

### Шаг 1. Создайте каркас проекта

Каркас создают командами в терминале. Сначала разберите пример: команда `mkdir` создаёт один каталог, а `cd` переходит в него.

```powershell
mkdir sklad-plus
cd sklad-plus
mkdir src
mkdir tests
mkdir docs
mkdir data
```

Первая команда создаёт папку проекта, вторая делает её текущей, остальные создают каталоги внутри. Проверить результат можно командой `dir`: она показывает содержимое текущего каталога.

Создайте пакет и слой расчётов:

```powershell
cd src
mkdir sklad
mkdir sklad\service
New-Item -ItemType File sklad\__init__.py
New-Item -ItemType File sklad\service\__init__.py
cd ..
```

Файлы `__init__.py` могут быть пустыми. Их наличие сообщает Python, что каталоги `sklad` и `sklad.service` это пакеты, а не просто папки с файлами.

Создайте файл `pyproject.toml` в корне проекта:

```toml
[project]
name = "sklad-plus"
version = "0.1.0"
requires-python = ">=3.13"
dependencies = []
```

Пока зависимостей нет, но файл фиксирует имя проекта и версию Python. Позже в нём появятся библиотеки для работы с базой и API.

Заполните `.gitignore`:

```text
__pycache__/
*.pyc
.venv/
```

Каталог `__pycache__` появляется после первого запуска, в нём лежит скомпилированный байт-код. Виртуальное окружение `.venv` весит десятки мегабайт и восстанавливается одной командой, поэтому в репозиторий его не кладут.

Целевая структура проекта:

```text
sklad-plus/
  .gitignore
  pyproject.toml
  README.md
  data/
    .gitkeep
  docs/
  src/
    sklad/
      __init__.py
      __main__.py
      service/
        __init__.py
        storage.py
  tests/
    service/
      check_storage.py
```

Файлы `__main__.py`, `storage.py` и `check_storage.py` появятся в следующих шагах. Пока создайте пустой `README.md` в корне проекта и пустой `data/.gitkeep`, чтобы Git сохранил каталог `data`.

### Шаг 3. Напишите первую функцию

Начните с функции объёма коробки. Проверьте её на одном примере: коробка 40 на 30 на 25 сантиметров.

```python
def box_volume(length_cm, width_cm, height_cm):
    return length_cm * width_cm * height_cm / 1_000_000
```

Произведение сторон даёт 30 000 кубических сантиметров, деление на миллион переводит их в 0,03 кубического метра. Запустите функцию в интерактивной оболочке или в отдельном файле и убедитесь, что результат совпадает:

```text
>>> box_volume(40, 30, 25)
0.03
```

Теперь перенесите функцию в файл `.../sklad-plus/src/sklad/service/storage.py`. Добавьте строку документации и подсказки типов: они не меняют работу программы, но показывают, что функция принимает и что возвращает.

```python
"""Расчёты хранения для ИС «Склад+»."""


def box_volume(length_cm: float, width_cm: float, height_cm: float) -> float:
    """Объём коробки в кубических метрах."""
    return length_cm * width_cm * height_cm / 1_000_000
```

Подсказки типов в Python необязательны и не проверяются при запуске. Их читает человек и редактор, который подсказывает ошибки до запуска.

Если забыть `return` и оставить только `print`, функция вернёт `None`. Проверка `box_volume(40, 30, 25) == 0.03` в этом случае даст `False`, а арифметика с результатом упадёт с ошибкой `TypeError`. Поэтому результат всегда возвращают, а печатают его уже в точке входа.

### Шаг 4. Добавьте расчёт паллет

Количество паллет округляют вверх: неполная паллета всё равно занимает место в машине. Для этого в модуле `math` есть функция `ceil`. Разберите её на примере груза объёмом 1,6 кубического метра при объёме паллеты 1,44.

```text
>>> import math
>>> 1.6 / 1.44
1.1111111111111112
>>> math.ceil(1.6 / 1.44)
2
```

Деление даёт 1,11, а `ceil` поднимает значение до 2. Обычное округление здесь ошиблось бы: 1,11 округляется до 1, и часть груза осталась бы без места.

Добавьте в `storage.py` константу и вторую функцию. Объём паллеты сделайте значением по умолчанию, чтобы её можно было заменить для другой машины.

```python
import math

PALLET_VOLUME_M3 = 1.44


def pallets_needed(total_volume_m3: float, pallet_volume_m3: float = PALLET_VOLUME_M3) -> int:
    """Количество паллет для груза заданного объёма."""
    return math.ceil(total_volume_m3 / pallet_volume_m3)
```

Проверьте функцию на трёх значениях и заполните таблицу. Первая строка дана как образец, остальные посчитайте сами.

| Объём груза, м3 | Паллет | Проверка вручную |
|---|---|---|
| 1,44 | 1 | 1,44 / 1,44 = 1 |
| 0,5 |  |  |
| 1,45 |  |  |
| 4,32 |  |  |

### Шаг 5. Соберите точку входа

Файл `__main__.py` связывает функции с данными и печатает результат. Импорт берёт функции из слоя `service`.

```python
"""Точка входа приложения «Склад+»."""

from sklad.service.storage import box_volume, pallets_needed


def main() -> None:
    volume = box_volume(40, 30, 25) * 24
    print(f"Объём: {round(volume, 3)} м3")
    print(f"Паллет: {pallets_needed(volume)}")


if __name__ == "__main__":
    main()
```

Конструкция `if __name__ == "__main__":` запускает `main` только при прямом запуске пакета. Если модуль импортируют из другого места, функция не выполнится сама по себе.

Запуск выполняют из папки `src`, потому что поиск пакета начинается с текущего каталога:

```powershell
cd .../sklad-plus/src
python -m sklad
```

Ключ `-m` означает «запустить модуль по имени». Попробуйте для сравнения запустить файл напрямую из корня проекта:

```text
> python src/sklad/__main__.py
ModuleNotFoundError: No module named 'sklad'
```

Ошибка появляется потому, что при прямом запуске Python ищет модули в папке самого файла `.../src/sklad`, а пакета `sklad` там нет. Команда `python -m sklad` решает задачу иначе: она ищет пакет от текущего каталога, и `src` оказывается на месте.

### Шаг 8. Добавьте ввод с клавиатуры

Программа должна уметь считать не только заранее записанные отгрузки. Добавьте в `main` запрос размеров одной коробки. Функция `input` возвращает строку, поэтому её сразу преобразуют в число: `float` для размеров и `int` для количества.

```python
length = float(input("Длина коробки, см: "))
width = float(input("Ширина коробки, см: "))
height = float(input("Высота коробки, см: "))
count = int(input("Количество коробок: "))
volume = round(box_volume(length, width, height) * count, 3)
print(f"Партия: объём {volume} м3, паллет {pallets_needed(volume)}")
```

Запустите программу и введите коробку 50 на 40 на 30 сантиметров в количестве 30 штук. Запишите результат в отчёт. Затем введите размеры с десятичной точкой, например 45.5, и проверьте, что программа принимает такое значение.

С десятичной запятой возникнет ошибка. Ввод `4,5` функция `float` не принимает, потому что в Python разделителем дробной части служит точка:

```text
ValueError: could not convert string to float: '4,5'
```

Это не поломка программы, а сигнал о неверном формате данных. Обработку таких ошибок разберут отдельно, а пока достаточно знать, что ввод с запятой программа не примет и завершится с сообщением.

### Шаг 9. Напишите проверки

Проверки фиксируют ожидаемое поведение функций. Файл `.../sklad-plus/tests/service/check_storage.py` повторяет структуру модуля и запускается из корня проекта.

```python
"""Проверки расчётов хранения."""

import sys
from pathlib import Path

sys.path.insert(0, str(Path(__file__).resolve().parents[2] / "src"))

from sklad.service.storage import box_volume, pallets_needed

assert round(box_volume(100, 100, 100), 3) == 1.0
assert round(box_volume(40, 30, 25), 3) == 0.03
assert pallets_needed(1.44) == 1
assert pallets_needed(1.5) == 2
print("Все проверки пройдены")
```

Строка с `sys.path` добавляет каталог `src` в список мест, где Python ищет пакеты. Без неё скрипт из папки `tests` не увидит пакет `sklad`. Выражение `parents[2]` поднимается на два уровня вверх, от `tests/service` к корню проекта.

Запустите проверки:

```powershell
python tests/service/check_storage.py
```

Добавьте не меньше трёх собственных проверок: граничный объём ровно на одну паллету, объём чуть больше паллеты и объём маленькой коробки. Одна из проверок должна ловить ошибку округления промежуточного значения.

Отчёт проверяют на воспроизводимость: по командам из README и отчёта другой человек должен получить тот же вывод. Если для запуска нужно перейти в особый каталог или установить пакет, это указано в отчёте отдельной строкой. Скриншоты не заменяют команды, они только подтверждают, что запуск действительно выполнялся.

## Критерии оценки

Оценка выставляется по шкале от 1 до 5.

- **5**: каркас соответствует структуре, функции расчёта имеют параметры, возврат и docstring, приложение запускается командой `python -m sklad`, результаты двух площадок совпадают с ручным расчётом, проверки проходят, README позволяет запустить проект без пояснений, в журнале не меньше двух осмысленных коммитов.
- **4**: работа выполнена полностью, но одна функция печатает результат вместо возврата, либо в README нет команды запуска, либо проверок меньше трёх, либо ручная проверка выполнена только для одной площадки.
- **3**: каркас собран, но пакет не используется: расчёты продублированы в `__main__.py`, проверки отсутствуют или не запускаются, README содержит только название.
- **2**: работа не выполнена или приложение не запускается.
- **1**: работа выполнена с использованием ИИ или скопирована полностью или частично, 1 балл без возможности исправления.
