## Цель работы

Ручной SQL удобен, пока запрос один. Когда приложение собирает условия по частям, проверяет права и преобразует строки в объекты, одинаковые куски SQL начинают повторяться в разных файлах. ORM переносит описание таблицы в класс, а сборку запроса в выражения Python. Цель работы: описать таблицы товаров, складов и остатков классами SQLAlchemy, выполнить через сессию выборку, добавление и изменение, затем сравнить каждый результат с эквивалентным SQL-запросом.

На выходе получаются модуль моделей, скрипт запросов, файл базы SQLite и таблица сверки, в которой для каждой операции стоят выражение ORM, SQL-запрос и результат. Сверка нужна не для отчёта: она показывает, что ORM не «делает что-то своё», а строит тот же запрос к тем же таблицам.

## Краткие теоретические сведения

ORM расшифровывается как object-relational mapping, отображение объектов на таблицы. Класс модели описывает таблицу: имя класса связано с именем таблицы, атрибуты с колонками. Экземпляр класса это строка таблицы, а его атрибуты это значения полей. В SQLAlchemy 2.x модель наследуется от `DeclarativeBase`, а типы полей задаются аннотациями `Mapped`.

Связь между таблицами описывают двумя объявлениями. `ForeignKey` создаёт внешний ключ на уровне базы. `relationship` добавляет удобную навигацию в Python: от остатка к товару и складу, от склада к списку остатков. Одно без другого работает не полностью: без внешнего ключа база не проверит ссылку, без связи придётся вручную сопоставлять строки по идентификаторам.

Таблица остатков связывает товар и склад. У неё составной первичный ключ из двух колонок: `warehouse_id` и `product_id`. Одна и та же пара не может встречаться дважды, поэтому остаток по товару на складе существует в единственном экземпляре. Количество и ячейка хранения относятся к этой паре, а не к товару вообще.

Сессия это единица работы с базой. Она открывает соединение, хранит загруженные объекты и накапливает изменения. Пока сессия не зафиксирована, изменения существуют только в памяти. `session.commit()` записывает их одной транзакцией, `session.rollback()` отменяет. Контекстный менеджер `with Session(engine) as session` закрывает сессию даже при ошибке.

Запрос в SQLAlchemy 2.x собирают функцией `select`. Она принимает класс модели или отдельные колонки, а методы `where`, `join`, `group_by`, `order_by` добавляют части запроса. Выражение `select(Product).where(Product.price < 1000)` читается как «выбрать товары дешевле тысячи». ORM преобразует его в SQL и передаёт драйверу.

У сессии есть кеш идентичности. Если дважды запросить товар с одним и тем же первичным ключом, сессия вернёт один и тот же объект, а не два разных. Это экономит память и помогает не потерять изменения, но требует помнить: объект в сессии может быть устаревшим по сравнению с базой. После `commit()` сессия по умолчанию истекает срок действия загруженных объектов, и следующее обращение к атрибуту перечитывает строку.

Ленивая загрузка это свойство связей, а не отдельных полей. Когда у склада запрашивают `warehouse.stock`, ORM по умолчанию загрузит связанные остатки только при обращении. В цикле по всем складам такое обращение даст дополнительный запрос на каждый склад, эту проблему называют N+1. Связи загружают заранее через `selectinload` или `joinedload`, если они нужны в цикле.

| Свойство | Чистый SQL | ORM |
|---|---|---|
| Описание таблицы | `CREATE TABLE` в скрипте | класс модели |
| Сборка запроса | строка SQL | выражение `select` |
| Результат | кортежи строк | объекты классов |
| Изменение | `UPDATE` вручную | изменение атрибута и `commit` |
| Проверка типов | во время выполнения | частично при написании кода |
| Контроль над запросом | полный | через построитель выражений |
| Стоимость освоения | ниже | выше |

ORM не отменяет SQL. Сложный отчёт с оконными функциями, подсказками планировщику и нестандартным соединением проще написать запросом. ORM выигрывает там, где нужно много однотипных операций над объектами и где важно не размазывать имена таблиц по всему коду.

### Шаг 2. Опишите таблицы классом модели

Создайте файл `.../sklad-plus/storage/models.py`. Ниже каркас: подключение к базе, модель склада и первые поля товара. Остальные поля и модель остатков добавьте по таблицам схемы.

| Таблица | Колонка | Тип | Ограничение | Смысл |
|---|---|---|---|---|
| `warehouses` | `id` | целое | первичный ключ | идентификатор склада |
| `warehouses` | `title` | строка | уникальный, обязательный | название площадки |
| `products` | `id` | целое | первичный ключ | идентификатор товара |
| `products` | `sku` | строка | уникальный, обязательный | артикул |
| `products` | `title` | строка | обязательный | название |
| `products` | `category` | строка | обязательный | товарная категория |
| `products` | `price` | вещественное | больше нуля | цена за единицу |
| `stock` | `warehouse_id` | целое | внешний ключ, часть ключа | склад |
| `stock` | `product_id` | целое | внешний ключ, часть ключа | товар |
| `stock` | `qty` | целое | не меньше нуля | остаток |
| `stock` | `min_qty` | целое | не меньше нуля | минимальный остаток |
| `stock` | `cell` | строка | обязательный | ячейка хранения |

```python
from pathlib import Path

from sqlalchemy import ForeignKey, String, create_engine
from sqlalchemy.orm import DeclarativeBase, Mapped, Session, mapped_column, relationship

BASE_DIR = Path(__file__).resolve().parents[1]
DB_PATH = BASE_DIR / "data" / "sklad.db"
engine = create_engine(f"sqlite:///{DB_PATH}")


class Base(DeclarativeBase):
    pass


class Warehouse(Base):
    __tablename__ = "warehouses"

    id: Mapped[int] = mapped_column(primary_key=True)
    title: Mapped[str] = mapped_column(String(40), unique=True)
    stock: Mapped[list["Stock"]] = relationship(back_populates="warehouse")


class Product(Base):
    __tablename__ = "products"

    id: Mapped[int] = mapped_column(primary_key=True)
    sku: Mapped[str] = mapped_column(String(20), unique=True)
    title: Mapped[str] = mapped_column(String(80))
    # добавьте category, price и связь stock
```

Остатки опишите отдельным классом. У него два первичных ключа, `warehouse_id` и `product_id`, каждый со своим `ForeignKey`. Для количества, минимума и ячейки хватит `Mapped[int]` и `Mapped[str]`. Связи `warehouse` и `product` должны указывать на одноимённые свойства в моделях склада и товара через `back_populates`.

Ограничения «не меньше нуля» и «больше нуля» можно задать через `CheckConstraint`, но в этой работе достаточно типа поля и проверки при вводе.

Дополните модель до запуска `create_all`. Если таблица уже создана без колонок, `create_all` её не изменит, и файл базы придётся удалить и создать заново.

```python

    DB_PATH.parent.mkdir(exist_ok=True)
    Base.metadata.create_all(engine)
    print("таблицы созданы")
```

Загрузку выполните через сессию. Сначала добавьте склады и товары, затем вызовите `flush`, чтобы получить их идентификаторы, и только после этого создавайте строки остатков. `flush` отправляет вставки в базу, но не фиксирует транзакцию.

WAREHOUSES = ["Москва", "Тверь", "Тула", "Калуга"]

PRODUCTS = [
    ("SKU-1001", "Перфоратор Bosch GSB 13 RE", "Инструмент", 8990.00),

    ("SKU-4002", "Саморез 4.2x75", "Крепёж", 3.40),
]

STOCK = [
    (1, 1, 12, 5, "A-01-01"),
    (2, 1, 3, 5, "A-01-01"),
    (1, 2, 4, 6, "A-01-02"),
    (3, 2, 8, 4, "B-02-01"),
    (1, 3, 340, 100, "B-02-02"),

with Session(engine) as session:

            product=products[product_id - 1],
            qty=qty,
            min_qty=min_qty,
            cell=cell,

    session.commit()

### Шаг 4. Выполните выборку через сессию

В начале `queries.py` импортируйте `Product`, `Stock`, `Warehouse` и `engine` из `models.py`.

Первый запрос дан как образец. Он выбирает товары дешевле 1000 и сортирует их по названию. Обратите внимание: в выборке участвует класс `Product`, а не имя таблицы.

```python
from sqlalchemy import func, select
from sqlalchemy.orm import Session

with Session(engine) as session:
    stmt = select(Product).where(Product.price < 1000).order_by(Product.title)
    for product in session.scalars(stmt):
        print(product.sku, product.title, product.price)
```

2. Сумму остатков по каждому складу. Соедините `Warehouse` и `Stock`, сгруппируйте по названию склада и отсортируйте по сумме от большей к меньшей.
3. Строки остатков, у которых `qty` меньше `min_qty`. Выведите название товара, название склада, остаток и минимум. Понадобятся два соединения: товар с остатком и остаток со складом.
4. Количество товаров в категории `Крепёж`. Используйте `func.count` и `select_from(Product)`.

Все выборки сохраните в файл `.../sklad-plus/storage/queries.py`, чтобы их можно было запустить одной командой и приложить к отчёту.

Для суммы и количества импортируйте `func` из `sqlalchemy`. Запрос с группировкой возвращает не объекты `Product`, а кортежи, поэтому результат читают через `session.execute(stmt)`, а не через `session.scalars`.

Разница между `scalars` и `execute` важна при чтении результата. `scalars` возвращает первый столбец каждой строки, поэтому для `select(Product)` это объекты. `execute` возвращает строки целиком, поэтому для `select(Warehouse.title, func.sum(Stock.qty))` нужен именно он. Если перепутать, вместо суммы можно получить объект или ошибку распаковки.

### Шаг 5. Измените запись и добавьте новую

Изменение в ORM выглядит как присваивание атрибута. Сессия отслеживает объект, а `commit` записывает разницу. Ниже образец: цена одного товара повышается на десять процентов.

```python
with Session(engine) as session:
    product = session.get(Product, 2)
    product.price = round(product.price * 1.10, 2)
    session.commit()
    print(product.sku, product.price)
```

Выполните две операции:

1. Повысьте цену всех товаров категории `Крепёж` на 5 процентов. Значение округлите до двух знаков после запятой через `round`. Выведите число изменённых строк и новые цены.
2. Добавьте товар `SKU-5001` с названием `Уровень строительный 600 мм`, категорией `Измерительный инструмент`, ценой 1290.00. Затем добавьте остаток этого товара на складе `Москва`: 15 штук, минимум 5, ячейка `E-01-01`. Для получения идентификатора нового товара используйте `flush`. После `commit` выведите количество товаров и количество строк остатков.

После `commit` сессия истекает срок действия объекта. Если сразу прочитать `product.price`, SQLAlchemy перечитает строку из базы. Это нормально, но объясняет лишний запрос в журнале. Если объект нужен после закрытия сессии, заранее скопируйте значения в обычные переменные.

### Шаг 6. Сравните ORM с SQL

Для каждой операции из шагов 4 и 5 запишите эквивалентный SQL. Выполните его через `text()` в той же сессии и сравните результат с ORM. Ниже образец для первой выборки.

| Что искали | Выражение ORM | SQL-запрос | Число строк | Первая строка | Совпало |
|---|---|---|---|---|---|
| Товары дешевле 1000 | `select(Product).where(Product.price < 1000).order_by(Product.title)` | `SELECT * FROM products WHERE price < 1000 ORDER BY title` |  |  |  |
| Инструмент дороже 10000 |  |  |  |  |  |
| Остатки по складам |  |  |  |  |  |
| Дефицит по складам |  |  |  |  |  |
| Количество товаров категории Крепёж |  |  |  |  |  |

```python
from sqlalchemy import text

with Session(engine) as session:
    rows = session.execute(
        text("SELECT sku FROM products WHERE price < 1000 ORDER BY title")
    )
    for row in rows:
        print(row)
```

Сравнивайте не только число строк, но и значения. Если ORM вернула 1 строку, а SQL 2, причина обычно в условии: `>` вместо `>=`, разный регистр строки или пропущенное условие. Если значения совпали, но порядок разный, проверьте `ORDER BY`.

Расхождение в числе строк почти всегда означает разное условие, а не ошибку ORM. Сравните текст SQL, который построила ORM: `print(stmt)` выводит запрос с подставленными именами колонок. Если в ORM стоит `Product.price > 10000`, а в SQL `>= 10000`, на границе появится лишняя строка. Если ORM добавила `ORDER BY`, а SQL нет, значения совпадут, а порядок нет.

SQL в `text()` не должен собираться склейкой пользовательских значений. Для сравнения на учебных данных это безопасно, но в рабочем коде значения передают параметрами: `text("... WHERE sku = :sku")` и `{"sku": value}`. Иначе появляется риск инъекции.

### Шаг 7. Проверьте конфликт уникальности

Попробуйте добавить товар с уже существующим `sku`. База отклонит вставку, SQLAlchemy выбросит `IntegrityError`. Перехватите ошибку, откатите транзакцию и выведите понятное сообщение.

```python
from sqlalchemy.exc import IntegrityError

with Session(engine) as session:
    session.add(
        Product(
            sku="SKU-1001",
            title="Дубль",
            category="Инструмент",
            price=1.00,
        )
    )
    try:
        session.commit()
    except IntegrityError:
        session.rollback()
        print("товар с таким sku уже существует")
```

Ответьте в отчёте, что произойдёт, если не вызвать `rollback` и попытаться продолжить работу в той же сессии. Проверьте ответ практикой: добавьте после ошибки корректный товар и посмотрите, проходит ли `commit`. Отдельно проверьте конфликт составного ключа: попробуйте вставить второй остаток для той же пары склада и товара.
