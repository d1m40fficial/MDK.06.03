## Смена в Туле, 08:40

Кладовщик открывает «Склад+» и видит 4800 позиций на четырёх площадках: в Москве, Твери, Туле и Калуге. Товары разложены по 12 категориям, от крепежа до электрики. Задача на утро звучит просто: понять, что нужно заказать у поставщика, пока склад не встал.

Простота обманчива. Заказывать все 4800 позиций нельзя, это заморозит деньги и забьёт ячейки. Заказывать только те, где остаток равен нулю, тоже нельзя: товар кончится раньше, чем придёт поставка. Правило склада учитывает минимальный остаток и кратность упаковки: поставщик везёт крепёж коробками по 10 штук, электрику по 12, сантехнику по 4. Если остаток ниже минимума, нужно добрать разницу и округлить её вверх до целой коробки.

Такое правило нельзя применить одной формулой ко всей таблице. Сначала нужно решить, какие строки вообще участвуют в расчёте, потом пройти по ним и накопить итог. Эти два действия и есть управляющие конструкции: **ветвление выбирает, какие данные обрабатывать, а цикл повторяет обработку для каждой выбранной строки**.

Ошибка в любом из двух мест выглядит одинаково: программа работает, числа выходят правдоподобные, а заказ приходит неполный. Поэтому разберём не синтаксис ради синтаксиса, а решение о пути, по которому идут данные.

## Ветвление: какие позиции попадают в заказ

Начнём с одной строки. У позиции `SKU-1042` остаток 12 штук, минимум 40, упаковка 10. Остаток ниже минимума, значит позиция попадает в заказ. У позиции `SKU-2087` остаток 96 при минимуме 60, заказывать нечего.

На Python это записывается так:

```python
quantity = 12
min_quantity = 40
if quantity < min_quantity:
    print("заказать")
else:
    print("не заказывать")
```

На C# то же решение выглядит почти так же, но с фигурными скобками и обязательными круглыми скобками вокруг условия:

```csharp
int quantity = 12;
int minQuantity = 40;
if (quantity < minQuantity)
{
    Console.WriteLine("заказать");
}
else
{
    Console.WriteLine("не заказывать");
}
```

Разница в записи не меняет смысла. В обоих языках условие вычисляется один раз, и выполняется ровно одна ветка. Как только ветка выбрана, вторая не выполняется вообще, даже если её условие тоже оказалось бы истинным.

Когда условий несколько, порядок становится частью алгоритма. Для склада их три: позиция активна, остаток ниже минимума, категория не исключена из автозаказа. Запись с `elif` в Python и `else if` в C# читается сверху вниз, и первая истинная ветка забирает управление.

```python
if not position["active"]:
    decision = "архив"
elif position["category"] == "Спецтехника":
    decision = "заказ вручную"
elif position["qty"] < position["min_qty"]:
    decision = "в заказ"
else:
    decision = "достаточно"
```

Порядок здесь не случаен. Если поставить проверку остатка первой, архивная позиция с нулевым остатком попадёт в заказ, хотя её сняли с продажи. Проверка активности должна стоять раньше, потому что она отсекает строку независимо от чисел.

Тот же приём в C# называют защитным условием, или ранним выходом. Вместо вложенных `if` функция сначала отбрасывает невозможные случаи и возвращает результат:

```csharp
static int ReorderQuantity(int quantity, int minQuantity, int packSize)
{
    if (quantity >= minQuantity)
    {
        return 0;
    }
    int missing = minQuantity - quantity;
    int packs = (missing + packSize - 1) / packSize;
    return packs * packSize;
}
```

Проверка `quantity >= minQuantity` стоит первой и снимает главный вопрос: нужен ли заказ. Всё, что ниже, уже работает только с дефицитом. Такая запись короче вложенных веток и легче читается, потому что каждая строка имеет один смысл.

Отдельно стоит запомнить `continue` внутри цикла. Он не выходит из цикла, а пропускает остаток тела для текущей строки и переходит к следующей. Для склада это удобно: позиции, которых хватает, не нужно считать, и они не должны увеличивать счётчик заказа.

## Цикл: один и тот же обход в двух языках

Одна строка обрабатывается ветвлением. 4800 строк обрабатываются циклом. В Python самый короткий способ пройти по списку словарей выглядит так:

```python
for row in positions:
    print(row["sku"])
```

Здесь нет счётчика и нет условия выхода: Python сам берёт следующий элемент, пока список не закончится. Если нужен номер строки, добавляют `enumerate`:

```python
for number, row in enumerate(positions, start=1):
    print(number, row["sku"])
```

В C# обход коллекции без счётчика делают через `foreach`:

```csharp
foreach (string sku in skus)
{
    Console.WriteLine(sku);
}
```

А обход по индексу через `for`:

```csharp
for (int i = 0; i < skus.Length; i++)
{
    Console.WriteLine(skus[i]);
}
```

Разница между двумя формами важна для перевода. `foreach` не даёт менять коллекцию во время обхода и не показывает индекс. `for` даёт индекс, но требует вручную задать начало, условие продолжения и шаг. В Python аналогичное деление выглядит как `for row in rows` и `for i in range(len(rows))`.

Третья форма это цикл с условием. Он нужен, когда число повторений заранее неизвестно: например, читать строки из файла, пока не встретится пустая. В Python это `while condition:`, в C# `while (condition)`. У C# есть ещё `do { } while (condition);`, где тело выполняется хотя бы один раз, даже если условие ложно с самого начала. В Python встроенного `do-while` нет, его собирают из `while True` и `break`.

| Задача | Python | C# |
|---|---|---|
| Ветвление по условию | `if`, `elif`, `else` | `if`, `else if`, `else` |
| Обход коллекции | `for row in rows` | `foreach (var row in rows)` |
| Обход по индексу | `for i in range(len(rows))` | `for (int i = 0; i < rows.Length; i++)` |
| Повтор по условию | `while condition:` | `while (condition)` |
| Тело хотя бы один раз | `while True` и `break` | `do { } while (condition);` |
| Пропустить строку | `continue` | `continue` |
| Выйти из цикла | `break` | `break` |
| Граница диапазона | правый конец не входит | граница задаётся условием |

Последняя строка таблицы объясняет половину ошибок перевода. `range(0, 5)` в Python даёт 0, 1, 2, 3, 4, то есть пять значений без пятёрки. В C# условие `i < 5` даёт те же пять значений, а `i <= 5` уже шесть. При переносе кода нужно переводить не символы, а количество повторений.

Соберём рабочий расчёт для пяти позиций. В Python данные удобно держать списком словарей:

```python
positions = [
    {"sku": "SKU-1042", "category": "Крепёж", "qty": 12, "min_qty": 40, "pack": 10},
    {"sku": "SKU-2087", "category": "Электрика", "qty": 96, "min_qty": 60, "pack": 12},
    {"sku": "SKU-3310", "category": "Крепёж", "qty": 0, "min_qty": 25, "pack": 5},
    {"sku": "SKU-4155", "category": "Инструмент", "qty": 7, "min_qty": 7, "pack": 1},
    {"sku": "SKU-5201", "category": "Электрика", "qty": 3, "min_qty": 30, "pack": 6},
]

total = 0
count = 0
for row in positions:
    if row["qty"] >= row["min_qty"]:
        continue
    missing = row["min_qty"] - row["qty"]
    packs = (missing + row["pack"] - 1) // row["pack"]
    order = packs * row["pack"]
    total += order
    count += 1
    print(row["sku"], row["qty"], row["min_qty"], "->", order)

print("Позиций к заказу:", count)
print("Всего единиц:", total)
```

Запуск даёт:

```text
SKU-1042 12 40 -> 30
SKU-3310 0 25 -> 25
SKU-5201 3 30 -> 30
Позиций к заказу: 3
Всего единиц: 85
```

Обратите внимание на строку `packs = (missing + row["pack"] - 1) // row["pack"]`. Это округление вверх при целочисленном делении. Для `SKU-5201` дефицит равен 27, упаковка 6. Обычное деление `27 // 6` дало бы 4 коробки и 24 штуки, чего не хватает до минимума. Добавка `pack - 1` превращает 27 в 32, и `32 // 6` даёт 5 коробок, то есть 30 штук. Тот же приём работает в C#, где целочисленное деление отбрасывает дробную часть.

Проверим расчёт по строкам вручную. Для каждой позиции дефицит равен разнице между минимумом и остатком, число коробок округляется вверх, заказ равен числу коробок, умноженному на упаковку.

| Позиция | Остаток | Минимум | Дефицит | Коробок | Заказ |
|---|---|---|---|---|---|
| SKU-1042 | 12 | 40 | 28 | 3 | 30 |
| SKU-2087 | 96 | 60 | нет | 0 | 0 |
| SKU-3310 | 0 | 25 | 25 | 5 | 25 |
| SKU-4155 | 7 | 7 | нет | 0 | 0 |
| SKU-5201 | 3 | 30 | 27 | 5 | 30 |

Сумма заказов равна 85, и это число совпадает с выводом программы. Такая таблица полезна не только для проверки: она показывает, что формула работает на всех пяти строках, включая нулевой остаток и остаток ровно по минимуму.

Иногда цикл нужен не для полного обхода, а для поиска первой подходящей строки. Тогда после находки работу прекращают через `break`:

```python
for row in positions:
    if row["qty"] < row["min_qty"]:
        print("Первая позиция к заказу:", row["sku"])
        break
```

Программа печатает `Первая позиция к заказу: SKU-1042` и больше не перебирает список. В C# `break` работает так же и выходит только из ближайшего цикла. Если циклы вложены, `break` во внутреннем не остановит внешний: для этого нужен флаг или вынос поиска в отдельную функцию.

## Перевод алгоритма с Python на C#

Перевод начинается не с кода, а с данных. В Python одна строка это словарь с ключами `sku`, `qty`, `min_qty`, `pack`. В C# до появления классов на этом курсе удобно держать те же значения в параллельных массивах: индекс `i` связывает `skus[i]`, `quantities[i]`, `minimums[i]` и `packs[i]`. Связь по номеру слабее связи по имени, но для перевода алгоритма её достаточно. На занятии про объекты эти массивы заменятся классом.

Второй шаг: переписать условие и тело цикла, сохранив порядок действий. Третий: проверить, что граница цикла даёт то же число повторений. Вот полная программа на C#:

```csharp
using System;
using System.Text;

class Program
{
    static void Main()
    {
        Console.OutputEncoding = Encoding.UTF8;
        string[] skus = { "SKU-1042", "SKU-2087", "SKU-3310", "SKU-4155", "SKU-5201" };
        int[] quantities = { 12, 96, 0, 7, 3 };
        int[] minimums = { 40, 60, 25, 7, 30 };
        int[] packs = { 10, 12, 5, 1, 6 };

        int total = 0;
        int count = 0;
        for (int i = 0; i < skus.Length; i++)
        {
            if (quantities[i] >= minimums[i])
            {
                continue;
            }
            int missing = minimums[i] - quantities[i];
            int packCount = (missing + packs[i] - 1) / packs[i];
            int order = packCount * packs[i];
            total += order;
            count++;
            Console.WriteLine(skus[i] + " " + quantities[i] + " " + minimums[i] + " -> " + order);
        }
        Console.WriteLine("Позиций к заказу: " + count);
        Console.WriteLine("Всего единиц: " + total);
    }
}
```

Вывод совпадает с Python строка в строку:

```text
SKU-1042 12 40 -> 30
SKU-3310 0 25 -> 25
SKU-5201 3 30 -> 30
Позиций к заказу: 3
Всего единиц: 85
```

Совпадение вывода это критерий правильного перевода. Если числа разошлись, ищите причину в трёх местах: в условии отбора, в округлении и в границе цикла. Синтаксис почти никогда не виноват, потому что программа с неверным синтаксисом просто не соберётся.

Есть и различия, которые нужно помнить при переносе.

| Что сравниваем | Python | C# |
|---|---|---|
| Длина коллекции | `len(rows)` | `rows.Length` для массива, `rows.Count` для списка |
| Целочисленное деление | `//` | `/` для целых типов |
| Остаток от деления | `%` | `%` |
| Логическое И и ИЛИ | `and`, `or`, `not` | `&&`, `||`, `!` |
| Истина и ложь | `True`, `False` | `true`, `false` |
| Вывод строки | `print(...)` | `Console.WriteLine(...)` |
| Сложение строки и числа | нужна f-строка или `str()` | `+` со строкой приводит число к строке |

Последняя строка часто удивляет, но в обратную сторону. В Python выражение `"Всего: " + total` завершится ошибкой `TypeError: can only concatenate str (not "int") to str`, потому что `+` не смешивает строку и число. Нужна f-строка `f"Всего: {total}"` или явное `str(total)`. В C# то же выражение работает: если хотя бы один операнд строка, второй приводится к строке, и порядок операндов не важен.

Ещё одно различие касается `switch`. В C# классический `switch` выбирает ветку по точному значению и требует `break` в конце каждой ветки. В Python с версии 3.10 есть `match`, который умеет сравнивать с образцом и не требует `break`. Для склада это удобно при выборе кода площадки по названию, но обе конструкции решают одну задачу: выбрать одну ветку из нескольких по значению, а не по диапазону.

## Граничные случаи

Цикл, который правильно работает на пяти строках, может упасть на пустом списке или на последней строке. Граничный случай это вход, на котором условие цикла меняет смысл: ноль элементов, один элемент, последний элемент, значение ровно на пороге.

Первый случай: пустая коллекция. В Python `for row in []` не выполнится ни разу, и итог останется нулевым. В C# `for (int i = 0; i < skus.Length; i++)` при длине 0 тоже не выполнится. Это правильное поведение, но только если переменные `total` и `count` объявлены до цикла. Если объявить их внутри тела, после цикла их просто не будет, и программа не соберётся.

Второй случай: значение ровно на пороге. Позиция `SKU-4155` имеет остаток 7 при минимуме 7. Условие `qty < min_qty` ложно, заказ равен нулю. Если заменить его на `qty <= min_qty`, позиция попадёт в заказ и склад начнёт закупать товар, которого и так достаточно. Порог это самая частая причина лишних заказов.

Третий случай: последний элемент. Здесь появляется ошибка на единицу. Такой цикл в файле `offby.py`:

```python
positions = ["SKU-1042", "SKU-2087", "SKU-3310"]
for i in range(len(positions) + 1):
    print(positions[i])
```

печатает три строки, а затем падает:

```text
SKU-1042
SKU-2087
SKU-3310
Traceback (most recent call last):
  File "offby.py", line 3, in <module>
    print(positions[i])
IndexError: list index out of range
```

В C# та же ошибка выглядит как `IndexOutOfRangeException` и возникает при `i <= skus.Length`. Причина одна: условие продолжения пропускает индекс, которого в массиве нет. Лечение тоже одно: граница это длина, а не длина плюс один.

Четвёртый случай: изменение коллекции во время обхода. Кладовщик хочет убрать из списка позиции, которых достаточно. В Python такой код:

```python
skus = ["SKU-1", "SKU-2", "SKU-3", "SKU-4"]
for sku in skus:
    if sku in ("SKU-2", "SKU-3"):
        skus.remove(sku)
print(skus)
```

печатает `['SKU-1', 'SKU-3', 'SKU-4']`. Вторая позиция удалена, третья осталась, хотя её тоже собирались удалить. После удаления элементы сдвигаются влево, и цикл перескакивает через следующий. В C# `foreach` по списку при удалении внутри тела выбрасывает `InvalidOperationException` с сообщением «Коллекция была изменена; невозможно выполнить операцию перечисления». Правильное решение в обоих языках: собрать новый список или пройти по копии, а удалять после обхода.

Пятый случай: деление и кратность. Если `pack` равен нулю, формула округления делит на ноль: в Python будет `ZeroDivisionError`, в C# `DivideByZeroException`. Если остаток отрицательный, формула даст отрицательный заказ. Оба случая отсекаются проверкой входа до цикла, а не внутри него.

| Случай | Вход | Ожидание | Что ломается |
|---|---|---|---|
| Пустая коллекция | нет строк | итог 0, счётчик 0 | переменные объявлены внутри цикла |
| Порог | остаток равен минимуму | заказ 0 | условие `<=` вместо `<` |
| Последний элемент | индекс равен длине | обход без падения | условие `<=` вместо `<` |
| Удаление в обходе | две позиции подряд | удалены обе | сдвиг элементов |
| Нулевая упаковка | `pack = 0` | понятная ошибка | деление на ноль |
| Отрицательный остаток | `qty = -3` | отказ | отрицательный заказ |

Граничные случаи проверяют не после написания программы, а вместе с ней. Достаточно прогнать четыре набора: обычный, пустой, один элемент и значение на пороге. Если все четыре дают ожидаемый результат, цикл скорее всего устроен верно.

## Какую конструкцию выбрать

Выбор конструкции это выбор формы данных и формы повторения. Если нужно отобрать строки, подходит ветвление внутри обхода. Если нужно посчитать итог по всем строкам, подходит цикл с накопителем. Если число повторений известно заранее, берите `for` по диапазону. Если неизвестно, берите `while`. Если нужно обойти коллекцию целиком и индекс не нужен, берите `foreach` или `for row in rows`.

| Ситуация | Конструкция | Почему |
|---|---|---|
| Отсеять архивные позиции | `if` с ранним `continue` | решение по одной строке |
| Посчитать итог по 4800 позициям | `for` с накопителем | число строк известно |
| Читать файл до пустой строки | `while` | число повторений неизвестно |
| Обойти все категории | `foreach` | индекс не нужен |
| Повторить попытку ввода | `do-while` в C#, `while True` в Python | тело нужно хотя бы раз |
| Найти первую позицию ниже минимума | `for` и `break` | дальше искать не нужно |

Два правила помогают не усложнять. Первое: глубина вложенности не больше двух. Три уровня `if` внутри `for` внутри `if` читаются плохо, и почти всегда их можно разбить на отдельные функции. Второе: `break` и `continue` применяют только тогда, когда они сокращают код. Если после `continue` остаётся половина тела, проще переписать условие.

## Типичные ошибки

**Ошибка первая: граница цикла на единицу больше.** Симптом: программа падает на последней строке или, наоборот, не обрабатывает последний элемент. Причина в условии `i <= length` или `range(len(rows) + 1)`. Проверка: подставить длину 0 и длину 1.

**Ошибка вторая: округление вниз вместо вверх.** Симптом: заказ меньше минимума на несколько штук. Причина в `missing // pack` без добавки `pack - 1`. Проверка: взять дефицит, который не делится на упаковку нацело.

**Ошибка третья: изменение коллекции во время обхода.** Симптом: часть строк пропущена или возникает исключение. Причина в `remove` внутри `for` или `foreach`. Проверка: собрать новый список и сравнить длины.

**Ошибка четвёртая: условие на пороге.** Симптом: заказывается товар, которого достаточно. Причина в `<=` вместо `<`. Проверка: строка, где остаток равен минимуму, должна давать ноль.

**Ошибка пятая: счётчик объявлен внутри цикла.** Симптом: итог всегда равен последнему значению, а не сумме. Причина в `total = 0` внутри тела. Проверка: вывести итог после цикла и сравнить с ручной суммой.

> [!PITFALL] Проверяйте не только середину списка
> Пять строк с разными остатками не показывают, что будет на пустом списке и на строке с остатком ровно по минимуму. Эти два входа ловят большинство ошибок границ.

## Итоги

- Ветвление выбирает, какие данные обрабатывать, цикл повторяет обработку для каждой выбранной строки.
- Порядок условий входит в алгоритм: проверка активности стоит раньше проверки остатка.
- Python обходит коллекцию через `for row in rows`, C# через `foreach` или `for` по индексу.
- При переводе сохраняют число повторений, а не символы: `range(n)` и `i < n` дают одинаковый обход.
- Округление вверх при целочисленном делении делают добавкой `pack - 1` до деления.
- Граничные случаи проверяют на пустом списке, одном элементе, последнем элементе и значении на пороге.

::quiz
Q: Что делает ветвление в алгоритме расчёта заказа?
+ Выбирает, какие строки участвуют в обработке
- Повторяет обработку для каждой строки
- Суммирует все остатки на складе
- Сортирует позиции по категории
! Ветвление принимает решение по одной строке, а повторение обеспечивает цикл.

Q: Какая конструкция подходит для обхода всех 4800 позиций, когда индекс не нужен?
+ `foreach` в C# и `for row in rows` в Python
- `while` с ручным счётчиком
- `do-while` в C#
- `switch` по категории
! Обход коллекции целиком без индекса записывается через `foreach` или прямой `for`.

Q: Сколько значений обойдёт Python-цикл `for i in range(0, 5)`?
+ Пять
- Четыре
- Шесть
- Зависит от длины списка
! Правый конец диапазона не входит, поэтому получаются числа от 0 до 4.

Q: Зачем в формуле округления добавляют `pack - 1`?
+ Чтобы округлить дефицит вверх до целой упаковки
- Чтобы уменьшить заказ на одну упаковку
- Чтобы избежать деления на ноль
- Чтобы перевести штуки в коробки без остатка
! Добавка перед целочисленным делением даёт округление вверх.

Q: Что произойдёт, если заменить условие `qty < min_qty` на `qty <= min_qty`?
+ Позиция с остатком ровно по минимуму попадёт в заказ
- Позиция с нулевым остатком выпадет из заказа
- Цикл пропустит последнюю строку
- Программа не соберётся
! Порог с нестрогим сравнением добавляет лишнюю позицию.

Q: Где нужно объявить накопитель итога?
+ До цикла, чтобы значение сохранилось после его окончания
- Внутри тела цикла, рядом с расчётом
- После цикла, перед выводом
- В условии цикла
! Переменная внутри тела создаётся заново на каждой итерации.

Q: Какие действия выполняет `continue` внутри цикла?
+ Пропускает остаток тела для текущей строки
+ Переходит к следующей итерации
- Прерывает цикл полностью
- Возвращает значение из функции
! `continue` не выходит из цикла, а завершает текущую итерацию.

Q: Какие пары конструкций решают одну задачу в Python и C#?
+ `for row in rows` и `foreach (var row in rows)`
+ `while condition:` и `while (condition)`
+ `if`, `elif`, `else` и `if`, `else if`, `else`
- `range(n)` и `do { } while`
- `print` и `switch`
! Остальные пары сопоставляют разные по смыслу конструкции.

Q: Что произойдёт при удалении элемента списка внутри `foreach` в C#?
+ Возникнет `InvalidOperationException`
- Элемент удалится без ошибки
- Цикл завершится досрочно без сообщения
- Компилятор запретит сборку
! Перечислитель замечает изменение коллекции и выбрасывает исключение.

Q: Почему в Python после удаления двух элементов подряд один остался в списке?
+ После удаления следующие элементы сдвигаются, и цикл перескакивает через один
- Python удаляет только первый элемент за цикл
- Условие `in` проверяет только первый элемент
- Список автоматически сортируется
! Сдвиг элементов приводит к пропуску соседней строки.

Q: Что означает ошибка `IndexError: list index out of range`?
+ Индекс вышел за пределы длины списка
- В списке хранятся значения разных типов
- Список пуст и не создан
- В условии использована строка вместо числа
! Ошибка возникает, когда запрашивают элемент с несуществующим индексом.

Q: Какой набор входов проверяет границы цикла?
+ Пустая коллекция
+ Один элемент
+ Значение ровно на пороге
- Только обычный список из пяти строк
- Только список с максимальным остатком
! Границы проверяют крайние случаи, а не середину.

Q: Чем отличается `while` от `do-while` в C#?
+ `do-while` выполняет тело хотя бы один раз
- `while` не может содержать `break`
- `do-while` работает только с массивами
- `while` проверяет условие после тела
! В `do-while` условие стоит после тела, поэтому тело выполняется минимум один раз.

Q: Как называется ошибка, когда цикл обрабатывает на один элемент больше длины массива?
= ошибка на единицу
= off-by-one
= выход за границу массива
! Условие продолжения пропускает индекс, которого нет в массиве.

Q: Что нужно сделать перед удалением элементов из коллекции во время обхода?
= собрать новый список
= пройти по копии
= удалять после обхода
! Изменять коллекцию во время перебора нельзя, поэтому удаление откладывают или работают с копией.
::/gate
