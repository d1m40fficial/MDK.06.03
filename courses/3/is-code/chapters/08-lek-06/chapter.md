## Отчёт, в котором 480 012 коробок

Менеджер «Северного склада» выгружает остатки и видит странное число: 480 012 коробок вместо 4 812. Ошибка появилась после того, как к количеству из файла прибавили двенадцать коробок, поступивших утром. В файле количество хранилось текстом, и программа сложила текст с числом: `"4800" + 12` дала `"480012"`.

На Python тот же код упал бы с ошибкой: строка и число не складываются. В C# операция прошла молча, потому что язык разрешает прибавить число к строке и получить строку. Оба языка что-то сделали с типами, но по разным правилам, и менеджер увидел результат этих правил, а не свой отчёт.

**Тип это договор о том, какие значения хранит переменная и какие операции с ними допустимы.** Пока договор соблюдается, программа считает. Как только значение одного типа попадает туда, где ожидали другой, результат зависит от языка: Python чаще останавливает программу, C# чаще молча приводит значение к нужному виду.

## Тип как договор

У типа три части. Первая это множество значений: целое число не может быть равно 4,75, а строка не может быть истиной. Вторая это набор операций: числа складывают, строки соединяют, логические значения объединяют через «и» и «или». Третья это способ хранения в памяти: целое занимает фиксированное число байт, строка хранится отдельно от переменной.

В Python тип привязан к значению, а не к имени. Переменная это ссылка на объект, и один и тот же объект несёт свой тип. Поэтому имя можно переприсвоить:

```python
value = 4800
value = "4800"
```

Вторая строка не ошибка: имя теперь указывает на строку. Тип проверяется в момент операции, когда программа до неё дошла.

В C# тип привязан к переменной и известен компилятору заранее:

```csharp
int value = 4800;
value = "4800";
```

Вторая строка не соберётся: компилятор сообщит `CS0029`, потому что переменная объявлена целой. Проверка происходит до запуска, и программа с такой ошибкой не попадёт к пользователю.

| Свойство | Python | C# |
|---|---|---|
| Когда известен тип | во время выполнения | при сборке |
| Где хранится | в объекте значения | в объявлении переменной |
| Можно ли сменить тип | да, переприсвоив имя | нет, только объявить новую |
| Когда видна ошибка | при выполнении операции | при компиляции |
| Объявление | `value = 4800` | `int value = 4800;` |

Динамическая типизация удобна для коротких скриптов и неудобна для больших программ: ошибку в имени или типе можно найти только на том пути, который выполнился. Статическая типизация требует больше букв, но проверяет все ветки сразу.

## Четыре семейства типов

Почти любое значение в учебном проекте относится к одному из четырёх семейств: целые числа, вещественные числа, строки и логические значения.

| Семейство | Python | C# | Пример из «Склад+» |
|---|---|---|---|
| Целые | `int` | `int`, `long`, `byte` | количество коробок, номер ячейки |
| Вещественные | `float`, `Decimal` | `double`, `decimal` | объём груза, цена |
| Строки | `str` | `string` | название товара, код накладной |
| Логические | `bool` | `bool` | признак переполнения ячейки |

В Python целое число не ограничено по размеру: `int` хранит сколько угодно цифр, пока хватает памяти. В C# у каждого целого типа есть жёсткий диапазон.

| Тип C# | Размер | Диапазон |
|---|---|---|
| `byte` | 1 байт | от 0 до 255 |
| `short` | 2 байта | от -32 768 до 32 767 |
| `int` | 4 байта | от -2 147 483 648 до 2 147 483 647 |
| `long` | 8 байт | примерно от -9,22 × 10 в 18 степени до 9,22 × 10 в 18 степени |

Для количества коробок и номеров хватает `int`. Стоимость запаса из 4800 позиций по 129,90 рубля даёт 623 520 рублей, это 62 352 000 копеек, и такое число в `int` помещается. Годовой оборот склада больше, для него может понадобиться `long`.

Вещественные числа хранят дробную часть, но по-разному. `double` использует двоичное представление и жертвует точностью ради диапазона. `decimal` хранит десятичные цифры и подходит для денег. В Python обычный `float` это двойная точность, а для денег применяют модуль `decimal`.

Строка это последовательность символов. В обоих языках строка неизменяема: методы возвращают новую строку, а исходная остаётся прежней. Логический тип принимает два значения: истину и ложь.

## Объявление переменных

В Python переменная создаётся присваиванием. Имя пишут строчными буквами с подчёркиваниями:

```python
positions = 4800
volume_m3 = 3.852
category = "Электроинструмент"
is_full = volume_m3 > 3.5
```

В C# переменную объявляют с типом. Локальные имена пишут с маленькой буквы в стиле camelCase, типы и методы с большой:

```csharp
int positions = 4800;
double volumeM3 = 3.852;
string category = "Электроинструмент";
bool isFull = volumeM3 > 3.5;
```

Ключевое слово `var` позволяет не писать тип явно, но не отменяет его: компилятор выводит тип из правой части и дальше считает переменную этим типом.

```csharp
var positions = 4800;      // int
var volumeM3 = 3.852;      // double
```

Если позже присвоить переменной `positions` строку, компилятор всё равно ошибётся. `var` экономит буквы, но не делает язык динамическим.

Константу объявляют словом `const`, и её значение должно быть известно при сборке:

```csharp
const double PalletVolumeM3 = 1.44;
```

В Python константу пишут заглавными буквами, но язык не запрещает её изменить. Это соглашение, а не правило, которое проверяет интерпретатор.

У переменных C# есть ещё одно отличие: локальная переменная должна быть присвоена до первого использования, иначе сборка остановится с ошибкой `CS0165`. Значения по умолчанию существуют у полей класса, но не у локальных переменных. Отдельно стоит помнить про `null`: строка может не содержать значения, и компилятор с включённой проверкой `Nullable` предупреждает, предлагая писать `string?`, если отсутствие значения допустимо. Для чисел используют `int?`:

```csharp
int? freeCells = null;
string? note = null;
```

В Python `None` может оказаться в любом имени без объявления, и ошибка проявится только при обращении к нему. В C# такой риск виден по типу и предупреждению компилятора.

## Целые числа, деление и переполнение

Самая частая ошибка новичка связана с делением. В Python оператор `/` всегда возвращает вещественное число, а `//` отбрасывает дробную часть:

```python
print(7 / 2)
print(7 // 2)
```

```text
3.5
3
```

В C# оба операнда целые, поэтому `/` выполняет целочисленное деление:

```csharp
Console.WriteLine(7 / 2);
Console.WriteLine(7.0 / 2);
```

```text
3
3,5
```

Если нужен дробный результат, хотя бы один операнд должен быть вещественным. Запись `(double)boxes / perPallet` приводит к вещественному типу только числитель, и деление становится дробным. Остаток от деления даёт оператор `%`: 4817 коробок по 40 штук на паллету дают 120 полных паллет и 17 коробок в остатке.

Переполнение в Python невозможно: число растёт, пока хватает памяти. В C# диапазон `int` конечен. По умолчанию арифметика не проверяется, и при выходе за границу значение переходит на противоположный конец диапазона:

```csharp
int max = int.MaxValue;
Console.WriteLine(max + 1);
```

```text
-2147483648
```

Если такая ошибка недопустима, блок `checked` превращает переполнение в исключение `OverflowException`:

```csharp
checked
{
    int max = int.MaxValue;
    int next = max + 1;
}
```

Константное выражение `int.MaxValue + 1` компилятор отвергает сразу, а переменная проверяется только в момент выполнения. Поэтому одинаковое на вид выражение ведёт себя по-разному в зависимости от того, известно ли значение при сборке.

## Вещественные числа и decimal

Двоичная дробь не может точно представить 0,1: в памяти это бесконечная дробь, обрезанная до 53 бит. Поэтому сумма двух десятых не равна трём десятым:

```python
print(0.1 + 0.2)
print(0.1 + 0.2 == 0.3)
```

```text
0.30000000000000004
False
```

В C# с типом `double` картина та же:

```csharp
double a = 0.1;
double b = 0.2;
Console.WriteLine(a + b == 0.3);
```

```text
False
```

Тип `decimal` хранит значение как целое с десятичным масштабом, поэтому десятые складываются точно:

```csharp
decimal a = 0.1m;
decimal b = 0.2m;
Console.WriteLine(a + b == 0.3m);
```

```text
True
```

Суффикс `m` обязателен: без него литерал считается `double`. В Python аналогичную роль играет `Decimal`:

```python
from decimal import Decimal

print(Decimal("0.1") + Decimal("0.2"))
```

```text
0.3
```

`Decimal` создают из строки, а не из `float`: `Decimal(0.1)` уже содержит двоичную ошибку, которую переносит в десятичное значение.

Выбор между `double` и `decimal` зависит от того, что означает число. Объём груза 3,852 кубического метра измерен с точностью до тысячных, и ошибка в шестнадцатом знаке после запятой на результат не влияет. Цена и сумма копеек требуют точного десятичного представления, потому что расхождение в одну копейку видно в отчёте и вызывает вопросы. Поэтому объёмы считают в `double`, а деньги в `decimal`.

| Свойство | double | decimal |
|---|---|---|
| Основание | двоичное | десятичное |
| Точность | около 15-17 значащих цифр | 28-29 значащих цифр |
| Диапазон | примерно до 1,7 × 10 в 308 степени | примерно до 7,9 × 10 в 28 степени |
| Скорость | быстрее | медленнее |
| Для чего | измерения, графики, объёмы | деньги, тарифы, суммы |

Округление тоже требует внимания. И Python, и C# по умолчанию округляют половину к чётному: 2,5 даёт 2, а 3,5 даёт 4. Это правило снижает накопление ошибки, но удивляет бухгалтера, который ждёт 2,5 → 3. Если нужен другой способ, его указывают явно: в Python через модуль `decimal` с режимом `ROUND_HALF_UP`, в C# через `MidpointRounding.AwayFromZero`.

## Строки

Строка хранит текст и не меняется после создания. Метод `ToUpper` в C# и `upper` в Python возвращают новую строку, а исходная остаётся прежней:

```csharp
string code = "sklad-4800";
string upper = code.ToUpper();
Console.WriteLine(code);
Console.WriteLine(upper);
```

```text
sklad-4800
SKLAD-4800
```

Соединение строк выполняют оператором `+`, но в C# он же соединяет строку с любым другим значением. Именно поэтому `"4800" + 12` даёт `"480012"`, а не ошибку. Python так не делает и сообщает `TypeError`.

Для вставки значений в текст удобнее интерполяция. В Python это `f`-строка, в C# строка с префиксом `$`:

```python
positions = 4800
print(f"Позиций: {positions}")
```

```csharp
int positions = 4800;
Console.WriteLine($"Позиций: {positions}");
```

Обе строки печатают одно и то же. Формат можно задать после двоеточия: `{volume:0.###}` оставляет до трёх знаков после запятой, `{price:0.00}` всегда показывает две цифры. В Python похожий результат даёт `f"{volume:.3f}"`, но там количество знаков фиксировано, а не максимально.

Сравнение строк в C# через `==` сравнивает значения, а не ссылки. Для сортировки и поиска с учётом языка используют `StringComparison`, иначе одинаковые на вид строки с разными регистрами или алфавитами сравниваются не так, как ожидает пользователь. В Python `==` тоже сравнивает значения, а регистр учитывается всегда.

## Логический тип

Логическое значение получается из сравнения: `volumeM3 > 3.5` даёт истину или ложь. В C# тип `bool` принимает только `true` и `false`, и число вместо него не подставишь:

```csharp
bool isFull = volumeM3 > 3.5;
Console.WriteLine(isFull);
```

```text
True
```

В Python `bool` это подвид целого: `True` равен 1, `False` равен 0, а `True + True` даёт 2. В C# такая арифметика не компилируется. Зато Python считает ложными пустую строку, ноль и пустой список, а C# требует явного сравнения:

```python
if volume_m3:
    print("Объём известен")
```

В C# аналогичная запись `if (volumeM3)` не соберётся, потому что `double` не преобразуется в `bool` неявно. Нужно написать `if (volumeM3 > 0)`. Явность защищает от ошибки, когда ноль означает допустимое значение, а не отсутствие данных.

## Преобразование типов

Преобразование бывает неявным и явным. Неявное выполняет компилятор без подсказки, если преобразование разрешено языком: `int` помещается в `long` без потерь, а `long` преобразуется в `double` неявно, хотя очень большие значения при этом теряют точность. Явное пишет программист и берёт ответственность за потерю данных.

```csharp
int boxes = 4817;
long total = boxes;          // неявно, без потерь
double average = boxes / 3.0; // неявно при смешивании с double
int truncated = (int)3.9;     // явно, дробная часть отбрасывается
```

Приведение `(int)3.9` даёт 3, потому что дробная часть отбрасывается, а не округляется. Функция `Convert.ToInt32(3.9)` округляет по правилу половины к чётному и даёт 4. Эти два способа легко перепутать, и разница в единицу портит итог.

| Задача | Python | C# |
|---|---|---|
| Строка в целое | `int("4800")` | `int.Parse("4800")` |
| Безопасный разбор | `try` и `except ValueError` | `int.TryParse` |
| Дробное в целое | `int(3.9)` даёт 3 | `(int)3.9` даёт 3, `Convert.ToInt32(3.9)` даёт 4 |
| Число в строку | `str(4800)` | `4800.ToString()` |
| Целое в дробное | `float(4800)` | `(double)4800` |

Разбор строки может закончиться ошибкой. Пробел внутри числа, запятая вместо точки и лишний символ приводят к исключению:

```csharp
int count = int.Parse("4 800");
```

```text
FormatException
```

Проверить строку заранее позволяет `TryParse`. Он не выбрасывает исключение, а возвращает признак успеха и записывает результат в переменную:

```csharp
int count;
bool ok = int.TryParse("4 800", out count);
Console.WriteLine($"{ok} {count}");
```

```text
False 0
```

В Python аналог это `try` и `except`, потому что отдельной функции с признаком успеха для `int` нет. В учебном проекте `TryParse` пригодится при чтении количества из файла: одна плохая строка не должна останавливать весь импорт.

Отдельная ловушка связана с культурой. На русской локали разделитель дробной части это запятая, поэтому `double.Parse("4.75")` завершится ошибкой, а `double.Parse("4,75")` вернёт 4,75. При обмене данными с внешними системами число всегда разбирают с явно указанной культурой или в инвариантном формате, иначе на другом компьютере тот же файл прочитается иначе.

Обратное преобразование, из числа в строку, подчиняется тем же правилам. Формат задают явно, а культуру указывают, если строка уходит в файл или в другую систему:

```csharp
using System.Globalization;

decimal price = 623520.00m;
Console.WriteLine(price.ToString("0.00", CultureInfo.InvariantCulture));
Console.WriteLine(price.ToString("0.00"));
```

```text
623520.00
623520,00
```

Первая строка одинакова на любой машине, вторая зависит от локали. В файлах обмена и в API используют первый вариант, а человекочитаемый отчёт может позволить себе второй.

## Типичные ошибки

1. Целочисленное деление вместо дробного. `4800 / 1000` в C# даёт 4, а не 4,8. Лечится приведением одного операнда к `double`.
2. Переполнение `int` при умножении. 4800 × 129,90 в копейках помещается, а годовой оборот склада может выйти за 2,1 миллиарда. Проверяют диапазон или берут `long`.
3. Деньги в `double`. При сложении и умножении появляются хвосты в дробной части, и отчёт не сходится на копейки. Для денег берут `decimal`.
4. Строка вместо числа. `"4800" + 12` в C# даёт текст, а не сумму. Значение разбирают до арифметики.
5. Разбор без проверки. `int.Parse` на пустой строке или на тексте с пробелом выбрасывает исключение. Для пользовательского ввода берут `TryParse`.
6. Неявное приведение с потерей. `(int)3.9` отбрасывает дробь, `Convert.ToInt32` округляет. Выбор зависит от задачи, и его фиксируют в коде явно.
7. Сравнение строк без учёта культуры. `==` в C# сравнивает значения, но для сортировки нужен `StringComparison`.
8. Логическое значение из числа. В Python `if count:` сработает при любом ненулевом числе, в C# такая запись не соберётся. Условие формулируют явно.

Разбор ошибок типа удобно начинать с сообщения компилятора. Код `CS0029` говорит о несовпадении типов при присваивании, `CS0165` об использовании локальной переменной без значения, `CS0266` о неявном преобразовании, которое требует явного. В Python имя ошибки `TypeError` указывает на недопустимую операцию, а текст сообщения называет типы, которые не подошли. Чтение сообщения целиком экономит больше времени, чем повторный запуск наугад.

## Итоги

- Тип задаёт множество значений, допустимые операции и способ хранения.
- В Python тип принадлежит значению и проверяется при выполнении, в C# тип принадлежит переменной и проверяется при сборке.
- Целые типы C# имеют конечный диапазон, переполнение по умолчанию не проверяется.
- Деньги хранят в `decimal`, а не в `double`, потому что двоичная дробь не представляет копейки точно.
- Строка неизменяема, а `+` в C# соединяет строку с любым значением, поэтому число разбирают до сложения.
- Явное преобразование выбирают, когда возможна потеря данных, и проверяют результат разбора через `TryParse`.

Q: Что задаёт тип переменной?
+ Множество значений, допустимые операции и способ хранения
- Только имя переменной в программе
- Только размер файла с исходным кодом
- Только цвет подсветки в редакторе
! Тип это договор о значениях и операциях, а не украшение объявления.

Q: Чем статическая типизация C# отличается от динамической в Python?
+ Тип известен при сборке и проверяется до запуска
- Тип проверяется только во время выполнения
- В C# типы вообще не проверяются
- В Python тип нельзя изменить после присваивания
! Компилятор C# проверяет типы заранее, Python в момент операции.

Q: Какой тип C# подходит для хранения денежных сумм?
+ decimal
- double
- float
- byte
! decimal хранит значение с десятичным масштабом и не накапливает двоичную ошибку.

Q: Что выведет выражение 7 / 2 в C#, если оба операнда целые?
+ 3
- 3,5
- 4
- 0
! Целочисленное деление отбрасывает дробную часть.

Q: Что выведет выражение 7 / 2 в Python?
+ 3.5
- 3
- 4
- 0
! Оператор / в Python всегда возвращает вещественное число.

Q: Какие типы в C# относятся к целым?
+ int
+ long
+ byte
- double
- decimal
! double и decimal хранят дробные значения.

Q: Что произойдёт при вычислении max + 1, где max равно int.MaxValue, без блока checked?
+ Значение станет -2147483648
- Программа выбросит OverflowException
- Значение станет 2147483648
- Компилятор остановит сборку
! По умолчанию переполнение не проверяется и значение переходит через границу.

Q: Чем decimal отличается от double?
+ Хранит десятичные цифры
+ Имеет точность 28-29 значащих цифр
+ Медленнее в вычислениях
- Имеет бесконечный диапазон
- Подходит для графики лучше double
! decimal точнее для денег, но медленнее и с меньшим диапазоном.

Q: Что делает приведение (int)3.9 в C#?
+ Отбрасывает дробную часть и даёт 3
- Округляет до 4
- Выбрасывает исключение
- Возвращает строку "3.9"
! Явное приведение к int отбрасывает дробную часть.

Q: Какие значения Python считает ложными?
+ 0
+ пустая строка
+ пустой список
- строка "0"
- число -1
! Ложными считаются ноль, пустые последовательности и None.

Q: Что вернёт int.TryParse("4 800", out count)?
+ False и 0 в count
- True и 4800 в count
- Исключение FormatException
- True и 4 в count
! Пробел внутри числа не допускается, разбор завершается неудачей.

Q: Чем Convert.ToInt32(3.9) отличается от (int)3.9?
+ Convert округляет до 4, приведение отбрасывает дробь и даёт 3
- Оба дают 3
- Оба дают 4
- Convert выбрасывает исключение
! Convert округляет, явное приведение отбрасывает дробную часть.

Q: Что даст выражение "4800" + 12 в C#?
+ Строку "480012"
- Число 4812
- Ошибку компиляции
- Число 480012
! Оператор + со строкой соединяет текст, а не складывает числа.

Q: Какой тип C# хранит деньги без двоичной ошибки?
= decimal
! decimal хранит десятичные цифры.

Q: Какая функция Python преобразует строку в целое число?
= int
= int()
! int("4800") возвращает целое число 4800.
