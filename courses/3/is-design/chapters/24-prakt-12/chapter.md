## Цель работы

Клиент и сервер пишут разные команды, и расхождение в одном поле стоит недели переделок. Контракт снимает спор до кода: в нём зафиксированы адреса, методы, поля, коды ответов и формат ошибки.

Цель работы: спроектировать REST API для «Библиотеки колледжа», оформить его спецификацией OpenAPI и собрать коллекцию Postman с проверками. Результат это файл спецификации, коллекция запросов и таблица проверок.

## Оборудование и программное обеспечение

- Персональный компьютер с браузером.
- VS Code с Python для проверки файла спецификации.
- Postman для коллекции запросов и примеров ответов.
- Текстовый редактор для YAML и JSON.
- Диаграмма контейнеров из предыдущей практики.

## Краткие теоретические сведения

**Ресурс** это объект, с которым работает API: книга, экземпляр, выдача, бронь, читатель, штраф. Адрес ресурса строят из существительных во множественном числе: `/books`, `/loans`, `/readers`. Глагол в адресе не нужен, действие передаёт HTTP-метод.

**HTTP-метод** задаёт операцию. `GET` читает и не меняет данные. `POST` создаёт новый ресурс. `PUT` заменяет ресурс целиком. `PATCH` меняет часть полей. `DELETE` удаляет. Методы `GET`, `PUT` и `DELETE` идемпотентны: повторный запрос с теми же данными даёт тот же результат. `POST` не идемпотентен, поэтому повторное создание выдачи требует защиты от дубля.

**Код ответа** сообщает результат. `200` означает успешное чтение, `201` создание, `204` успех без тела. `400` означает ошибку формата запроса, `401` отсутствие входа, `403` нехватку прав, `404` отсутствие ресурса, `409` конфликт состояния, `422` ошибку бизнес-правила, `500` сбой сервера. Код выбирают по причине, а не по удобству клиента.

**Формат ошибки** должен быть единым для всех операций. Удобно использовать `application/problem+json` с полями `type`, `title`, `status`, `detail`, `instance`. Дополнительно добавляют `code` для машинной обработки и `fields` для ошибок валидации.

**Пагинация** защищает от ответа на миллион строк. Параметры `limit` и `offset` просты, но при вставках дают сдвиг. Курсорная пагинация устойчивее, но сложнее. Для каталога библиотеки достаточно `limit` и `offset` с жёстким максимумом.

**OpenAPI** это машиночитаемое описание API. В нём есть версия, информация, серверы, пути, операции, схемы данных и примеры. Спецификация служит источником для документации, генерации клиента и проверки ответов.

## Ход работы

### Шаг 1. Составьте список ресурсов

Выпишите ресурсы из модели данных и диаграммы контейнеров. Для каждого определите, какие операции нужны читателю, библиотекарю и администратору.

| Ресурс | Адрес | Операции | Кто вызывает |
|---|---|---|---|
| Книга | `/books` | `GET`, `POST` | Читатель, библиотекарь |
| Экземпляр | `/books/{bookId}/copies` | `GET`, `POST` | Библиотекарь |
| Выдача | `/loans` | `GET`, `POST` | Библиотекарь |
| Возврат | `/loans/{id}/return` | `POST` | Библиотекарь |
| Бронь | `/reservations` | `GET`, `POST`, `DELETE` | Читатель |
| Читатель | `/readers` | `GET`, `POST`, `PATCH` | Библиотекарь |
| Штраф | `/fines` | `GET` | Библиотекарь |

### Шаг 2. Задайте коды ответов

Для каждой операции выберите успешный код и не менее двух ошибочных. Пустой список ошибок означает, что контракт не описывает реальность.

| Ситуация | Код | Тело ответа |
|---|---|---|
| Список книг получен | 200 | Массив книг и пагинация |
| Выдача создана | 201 | Созданная выдача с `id` |
| Бронь отменена | 204 | Тела нет |
| Нет параметра `readerId` | 400 | Ошибка с полем |
| Нет или истёк токен | 401 | Ошибка входа |
| Читатель не может вернуть чужую книгу | 403 | Ошибка прав |
| Книга не найдена | 404 | Ошибка с `instance` |
| Экземпляр уже выдан | 409 | Конфликт состояния |
| Дата возврата раньше выдачи | 422 | Ошибка правила |

### Шаг 3. Зафиксируйте формат ошибки

Один формат на все операции. Клиент не должен разбирать пять разных ответов.

```json
{
  "type": "https://library.college/errors/conflict",
  "title": "Экземпляр уже выдан",
  "status": 409,
  "detail": "Экземпляр 1042 выдан читателю 318 до 2026-11-05",
  "instance": "/loans",
  "code": "COPY_ALREADY_LOANED",
  "fields": []
}
```

Для ошибки валидации поле `fields` заполняется списком объектов с именем поля и сообщением. Код `COPY_ALREADY_LOANED` остаётся стабильным, даже если текст `detail` изменится.

### Шаг 4. Опишите пагинацию

Задайте параметры `limit` (от 1 до 50, по умолчанию 20) и `offset` (от 0). Ответ верните объектом, а не голым массивом: так можно добавить `total` и ссылки, не ломая клиент.

```json
{
  "items": [
    {"id": 12, "title": "Алгоритмы и структуры данных", "author": "Кормен", "available": 2}
  ],
  "limit": 20,
  "offset": 0,
  "total": 143
}
```

### Шаг 5. Напишите спецификацию OpenAPI

Создайте файл `openapi.yaml`. Опишите две операции полностью: список книг и создание выдачи. Остальные ресурсы добавьте путями с краткими ответами.

```yaml
openapi: 3.0.3
info:
  title: Library API
  version: 1.0.0
  description: API учебной ИС «Библиотека колледжа»
servers:
  - url: https://library.college/api/v1
paths:
  /books:
    get:
      operationId: listBooks
      parameters:
        - name: query
          in: query
          schema: {type: string, maxLength: 100}
        - name: limit
          in: query
          schema: {type: integer, minimum: 1, maximum: 50, default: 20}
        - name: offset
          in: query
          schema: {type: integer, minimum: 0, default: 0}
      responses:
        "200":
          description: Список книг
          content:
            application/json:
              schema: {$ref: "#/components/schemas/BookPage"}
  /loans:
    post:
      operationId: createLoan
      requestBody:
        required: true
        content:
          application/json:
            schema: {$ref: "#/components/schemas/LoanCreate"}
      responses:
        "201":
          description: Выдача создана
          content:
            application/json:
              schema: {$ref: "#/components/schemas/Loan"}
        "409":
          description: Экземпляр уже выдан
          content:
            application/problem+json:
              schema: {$ref: "#/components/schemas/Problem"}
components:
  schemas:
    LoanCreate:
      type: object
      required: [copyId, readerId, dueDate]
      properties:
        copyId: {type: integer, minimum: 1}
        readerId: {type: integer, minimum: 1}
        dueDate: {type: string, format: date}
    Loan:
      type: object
      properties:
        id: {type: integer}
        copyId: {type: integer}
        readerId: {type: integer}
        dueDate: {type: string, format: date}
        status: {type: string, enum: [active, returned, overdue]}
    BookPage:
      type: object
      properties:
        items:
          type: array
          items: {type: object}
        limit: {type: integer}
        offset: {type: integer}
        total: {type: integer}
    Problem:
      type: object
      required: [type, title, status]
      properties:
        type: {type: string}
        title: {type: string}
        status: {type: integer}
        detail: {type: string}
        instance: {type: string}
        code: {type: string}
```

Проверьте файл скриптом: он ловит пустые `operationId`, отсутствие ответа и ссылки на несуществующие схемы.

```python
import yaml

with open("openapi.yaml", encoding="utf-8") as f:
    spec = yaml.safe_load(f)

seen = set()
for path, methods in spec["paths"].items():
    for method, op in methods.items():
        oid = op.get("operationId")
        assert oid, f"{method} {path}: нет operationId"
        assert oid not in seen, f"повтор operationId {oid}"
        seen.add(oid)
        assert "responses" in op, f"{oid}: нет responses"
print("операций:", len(seen))
```

### Шаг 6. Соберите коллекцию Postman

Создайте коллекцию `Library API` с переменной `baseUrl`. Добавьте запросы: список книг с поиском, создание выдачи, возврат, бронь. Для каждого сохраните пример успешного ответа и ответ с ошибкой.

Вкладка Tests проверяет контракт, а не только факт ответа.

```javascript
pm.test("код 201", () => pm.response.to.have.status(201));
const body = pm.response.json();
pm.test("есть id выдачи", () => pm.expect(body.id).to.be.a("number"));
pm.test("статус active", () => pm.expect(body.status).to.eql("active"));
pm.test("дата в формате ISO", () => pm.expect(body.dueDate).to.match(/^\d{4}-\d{2}-\d{2}$/));
```

Для запроса списка добавьте проверки кода `200`, наличия `items` и того, что `total` не меньше длины массива.

### Шаг 7. Проверьте контракт

Если учебный стенд доступен, выполните запросы и сохраните ответы. Если стенда нет, сверьте сохранённые примеры со схемами спецификации вручную и заполните таблицу.

| Проверка | Запрос | Ожидание | Результат |
|---|---|---|---|
| Список книг | `GET /books?limit=5` | 200, не больше 5 элементов | |
| Поиск без результата | `GET /books?query=абракадабра` | 200, пустой `items` | |
| Создание выдачи | `POST /loans` | 201, есть `id` | |
| Повтор выдачи | `POST /loans` с тем же `copyId` | 409, код `COPY_ALREADY_LOANED` | |
| Нет поля | `POST /loans` без `readerId` | 400, поле в `fields` | |
| Чужая бронь | `DELETE /reservations/99` | 403 | |

Скриншот ответа Postman прикладывайте только как доказательство проверки: в кадре нужны адрес запроса, код и тело. Если сдаёте файл коллекции с сохранёнными примерами, скриншоты не обязательны.

### Шаг 8. Сверьте контракт с моделями

Проверьте, что каждое поле выдачи есть в схеме базы и на диаграмме компонентов. Если API возвращает `readerName`, а в базе только `readerId`, решите, кто собирает имя: сервис приложения или клиент. Запишите решение в пояснение.

### Требования к отчёту

В отчёт включите таблицу ресурсов, таблицу кодов, пример ошибки, пример пагинации, файл `openapi.yaml`, коллекцию Postman, таблицу проверок и короткое пояснение о спорных полях. Спецификацию сдавайте файлом, а не скриншотом редактора.

| Критерий | Баллы | Что проверяется |
